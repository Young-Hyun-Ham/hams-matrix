# 첨부 문서 일괄 생성 제안요청서 동시 생성

- 작성일: 2026-11-16 (한국시간)
- 요청: 제안요청서 탭에서 사업계획서 등 첨부로 연계 문서를 일괄 생성하면 제안요청서 데이터도 함께 생성하고 연계한다.
- 원인: 기존 일괄 생성 대상은 WBS·요구사항·화면·기능·DB·프로그램 6종뿐이고 RFP는 읽기용 출처로만 처리했다.

## 주요 변경

- 저장된 RFP가 없는 생성 창에서 '제안요청서 초안도 함께 생성'을 기본 선택한다. 기존 RFP는 자동 덮어쓰지 않는다. RFP 생성 권한이 없으면 명확히 표시하고 선택을 비활성화한다. 선택 해제 시 기존 6종 생성 동작을 유지한다.
- 요청에 선택적 createRfp를 추가했다. 기존 요청은 옵션이 없으면 예전 동작을 유지한다. 새 RFP에는 첨부 원본이 필요하며 CREATE 권한과 부재 상태를 확인한다.
- 기존 RFP 생성용 7개 장 JSON 스키마를 재사용하여 같은 AI 응답에서 rfpDocument와 연계 산출물을 함께 받는다. 원문에 없는 발주기관·일자·예산·제안 마감·평가 점수 등은 임의로 채우지 않는다. 서버가 projectId·schemaVersion과 목록 항목 ID를 확정하고 validateRfp로 검증한다. 부록 참고자료에 선택한 출처 파일명을 기록한다.
- RFP 생성 1건을 관리자 maxChanges에 포함한다. RFP와 산출물을 함께 생성하려면 한도가 최소 2건 필요하다. 최종 저장에서도 최신 정책을 다시 확인한다.
- 기존 mutateRfp의 CREATE를 산출물 저장 트랜잭션 내부에서 호출한다. RFP 문서·개정 이력·RFP 불변 snapshot·산출물·연결·관리번호·변경 이력과 완료 상태를 모두 같은 트랜잭션에 저장한다. 생성 도중 별도 RFP가 등록되면 덮어쓰지 않고 충돌 처리한다.
- 각 신규 산출물은 생성된 RFP snapshot과 선택 원본 파일 snapshot을 모두 출처로 보존한다. 상세에서 RFP 원문과 현재 RFP로 이동할 수 있다. RFP 자체의 원본 첨부 정보는 작업 payload.sources와 RFP 부록 참고자료에 남는다.
- 기존 산출물 재사용을 명시적으로 선택하면 기존 내용은 유지하고 RFP 출처만 추가한다. UPDATE 권한·관리자 UPDATE 정책을 확인하며 버전과 변경 이력을 남긴다. 정책 확인은 중복 검토 선택 시와 최종 저장에서 수행한다.
- 완료 상태에 rfpResult를 반환하고 '생성된 제안요청서 보기'를 제공한다. RFP 조회 캐시를 무효화하여 현재 탭에서도 새 문서를 확인한다. 기존 미저장 RFP 편집본 보호 동작은 유지한다.

- scripts/test-deliverable-generation.mjs, scripts/test-artifact-detail-navigation-browser.mjs: 회귀 검증.
- README.md, AGENTS.md, CLAUDE.md, WORK_HISTORY.md 및 이 기록.

## DB 변경 여부

스키마 변경·새 마이그레이션 없음. 기존 project_rfp_documents / project_rfp_revisions / project_source_snapshots / artifact_source_references를 사용한다. 작업 payload에 rfpDraft와 rfpResult를 추가한다. 실제 사용자 데이터를 AI로 재생성하거나 이미 완료된 작업을 소급 수정하지 않는다.

## 미완료 및 실행 정보

- 실제 사업계획서에 대한 유료 AI 호출은 수행하지 않는다. 새 요청에만 적용하며, 이미 생성된 산출물에 RFP를 소급 생성하지 않는다.
- 처리 중인 작업 0건을 확인하고 이전에 실행한 독립 작업자만 새 코드로 재시작했다. 시작 로그와 생존을 확인했다. 새 요청부터 동시 생성이 적용된다.
- 복원된 개요 화면과 기존 guard.inspect 주석은 유지한다.
- 구조화 응답은 [공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 확인하고 기존 RFP 스키마를 그대로 재사용했다.
