# 플래닝보드 화면설계서 이식

- 작성일: 2026-11-03 (한국시간)
- 기준: [최신 설계서](../../history/2026-11-03/플래닝보드-화면설계서-이식-설계.md)를 다시 읽고 구현. 문서 말미에 추가된 Matrix 로그인 사용자 기준 AI 권한 정책도 반영했다.

## 주요 변경사항

- 화면설계서 행에 **플래닝보드** 링크를 추가했다. `projectId`와 `screenId`로 기존 화면에 연결하며, `noopener`를 적용한 새 창으로 연다. 보기 전용 구성원도 조회할 수 있다.
- `app/(editor)/planning-board/` 안에 편집기·캔버스·레이어·속성·11종 요소·SVG/MUI 아이콘·다중 페이지·확대/이동·기기 폭 선택·댓글·메모·미리보기·템플릿 3종·AI 생성/기록·검토 흐름·5종 코드 내보내기를 이식했다.
- Provider마다 별도 Zustand 저장소를 만든다. 원본 undo 40건/350ms 묶음을 유지하고, 권한 갱신·검토 중 본문 잠금·보기 전용 붙여넣기 차단·저장되지 않은 내용의 창 닫기 경고를 반영했다. 작은 화면은 편집 도구 전체를 가로로 탐색할 수 있도록 했다.
- Firebase/SSO 호출을 제거하고 Matrix 세션·프로젝트 소속·`screen.READ/UPDATE` 권한을 API마다 검사한다. 공유 설정은 기존 프로젝트 권한 모달을 사용하며, 검토자는 UPDATE가 있는 기존 구성원 중에서 선택한다.
- 최초 조회는 DB 보드를 만들지 않는다. 저장할 때 보드/화면 버전을 함께 검사하고, 보드 본문·이력·화면 경량 참조와 화면 버전·기존 산출물 감사 기록을 한 트랜잭션으로 갱신한다. 요청 ID·기대 버전 등 전송용 메타데이터는 본문 JSON에서 제외한다. 기존 화면 필드·관리번호·연결·상태는 보존한다.
- 검토 요청/반려/완료/완료 후 재편집과 소유자의 검토자 재지정을 연결했다. 검토 중 본문은 잠그고 UPDATE가 있는 구성원의 댓글·메모 협의는 허용한다. 보드 상태와 Matrix 산출물 상태는 별도로 유지한다.
- 이미지는 비공개 R2 자산 참조로 저장한다. PNG/JPEG/WebP 실제 디코딩, 8MiB·4천만 픽셀·화면당 자산 50개 제한, 첨부 범위 검사, 미저장 임시 자산 만료 및 다음 업로드 시 정리를 추가했다. 저장된 이력에 필요한 첨부는 유지한다.
- AI는 Matrix 모델 목록·사용 중지 정책·가드레일·UPDATE 허용/변경 건수·토큰 예약/사용량 기록을 사용한다. 요청 ID/입력 해시로 중복 처리를 차단하며, 생성/검증/저장이 모두 성공한 결과만 편집기에 반영한다. 실패·버전 충돌은 편집본을 보존한다. 현재 편집본과 같은 프로젝트의 화면 정의·연결 요구사항을 문맥으로 사용한다.
- AI 원본의 페이지/요소 조용한 잘라내기를 제거하고 ID·부모·깊이·좌표·크기·스타일·첨부를 검사한다. 기능별 출력 옵션은 최대 16,000 토큰이며, 기존 AI 기능의 기본 6,000 토큰은 유지했다.
- 미리보기는 저장본 조회와 미저장 스냅샷 전달을 지원한다. 전달 시 동일 출처·원본 창·nonce를 확인한다. 내보내기는 CSS/HTML5/React/Astro/Svelte, 일반/한 줄 복사를 지원하고 비공개 이미지는 내보낸 CSS 안의 내장 데이터로 변환한다. HTML 등 결과물과 함께 CSS 코드를 사용한다.
- 공통 모달·테마 스타일을 재사용하고 편집기/미리보기 CSS를 기능 루트에 한정했다. 보드 저장 알림을 받은 화면설계서 목록은 서버 데이터를 다시 조회한다.

- `app/(editor)/planning-board/`: 화면·미리보기·컴포넌트·아이콘·타입·Zustand Provider·클라이언트 API·서버 서비스·템플릿·스타일·README 신규.
- `app/(editor)/planning-board/api/[...path]/route.ts`: 화면 범위 API를 단일 Route Handler에서 분배한다. 코드 포맷 API도 프로젝트/화면 범위 아래에 배치했다.

- `lib/ai-server.ts`: 기능별 출력 토큰 상한 옵션 및 동일 기준 토큰 예약.
- `db/migrations/032_planning_boards.sql`: 전용 DB 스키마.
- `package.json`, `pnpm-lock.yaml`: MUI/Emotion, Prettier 및 Astro/Svelte 플러그인, 이미지 검증용 sharp, 검증 명령.
- `scripts/test-planning-board.mjs`, `scripts/test-planning-board-browser.mjs`: 격리 DB/API/Chrome 검증.
- 이 작업 기록과 `WORK_HISTORY.md`.

## DB 변경 여부

- **변경 있음. 연결된 DB에 신규 032 마이그레이션 적용 완료.** 기존 마이그레이션을 재실행하지 않고 032만 적용하고 생성 결과를 조회했다.
- 신규 7개 테이블: `planning_boards`, `planning_board_revisions`, `planning_board_comments`, `planning_board_memos`, `planning_board_review_history`, `planning_board_assets`, `planning_board_ai_requests`.
- 범위 외래키·화면당 보드 유일성·조회 인덱스·본문/검토 이력 불변 트리거를 추가했다. 기존 업무 데이터와 다른 작업의 DB 변경은 보존했다.

## 미완료 사항·범위

- 이번 이식 범위의 필수 구현 미완료 사항은 없다.
- 실제 유료 AI 호출과 운영 R2 업로드는 실행하지 않았고, 외부 서비스 대역과 격리 DB/서버로 검증했다.
- 기존 Firestore 자료 일괄 이전, 독립 SSO 로그인/프로필, 이메일로 새 권한을 만드는 공유 기능은 설계서에 따라 포함하지 않았다. 기존 RFP 가드레일 비활성화와 관련 테스트 기대값의 정합성은 별도 작업 사항이다.
