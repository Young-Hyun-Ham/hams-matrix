# 팀 공유와 프로젝트 권한

`pnpm db:migrate`로 `019_single_team_owner.sql`까지 적용합니다.

## 가입과 팀 추가

팀 공유는 프로젝트를 선택해야 사용할 수 있습니다. 미선택 시 프로젝트 선택 안내 화면만 표시하고 구성원·팀 이야기·함께하는 사람들은 조회하거나 표시하지 않습니다. 화면의 **공유 글 작성**은 선택한 프로젝트의 member에게만, **멤버 추가**는 선택한 프로젝트의 owner/admin에게만 표시합니다. 서버도 같은 권한을 검사합니다.

- 팀 가입 신청 후 팀 owner가 승인하면 `workspace_members.role=member`가 됩니다. 기존·이후 생성 프로젝트에 참여하고 역할이 허용하는 문서 편집을 할 수 있습니다. 신청 승인 전에는 Guest 공간만 사용할 수 있습니다.
- Free/Guest로 가입한 사용자를 선택한 프로젝트의 owner/admin이 **함께하는 사람들 → 멤버 추가** 모달에서 이메일로 추가하면 해당 프로젝트에만 viewer로 참여시킵니다. 프로젝트 미선택 추가나 전체 프로젝트 일괄 추가는 허용하지 않습니다. 이미 구성원이면 기존 권한을 덮어쓰지 않습니다.
- 직접 추가된 사용자를 다른 프로젝트나 이후 생성되는 프로젝트에 자동 포함하지 않습니다. 기존 참여 관계를 일괄 삭제하지는 않습니다.
- 추가·승인 시 사용자의 현재 팀과 살아 있는 로그인 세션을 해당 팀으로 전환합니다. 사용자가 새로고침하면 반영됩니다. 메일은 발송하지 않습니다.
- 가입 및 소셜 온보딩의 **담당 역할·직무**는 `users.job_title`에 최대 80자로 저장합니다. 접근 권한을 직접 지정하는 필드가 아닙니다. 팀 공유의 구성원 이름 아래에 표시하며 기존 미등록 계정에는 미등록으로 표시합니다.

## 팀 소속과 프로젝트 권한

`users.account_role`은 가입 유형 owner/user입니다. 실제 업무 권한은 팀 소속과 선택한 프로젝트의 권한으로 검사합니다. user 계정이어도 승인되어 member가 되면 문서 편집이 가능합니다.

- 팀 소속 권한 관리 API는 팀 owner만 사용할 수 있습니다. 팀 공유 화면에서는 프로젝트 선택 후 해당 프로젝트의 권한만 표시합니다.
- **특정 프로젝트**: 해당 프로젝트 owner만 구성원의 admin/member/viewer 권한을 변경하거나 다른 구성원에게 소유권을 양도합니다. 팀 owner라도 해당 프로젝트의 소유권을 양도한 후에는 그 프로젝트의 구성원 권한을 관리할 수 없습니다.
- 프로젝트별 권한을 지정하면 팀 소속 권한보다 우선합니다. 프로젝트에서 별도로 지정하지 않은 구성원은 팀 권한을 따릅니다. 팀 owner가 다른 사람이 소유한 프로젝트에 참여할 때 기본 프로젝트 권한은 admin입니다.
- admin/member/owner는 해당 범위에서 편집하고 viewer는 조회합니다. 프로젝트 생성은 팀 소속 owner/admin/member만 할 수 있습니다. 프로젝트 owner가 되어도 팀 전체 관리나 가드레일 관리자 권한을 얻지 않습니다. 가드레일은 워크스페이스 owner/admin만 관리합니다.

## 소유권 양도

팀 소속 권한 또는 선택한 프로젝트 권한에서 이전받을 구성원을 **owner · 소유권 이전**으로 바꿉니다. 경고 모달에 대상과 범위를 표시하며 **이전 / 취소**를 제공합니다. **이전**으로 확정하면 소유자를 한 트랜잭션으로 교체하고 이전 소유자는 해당 범위의 **member**가 됩니다. 취소하거나 서버 검증에 실패하면 원래 소유자를 유지합니다.

팀 이전은 `workspaces.owner_id`와 두 구성원의 팀 역할을 함께 변경하며 기존 프로젝트 소유권은 유지합니다. 프로젝트 이전은 해당 프로젝트에만 적용합니다. 팀 owner도 하나만 존재하도록 부분 유니크 인덱스를 적용합니다. 가입 유형이 user인 Free 구성원도 팀 owner가 되면 팀 검색·가입 승인·멤버 관리 기능을 사용할 수 있으며 가입 유형이나 플랜을 임의 변경하지 않습니다.

`projects.owner_id`가 프로젝트의 단일 소유자를 나타냅니다. 프로젝트 구성원 API는 이 사용자를 owner로 표시하며, `project_members.role`에는 owner를 중복 저장하지 않습니다. 소유자를 NULL로 변경하거나 양도 전에 참여 관계를 삭제하지 못하도록 DB에서도 보호합니다. 양도 대상은 같은 프로젝트 구성원이어야 합니다. 수정 요청의 현재 역할/소유자를 검사하고 트랜잭션 안에서 관리 권한을 다시 확인합니다.

기존 프로젝트는 생성자를 소유자로 보존합니다. 기존 승인 완료 viewer는 member로 전환하지만 승인 이력이 없는 viewer는 유지합니다.

## 팀 이야기와 함께하는 사람들

- 구성원은 실제 팀/프로젝트 참여 관계와 이름·담당 역할·권한으로 표시합니다. 가짜 접속 상태나 샘플 인물은 사용하지 않습니다.
- 팀 이야기는 `team_posts`, 댓글은 `team_comments`에서 조회·작성합니다. 팀 전체 게시글과 프로젝트 게시글을 구분하고, 프로젝트 참여자가 아닌 사용자에게 프로젝트 게시글·댓글을 공개하지 않습니다.
- 공유 글은 프로젝트를 선택한 member만 작성할 수 있습니다. owner/admin/viewer는 공유 글 작성 버튼을 표시하지 않으며 API 작성도 거부합니다. 댓글은 기존 역할별 편집 권한을 따릅니다. 제목 160자, 본문 10,000자, 댓글 2,000자까지 허용합니다. 게시글은 최근 100개, 댓글은 200개까지 조회합니다. 입력은 HTML로 실행하지 않고 텍스트로 표시합니다.
- 가입 승인, 직접 추가, 권한 변경, 소유권 양도, 게시글·댓글 작성은 기존 DB 감사 설정에 따라 데이터와 같은 트랜잭션으로 기록합니다.

## 검증

`pnpm test:auth`에 팀 승인/member 편집, Free 사용자/viewer 추가, 가입 직무 저장, 프로젝트 역할 변경·양도·동시성, 단일 소유자 보호, 새 프로젝트 자동 공유, 실제 게시글/댓글, 다른 팀 접근 차단 검사를 포함합니다. `node scripts/test-team-migration.mjs`는 기존 데이터 이관을 검증합니다. AI·문서 편집 경로에도 동일한 프로젝트 역할을 적용합니다.
