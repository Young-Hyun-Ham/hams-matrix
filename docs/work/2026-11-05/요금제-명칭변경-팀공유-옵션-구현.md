# 요금제 명칭 변경 및 팀공유 옵션 구현

- 작성일: 2026-11-05 (한국시간, Asia/Seoul)
- 기준 문서: [요금제 명칭 변경 및 팀공유 옵션 분석·설계](../../history/2026-11-05/요금제-명칭변경-팀공유-옵션-설계.md). 구현 전에 최신 내용을 다시 읽었다.
- 상태: 요청 기능 구현 및 연결된 DB 적용 완료. 관련 검증 통과. 전체 인증 테스트의 기존 경로 불일치는 아래에 별도 기록한다.

## 적용 정책과 주요 변경사항

작업 중 사용자가 선택한 **권장안 + 화면·API 제한**을 적용했다.

- 기존 코드 `plus`의 표시명을 Pro, 기존 `pro`의 표시명을 Team으로 변경했다. 코드는 유지하며 구독·가격·할인·한도·추천 설정을 보존했다.
- 관리자설정 요금제 탭에 요금제별 “팀공유” 체크를 추가했다. 초기값은 Free/Pro 해제, Team/Business 활성화이며 이후 네 요금제 모두 독립적으로 변경할 수 있다.
- 옵션을 필수 boolean으로 검증하고 기존 버전 충돌 검사·트랜잭션·수정자·변경 이력을 유지했다. 이력 상세에도 변경 전후 옵션을 표시한다.
- 회원 본인의 구독 옵션을 사용자 DTO에 포함하고 메뉴·메뉴 검색·알림의 팀공유 진입점을 제어했다. 관리자도 본인 요금제를 따르며 게스트 데모는 유지했다.
- `/team` 직접 접근은 요금제 안내로 이동한다. 게시글·댓글·구성원 관리·가입 신청 조회/승인·프로젝트 역할별 권한 API와 새 공동 멤버 등록은 서버에서 최신 옵션을 검사한다. 쓰기 검사는 기존 트랜잭션 안에서 수행하며 기존 프로젝트 역할·소속 제한도 유지했다.
- 미지원 회원의 프로젝트 ID 없는 팀원 조회는 본인만 반환하고 관리 권한은 false로 반환한다. 개인 프로젝트 생성은 허용하고 타인 `memberIds`를 통한 공동 등록은 차단한다. 기존 게시글·댓글·구성원·프로젝트는 삭제하지 않는다.
- 요금제/관리자 설정 저장 후 서버 상태를 갱신하고, 화면 진입·창 재활성화·팀 요청 403 때 사용자 옵션을 재조회한다. 다른 세션 변경에 대한 실시간 푸시나 주기적 폴링은 추가하지 않았다.
- 회원 관리의 목록·상세·필터·수정 옵션은 카탈로그 표시명을 사용하며 요청 value는 기존 코드로 유지한다. 요금제 카드에도 팀공유 지원 여부를 추가했다.
- 이메일 가입 응답은 저장 후 실제 사용자 DTO를 다시 조회한다. 소셜 가입 및 문서 편집용 내부 사용자 객체에도 신규 필드를 명시해 타입과 기존 흐름을 유지했다.

## DB 변경 여부

**변경함. SQL 파일 작성뿐 아니라 프로젝트에 설정된 연결 DB에도 034를 적용했다.**

- `plans.team_sharing_enabled`를 NOT NULL 정수 boolean과 0/1 CHECK 제약으로 추가했다.
- 코드별 표시명·초기 옵션을 변경하고 기존 요금제 버전을 증가시켰다. 기존 `updated_by`와 과거 로그는 보존했다.
- 적용과 `schema_migrations` 등록을 하나의 쓰기 트랜잭션으로 처리했다. 검사 실패 시 롤백했고, ALTER 이전 SELECT의 열 메타데이터 재사용을 피한 조회로 검증한 후 최종 커밋했다.
- 적용 전후 기존 상업 설정 필드 전체, 코드/청구 주기별 구독 분포, 외래키를 비교했다. 새 연결로 네 요금제 명칭·옵션과 034 등록을 다시 확인했다.
- 기존에 미적용으로 표시되던 `023_toast_colors.sql`은 이번 범위와 무관하여 실행하거나 적용 이력을 변경하지 않았다. 일괄 `db:migrate` 대신 034만 적용했다.
- 회원·프로젝트·게시글·댓글·가입 신청·기존 이력 데이터를 삭제하거나 구독을 다른 코드로 이관하지 않았다.

## 미완료 사항 및 참고

- 요청 기능과 관련 DB 변경의 미완료 사항은 없다. 별도의 서비스 배포·운영 프로세스 재시작은 수행하지 않았다.
- 전체 `test-auth.mjs`는 이번 변경 전부터 없는 `/requirements` 등의 옛 독립 화면을 검사한다. 해당 경로는 HEAD에도 없으며 이번 변경으로 삭제하지 않았다. 실패 이전의 인증·가입·프로젝트·산출물·팀 협업 검증은 통과했다. 이와 별도로 최신 경로를 사용하는 accounts, 팀공유, 프로젝트 권한 및 브라우저 검증은 모두 통과했다. 전체 인증 테스트의 구경로 정리는 별도 작업으로 남긴다.
- 다른 환경에 적용할 때도 034 스키마를 먼저 적용한 뒤 새 코드를 실행해야 한다. 이번 연결 DB에서 확인한 미적용 023은 별도 상태 점검 대상이며 무조건 재실행하지 않는다.
