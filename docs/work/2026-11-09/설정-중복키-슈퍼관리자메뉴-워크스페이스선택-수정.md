# 설정 중복 키·슈퍼관리자 메뉴·워크스페이스 선택 수정

- 작성일: 2026-11-09 (Asia/Seoul)
- 기존 변경사항을 보존하며 사용자 후속 요청을 반영했다. 이전 설계의 master 관리자설정 접근 금지는 이번 요청으로 변경한다.

## 주요 변경사항

- 개인 설정의 토큰 통계에서 서로 다른 프로젝트의 `architecture-mermaid` 기록을 같은 React 키로 렌더링하던 문제를 수정했다. 채팅방 선택 항목의 키에 프로젝트 ID와 작업/채팅방 ID를 함께 사용한다.
- master에게 관리자설정 메뉴와 페이지 접근을 허용했다. 현재 관리 권한이 있는 워크스페이스의 회원·프로젝트 필터·가드레일·이력을 제공한다. 상품 ID가 없는 개인 공간에서도 사용할 수 있다.
- 서버에서 실제 master 역할과 해당 공간의 owner/admin 소속을 재검증한다. 다른 공간의 프로젝트 필터·가드레일 접근은 거부한다. 가드레일 저장 트랜잭션에서도 같은 검사를 수행한다.
- 고객 관리자의 상품 범위는 유지한다. Business/Team 상품 지원·계약 운영은 슈퍼관리자설정에 두고, master의 일반 관리자설정에는 상품 지원 추가·회수 기능을 노출하지 않는다.
- 상단의 별도 새 워크스페이스 버튼을 제거하고 선택 상자의 첫 항목에 `+ 새 워크스페이스`를 넣었다. 공간이 한 개여도 선택 상자를 보여 주며, 첫 항목 선택 시 기존 생성 모달을 연다. 기존 공간 선택은 전환 동작을 유지한다.

## DB 변경 여부

- 이번 수정에는 마이그레이션과 실제 DB 변경이 없다. 검증용 계정·프로젝트·사용량은 임시 DB에만 생성했다.

## 검증 결과

- `tsc --noEmit`: 통과.
- 변경 소스 대상 ESLint: 오류·경고 없이 통과.
- `node scripts/test-product-administration.mjs`: 통과. master의 자기 공간 조회, 일반 계정의 해당 경로 접근 차단, 세 메뉴 권한, 기존 상품 격리·정원·결제 정책을 검증했다.
- `node scripts/test-product-administration-browser.mjs`: 통과. 두 프로젝트에 같은 `architecture-mermaid` ID를 넣고 설정 화면에서 둘 다 렌더링되는지, 중복 키 콘솔 오류가 없는지 확인했다. master의 관리자설정 회원·프로젝트·가드레일·이력 접근, 다른 공간 접근 차단, 한 개 공간일 때 선택 상자 첫 생성 항목과 모달 진입도 확인했다.
- master의 자기 워크스페이스 가드레일 초안 저장 API도 임시 DB에서 200 응답과 함께 통과했다.
- 변경 파일의 `git diff --check`: 통과.

## 후속 사항

- 기존 Team 결제사 미정 상태는 유지한다. 이번 수정의 추가 미완료 기능은 없다.
- master의 관리자설정은 선택한 워크스페이스에 관리 소속이 있어야 데이터를 제공한다. 업체·팀 전체 운영은 기존 슈퍼관리자설정을 사용한다.
