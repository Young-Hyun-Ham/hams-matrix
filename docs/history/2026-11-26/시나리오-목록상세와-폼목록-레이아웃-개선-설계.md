## 2. 현재 구조

### 시나리오 목록

[ScenarioList.tsx](../../../app/(builder)/react-flow/scenario-list/ScenarioList.tsx)의 검색 영역은 화면 상단에서 `px: 2`만 지정한 래퍼 안에 있다. 안쪽 MUI `Box`는 `--builder-border` 테두리와 `borderRadius: 2`, `p: 1.5`를 사용한다. 카드 내부는 8px 간격의 가로 폼이며 정렬·기간·배포 상태 선택, 이름 입력, 유연한 빈 영역, 초기화 아이콘, 검색 버튼이 순서대로 배치된다. 공통 입력·선택 컴포넌트의 작은 규격은 높이 24px, 입력 글자 크기 12px이며 초기화 버튼은 32×32px이다.

검색은 `react-hook-form`으로 처리한다. 이름은 검색 버튼이나 Enter로 적용하고 정렬·기간·배포 상태는 변경 시 즉시 반영한다. 초기화는 폼 기본값을 복원하고 다시 조회한다. 검색 카드 아래의 목록과 편집 영역은 남은 높이를 사용하는 별도 flex 영역에 있다.

### 시나리오 상세

[ScenarioView.tsx](../../../app/(builder)/react-flow/scenario-view/ScenarioView.tsx)의 세로 루트는 `gap: 1.5`를 사용한다. 빌더의 기본 MUI 간격 단위 8px을 기준으로 상단 버튼 행과 아래 본문 테두리 사이는 12px이다. 버튼 행은 `px: 1`로 좌우 여백을 두고, 왼쪽에 `목록`, 오른쪽에 시뮬레이터·배포 이력을 배치한다. 화면 위쪽에는 그 12px과 대응하는 패딩이 없다. `목록`은 `goList()`에서 기존 브라우저 이력의 `router.back()`을 호출한다.

[VersionsTreeUI.tsx](../../../app/(builder)/components/VersionsTreeUI.tsx)는 바깥 패널의 폭을 펼침 264px, 접힘 46px로 지정한다. 안쪽 래퍼에도 `width`와 `minWidth`가 각각 264px로 지정되어 있고 접힐 때 `translateX(-218px)`을 사용한다. [VersionsTree.tsx](../../../app/(builder)/components/VersionsTree.tsx)의 루트 폭은 260px이다. 따라서 바깥 폭만 줄이면 내부 행이나 배포 표시가 잘릴 수 있다. `VersionsTreeUI`의 호출처는 현재 상세 화면이며, `VersionsTree`는 이 패널 안에서만 사용된다. 바깥 패널은 사용자 토글과 시뮬레이터 연동으로 접힐 수 있고, 내부에는 기본 그룹 접기와 선택·배포 버전 표시가 별도로 있다.

오른쪽 React Flow 영역은 [Detail.module.css](../../../app/(builder)/components/Detail.module.css)의 `.mainContent`에서 남은 폭을 사용하며 최소 너비 300px을 갖는다. 이 스타일 모듈은 시나리오 편집 화면과 편집 모달에서도 참조한다.

### 폼 목록

[FormList.tsx](../../../app/(builder)/form-builder/list/FormList.tsx)는 `<section>` 아래에 `폼 목록` 제목과 `신규 작성` 링크가 있는 헤더를 렌더링한다. 그 아래 검색 폼은 제목 입력, 정렬 선택, `조회`, `초기화`로 구성된다. [FormList.module.css](../../../app/(builder)/form-builder/list/FormList.module.css)는 헤더·폼·페이지 이동의 flex 규칙을 묶고, 검색 폼에는 16px 패딩, 12px 간격, 8px 모서리, `--builder-muted-surface` 배경을 적용한다. 버튼 스타일 일부는 목록 전체에 적용되며 신규 작성 링크 스타일은 헤더 안의 링크에 연결되어 있다.

`listForms()`가 기존 폼 API의 커서 결과를 가져오고 화면에서 제목 검색·정렬·10개 단위 페이지를 계산한다. 적용한 조건은 `title`, `sort`, `page` URL 값으로 복원된다. 신규 작성의 목적지는 `/form-builder?mode=new`이며 `returnTo`에 현재 적용된 검색 조건과 보정된 페이지를 담는다. 기존 폼 편집 링크도 같은 복귀 주소를 사용한다.

## 3. 수정 방향

### 3.1 시나리오 목록 검색 카드 상단

`ScenarioList.tsx`에서 검색 카드를 감싸는 `px: 2` 래퍼에 `pt: "10px"`을 추가한다. 여백은 카드 테두리 바깥에 적용하고 내부 패딩, 좌우 여백, 검색 조건 및 조회 동작을 유지한다. 화면 전체의 공통 `.builder-content`는 세 화면과 다른 빌더 화면도 사용하므로 여백 지정은 검색 카드 래퍼에 둔다. 목록과 편집 영역의 남은 높이 및 스크롤을 확인한다.

### 3.2 시나리오 상세의 상단 여백과 버전 목록

- 상단 버튼 행의 위쪽에 루트의 기존 행 간격과 같은 값을 적용한다. 루트의 `gap: 1.5`와 상단 패딩 `pt: 1.5`를 같은 값으로 관리하는 방안을 권장한다. 기준점은 빌더 내비게이션 하단에서 버튼 행 상단까지와 버튼 행 하단에서 본문 테두리 상단까지다. 한 줄 화면에서는 `목록` 버튼 자체의 위아래 간격도 확인하고, 좁은 화면에서는 버튼 행 전체를 기준으로 확인한다.
- `VersionsTreeUI.tsx`에서 펼침 폭 132px과 접힘 폭 46px을 한 곳에서 관리한다. 내부 래퍼의 펼침 폭과 접힘 이동 거리도 이 값에서 계산한다. 기존과 같은 이동 방식을 유지하면 이동 거리는 86px이다. 일반 너비에서는 패널이 flex 배치로 추가 축소되지 않도록 하며, 기준 폭을 패널 테두리를 포함한 실측값과 맞춘다.
- `VersionsTree.tsx`의 고정 260px은 부모 폭을 따르도록 바꾼다. 한 개의 세로 스크롤 영역에서 모든 버전에 접근할 수 있게 하고, 행 안에서 배포 체크 아이콘과 버전 번호가 함께 보이도록 패딩과 간격을 점검한다. 버전 선택 상태, 사용자 토글, 기본 그룹 접기, 시뮬레이터 연동 접힘을 유지한다.
- 줄어든 폭은 오른쪽 캔버스에 배분한다. 132px 패널과 기존 300px 최소 캔버스 폭을 기준으로 좁은 화면을 확인한다. 추가 대응이 필요하면 상세 화면의 레이아웃에서 적용한다. 목록 복귀, 버전 조회·선택·복원·배포 호출은 기존 경로를 사용한다.

### 3.3 폼 목록 검색 카드

- 상단 헤더를 제거하고 검색 카드 안에 `제목 입력 → 정렬 선택 → 초기화 → 조회 → 신규 작성` 순서로 배치한다. 가로 공간이 충분할 때는 제목·정렬을 왼쪽에, 동작 버튼과 링크를 오른쪽에 둔다. 여유 폭은 CSS flex로 배분한다. 좁은 화면에서는 카드 안에서 컨트롤을 줄바꿈하고 그 줄의 오른쪽 끝에 `신규 작성`을 둔다.
- 시나리오 목록의 1px 테두리, 작은 모서리, 약 12px 내부 여백과 8px 컨트롤 간격, 작은 입력 높이와 라벨 배치에 맞춘다. 카드의 별도 강조 배경을 걷고 빌더 배경과 어울리게 한다. 입력·테두리·포커스와 주요 버튼은 기존 `--builder-*` 테마 변수를 사용한다. 폼 목록의 검색 영역 전용 클래스에서 이 스타일을 적용한다.
- `조회`는 submit 버튼, `초기화`는 일반 버튼, `신규 작성`은 기존 `Link`로 유지한다. 검색 폼 안으로 이동한 링크는 해당 폼을 제출하지 않으며, 목적지의 `mode=new`와 `returnTo`는 그대로 사용한다. 키보드로 제목에서 Enter를 누르면 조회가 동작하고 Tab으로 신규 작성에 진입할 수 있다.
- 화면에 보이던 제목을 제거하는 대신 목록 섹션의 접근성 이름을 `폼 목록`으로 제공한다. 검색 폼은 `폼 검색`으로 식별하고 기존 입력 라벨과 포커스 표시를 유지한다. 결과 표, 상태 메시지, 페이지 이동, 편집 링크에는 기존 스타일과 동작을 적용한다.

## 5. 검증 방법

검증은 구현 후 테스트용 빌더 관리자 계정과 임시 DB에서 진행한다.

| 검증 대상 | 방법 및 기대 결과 |
| --- | --- |
| 시나리오 목록 여백 | 개발자 도구로 내비게이션 하단과 검색 카드 상단의 차이가 약 10px인지 확인한다. 검색 버튼과 Enter, 정렬·기간·배포 상태 변경, 초기화, 결과 스크롤과 목록의 상세 진입을 확인한다. |
| 상세 버튼 행 | 데스크톱에서 `목록` 버튼과 내비게이션·본문 사이의 위아래 간격을 측정한다. 버튼이 줄바꿈되는 좁은 화면에서는 행 바깥의 상하 여백과 우측 버튼의 접근성을 확인한다. 목록에서 상세로 진입한 뒤 `목록`으로 복귀한다. |
| 상세 버전 목록 | 펼침 약 132px, 접힘 약 46px, 스크롤 및 가로 잘림 여부를 확인한다. 0개·여러 개·여러 자릿수 버전으로 기본 그룹 토글, 배포 체크, 현재 선택, 과거 버전 클릭 후 캔버스 전환을 확인한다. 시뮬레이터를 열고 닫을 때의 접힘 연동과 캔버스 조작도 확인한다. |
| 폼 목록 배치 | 시나리오 목록과 폼 목록을 같은 라이트·다크 테마에서 비교한다. 상단 헤더가 사라지고 검색 카드 안에 `신규 작성` 링크가 하나만 있는지 확인한다. 좁은 창에서 컨트롤 겹침, 가로 스크롤, 포커스 잘림 여부를 확인한다. 결과 표의 기존 자체 스크롤은 별도로 확인한다. |
| 폼 목록 동작 | 검색어와 정렬을 적용하고 다음 페이지로 이동한 상태에서 신규 작성과 기존 폼 편집을 각각 연다. 편집기의 `목록`으로 돌아왔을 때 검색·정렬·페이지가 복원되는지 확인한다. 검색 Enter, 초기화, 빈 결과와 재조회도 확인한다. |

기존 `node scripts/test-builder-browser.mjs`의 과거 버전 전환과 폼 목록·편집 진입 시나리오를 회귀 확인에 활용한다. 간격과 폭은 개발자 도구에서 실측한다. 이전 구현 기록에는 기존 브라우저 스크립트가 시뮬레이터의 `.builder-emulator`를 기다리다 중단된 결과가 있어, 같은 문제가 재현되면 세 화면의 검증을 수동으로 진행하고 스크립트 결과를 따로 기록한다. [이전 브라우저 검증 기록](../../../docs/work/2026-11-26/시나리오빌더-노드펼침과-테마개선-구현.md)
