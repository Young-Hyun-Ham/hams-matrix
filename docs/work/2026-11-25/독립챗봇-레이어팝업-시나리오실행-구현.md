# 독립 챗봇 레이어 팝업 및 시나리오 실행 구현

- 작성일: 2026-11-25 (Asia/Seoul)
- 기준: [최신 설계](../../history/2026-11-25/독립챗봇-레이어팝업-시나리오실행-설계.md)를 작업 시작 시 다시 읽었다.
- 상태: 소스 구현과 구성 DB의 054 적용, 최종 검증 및 관련 문서 갱신 완료.

## 주요 변경사항

- `components/chatbot/`에 별도 챗봇을 구현했다. 인증된 workspace·builder·database·planning-board·control-tower layout에 단일 호스트를 배치하고 우측 하단 원형 버튼 → 위쪽 메뉴 → 새 채팅 → DOM 레이어 팝업으로 연결했다.
- 기존 AI Chat의 API·방·메시지·설정·승인·사용량 저장소와 분리했다. 기존 챗봇 메뉴와 기능은 유지한다. 샘플 `/api/chatbot`은 `/api/sample/chatbot`으로 이동했다.
- 시안의 좌측 이력, 인라인 제목 변경·삭제, 메시지, 입력 메뉴, 자체 설정 패널을 구현했다. 자체 8개 테마와 언어·긴 답변 접기·placeholder를 사용자/workspace별로 저장하며 미리보기·저장·취소·버전 충돌을 처리한다. Matrix 테마를 변경하지 않는다.
- 입력 `☰`의 이미지 생성/파일 생성은 각각 `시각화 및 수정`/`문서 및 수정` tooltip을 제공한다. 입력 앞 모드 문구·색상과 허용 모델을 함께 바꾸고 입력·첨부를 보존한다. 서버에서도 모드와 모델을 검증한다.
- 일반 채팅, 이미지 생성·참조 이미지 수정, Markdown/텍스트 파일 생성·수정·다운로드를 신규 API로 연결했다. 생성물은 별도 버전으로 저장하며 기존 버전 교체는 서버 보관 변경안의 HITL 승인을 거친다. 후보 이미지의 검토 미리보기와 이전 버전을 제공한다.
- 정책 차단의 관리자 승인 요청/반려/취소/요청자 재개를 별도로 구현했다. 관리자 UI는 기존 관리자 범위와 진입 프로젝트 owner 조건을 확인한다. 완료된 모델 결과와 검사 결과를 저장해 재개 시 유료 호출을 반복하지 않는다.
- Flow와 View 시뮬레이터를 같은 팝업으로 전환했다. View에는 누락되어 있던 실행 버튼도 추가했다. 현재 그래프 snapshot을 서버에서 고정하고 자동 시작하며 일반 대화 이력 UI/API를 사용하지 않는다. 빌더 실행 이력은 별도 메뉴에서 읽기 전용으로 확인한다.
- 서버 시나리오 실행은 메시지·조건/선택 분기·폼·slot·setSlot·delay·포함된 하위 그래프·API·LLM을 처리한다. 기존 숫자 열/평탄 배열 그리드와 객체 행, 선택지, 날짜 범위 입력을 정규화·검증한다. 외부 API는 승인 후 실행하고 확인된 HTTP 실패는 오류 분기로 진행하며 불명확한 결과는 자동 재실행하지 않는다.
- 링크는 명시적으로 열고, iframe은 허용된 HTTPS 주소만 사용해 사용자가 표시를 선택했을 때 sandbox로 표시한다. 스크립트·폼 실행을 허용하지 않는다.
- 요청/실행의 멱등키·서버 seq·잠금 만료·중단·원본/정책/권한 재검증과 별도 이벤트 이력을 추가했다. 긴 실행 이력은 seq 커서로 추가 조회한다.
- 첨부·생성 바이너리와 실행 checkpoint는 소유 범위를 AAD에 포함해 암호화한다. R2는 `chatbot/` 전용 prefix를 사용하며 임시 업로드 원장과 만료/고아 객체 정리를 추가했다.
- 독립 작업자는 기본 동시성 2로 실행한다. `pnpm dev`/`pnpm start`의 기존 감독 프로세스가 함께 실행하며 정리 실패가 일반 생성 작업을 막지 않게 했다. 실제 운영 프로세스를 이번 작업에서 재시작하지는 않았다.

## DB 변경

- 구성된 DB에 `054_chatbot_storage.sql`만 선택 적용했다. 다른 미적용 migration을 일괄 실행하지 않았다.
- 신규 16개 테이블: `chatbot_conversations`, `chatbot_user_settings`, `chatbot_turns`, `chatbot_messages`, `chatbot_requests`, `chatbot_attachments`, `chatbot_artifacts`, `chatbot_artifact_versions`, `chatbot_reviews`, `chatbot_policy_events`, `chatbot_policy_approvals`, `chatbot_approval_events`, `chatbot_scenario_runs`, `chatbot_scenario_run_events`, `chatbot_usage`, `chatbot_blob_uploads`.
- owner 복합 FK, 상태/JSON 제약, 실행·승인·버전/이벤트 인덱스와 불변 제약을 추가했다. 기존 `ai_*` 방/메시지/승인으로의 FK나 데이터 이전은 없다.
- 실제 DB 적용 전후 기존 스키마 hash와 AI·빌더·사용자/워크스페이스·프로젝트·개인 설정 테이블 건수를 비교해 동일함을 확인했다. 신규 테이블 16개와 migration 이력, 외래키 위반 0건, integrity `ok`를 확인했다.
- 실제 DB에는 회귀용 계정·채팅·파일·실행 데이터를 만들지 않았다. 테스트는 임시 DB·합성 계정·모의 AI·메모리 객체 저장소를 사용했다.

## 운영 및 범위 제한

- 이미 실행 중인 개발/운영 프로세스에는 작업자가 추가되지 않으므로 `pnpm dev`/`pnpm start`를 재시작해야 한다. 별도 상시 작업자는 `pnpm worker:chatbot`, 정리는 `pnpm cleanup:chatbot`으로 실행한다. 서버리스 환경도 별도 작업자가 필요하다.
- 모델/키는 기존 서버 설정을 기본으로 사용한다. 필요할 때 `CHATBOT_OPENAI_API_KEY`, `CHATBOT_TEXT_MODELS`, `CHATBOT_IMAGE_MODELS`, 기본 모델 변수와 `CHATBOT_WORKER_CONCURRENCY`로 분리할 수 있다. 값은 이 문서에 기록하지 않는다.
- 파일 저장에는 기존 R2 및 암호화 설정이 필요하다. API/iframe 대상은 `CHATBOT_API_ALLOWED_HOSTS`, 인증 헤더는 서버 전용 `CHATBOT_CONNECTOR_HEADERS`로 제한한다. 그래프 안의 비밀값이나 브라우저 직접 외부 호출을 허용하지 않는다.
- 현재 파일 출력은 `.md`/`.txt`다. Office/PDF, 시안의 즐겨찾기·Fast/Deep·Personal/Chatbot 전환·피드백·도움말은 설계의 추가 결정 항목으로 남긴다. 동작 없는 옵션은 추가하지 않았다.
- 하위 시나리오는 포함된 자식 그래프를 실행한다. 외부 참조만 있는 시나리오와 폼 내부의 동적 API는 시작 전 명시 오류로 처리하며, 자식 그래프 또는 승인 가능한 API 노드로 구성해야 한다.
- 방은 논리 삭제하고 감사/생성물 버전은 보존한다. 미사용 업로드/고아 객체 및 승인 대기는 기본 24시간 기준으로 정리한다. 장기 보존·개인정보 삭제 정책은 별도 결정 대상이다.
- 전체 Query 감사의 기존 14개 미분류와 빌더 전체의 기존 린트 정리는 이번 구현에서 임의 변경하지 않았다. 재개 시 최신 설계·이 기록을 읽고 신규 테스트와 해당 기존 영역을 구분해 검증한다.

기존 사용자 변경인 `PROMPT.md`, 설계 문서, 시안 이미지 및 이전 이력 목록은 보존했다. 비밀번호·키·토큰·DB 접속 정보는 작업 문서에 기록하지 않는다.
