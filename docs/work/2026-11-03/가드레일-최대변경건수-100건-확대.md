# 가드레일 최대 변경 건수 100건 확대

- 작성일: 2026-11-03 (한국시간)

## 주요 변경사항

- 관리자 가드레일의 ‘한 요청의 최대 변경 건수’ 입력란을 0~100 정수로 설정할 수 있도록 변경했다.
- 클라이언트 입력 상한과 서버 정책 검증에서 공통 상수 `MAX_GUARDRAIL_CHANGES=100`을 사용한다.
- AI 산출물 변경 제한은 활성 정책의 `maxChanges`를 따르며, 초과 오류 메시지도 실제 설정값을 표시한다.
- 공통 AI 응답 처리에 남아 있던 응답당 도구 호출 3개 제한을 101개(100개 변경과 1개 조회)로 확대했다. 실제 변경 건수는 에이전트에서 별도로 정책값을 검사한다.
- 기본값과 기존 활성 정책은 3건 등 현재 값으로 유지한다. 관리자가 초안에서 원하는 값으로 수정하고 정책을 적용해야 새 요청에 반영된다.
- 토큰·시간·AI 실행 단계 제한은 유지한다. 100건은 허용 상한이며 모든 요청의 100건 생성 완료를 보장하는 값은 아니다.

## 변경 파일

- `lib/ai/guardrail-types.ts`: 설정 상한 상수.
- `lib/ai/guardrail-policy.ts`: 0~100 정수 검증.
- `components/admin/guardrail-admin.tsx`: 입력란 max=100, step=1.
- `lib/ai/page-tools.ts`: 설정값을 반영하는 초과 메시지.
- `lib/ai-server.ts`: 도구 호출 배치 상한 확대.
- `scripts/check-guardrail-change-limit.mjs`, `scripts/test-rfp-source.mjs`: 변경 한도 전용 검증.
- `docs/AI_GUARDRAILS.md`, `components/ai/README.md`: 설정 범위와 적용 방법 설명.
- `WORK_HISTORY.md`: 작업 기록 링크.

## DB 변경 여부

- 스키마 및 운영 데이터 변경 없음. 활성 정책을 자동 변경하지 않았다.
- 검증은 임시 SQLite와 모의 AI 응답으로 수행하며 유료 AI 호출은 없다.

- `node scripts/test-rfp-source.mjs --change-limit-only`: 통과.
  - 0·3·4·99·100 허용, 음수·101·소수·문자열·null 거부.
  - 실제 WBS 변경안 100건 검증 및 트랜잭션 내 100건 저장 확인 후 롤백.
  - 101번째 변경 거부, 0건 정책 적용, 기존 기본값 3 유지.
  - 모의 AI 응답의 101개 도구 호출 처리와 102개 초과 거부 확인.
- 전체 TypeScript 검사 및 변경 파일 ESLint 통과.
- 변경 소스 diff 공백 검사 통과.

## 미완료 사항

- 없음. 관리자 화면에서 정책을 수정·적용하는 운영 작업은 수행하지 않았다.
