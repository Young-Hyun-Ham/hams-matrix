# 가드레일 컨트롤타워 관제 화면 개편 구현

- 작성일: 2026-11-23 (한국시간)
- 기준: 최신 [설계 문서](../../history/2026-11-23/가드레일-컨트롤타워-관제화면-개편-설계.md)를 재확인하여 기본안으로 구현.
- 상태: 구현 및 관련 검증 완료.

## 주요 변경사항

- 전용 좌측 메뉴와 상단 헤더, 관제 대시보드/승인 대기열/처리 이력, 목록 미리보기와 같은 창의 전체 상세 검토를 구성했다. 기존 view 없는 진입은 승인 대기열, approvalId 직접 링크는 상세로 유지한다.
- 실제 DB에서 KST 오늘 검사/차단, 현재 승인 상태, pending 중 2시간 내 만료 요청, 최근 검사 20건·임박 요청 5건, 정책/단계 분포를 집계하는 읽기 전용 overview API를 관리자/슈퍼관리자 경로에 추가했다. 정책 테스트 포함을 표시하며 검사 건수와 실행 횟수를 구분한다.
- 기존 승인 의견·범위 확인·확정/반려·canDecide·owner/admin 자기 요청 승인·사용자 명시적 재개는 보존했다. 기존 목록 필터·커서·정렬과 Query scope를 유지하고 메뉴/상세 전환 시 목록 조건·선택·스크롤과 브라우저 이력을 복원한다. 상태 탭이 바뀌면 페이지 커서와 이력 상태 조건을 초기화한다. 의견 초안 이동/닫기 보호를 추가했다.
- 상단 우측에 공통 ThemeToggle을 연결했다. 공통 PreferencesRuntime에서 같은 사용자 storage 이벤트를 받은 뒤 DB API를 재조회한다. 연속 이벤트는 합치고 조회 중 추가 이벤트는 후속 재조회한다. 저장 중은 지연하고 기존 version/owner/generation 및 초안 병합을 유지한다. storage payload는 설정으로 신뢰하지 않는다.
- 공통 테마 토큰과 390px부터 데스크톱까지의 반응형 배치를 적용했다. 최근 이벤트는 카드 내부 스크롤로 대시보드 높이를 제한했다. 이미지의 가상 R등급·지역·당직·2인 승인·에이전트 정지 기능은 추가하지 않았다.

## DB 변경 여부

- 추가 DB 변경/마이그레이션 없음. 기존 017 검사 이벤트·051 승인/이력·개인 설정 테이블을 사용한다.
- 실제 구성 DB에 fixture를 넣거나 운영 데이터를 수정하지 않았다. 임시 DB에서 실행 계획을 확인해 검사 기간 집계가 기존 `idx_guardrail_events_scope` 인덱스를 사용하는 것을 검증했다.
- 기존 승인 count의 만료/abandoned lease 정리를 재사용한 뒤 읽기 트랜잭션에서 기준 시각을 고정해 집계한다.

## 미완료 사항 및 재개 정보

- 요청 범위 내 미완료 사항 없음. 재검증은 `node scripts/test-ai-guardrail-approvals.mjs --browser`(먼저 pnpm build), `node scripts/test-personal-preferences.mjs`를 사용한다. 브라우저 검증 스크립트는 자기 테스트 서버·Chrome을 종료하며 합성 화면 스크린샷은 임시 fixture 폴더에 남긴다.
- 테마 동기화는 같은 사용자·같은 브라우저 origin의 storage 이벤트를 사용한다. 저장소가 차단된 환경에서는 각 창 저장/테마 전환은 동작하고 다른 창은 다음 설정 조회/새로고침 때 반영된다.
- 추가 에이전트 제어·업무별 R등급·2인 승인·보고서/기준 데이터 기능은 설계의 확장 범위로 남긴다.
