# 일괄 생성 설계 근거와 직접 인용 구분

- 작성일: 2026-11-16 (한국시간)
- 현상: 사업계획서 일괄 생성이 '원문과 생성 근거가 일치하지 않습니다.' 오류로 실패함. 실패 시 롤백 범위도 확인 요청.
- 실제 확인: 기존 AI 응답 75개 중 64번째 프로그램 문서 1개에서 설계 도출 요약을 excerpt로 반환했다. 원본은 존재했고 공백 정규화로도 일치하지 않아 단순 줄바꿈 차이는 아니었다. 새 AI 생성은 호출하지 않았다.

## 변경 사항

- 출처 번호는 모든 경우에 실제 원본을 가리켜야 한다. 잘못된 번호는 항목 순번을 포함하여 거절한다.
- '원문 명시'의 잘못된 직접 인용은 계속 차단한다. 정확한 인용과 빈 excerpt는 기존대로 처리한다.
- '설계 도출'의 발췌가 원문과 다르면 직접 인용으로 저장하지 않고 excerpt를 비워 전체 원문 snapshot을 연결한다. origin은 설계 도출로 유지하고 항목별 evidenceWarnings를 payload/상태 DTO/생성 화면에 표시하여 검토가 필요함을 알린다. 해당 요약이 원문에 있다는 주장으로 처리하지 않는다.
- 프롬프트에 직접 인용은 연속 부분 문자열이어야 하며, 설계 요약은 excerpt가 아닌 rationale에 작성하도록 명시했다.

## 롤백 범위

- 이번 실패는 stage 0의 AI 응답 검증 단계다. 산출물 업무 저장 이전이므로 일부 문서가 저장되는 경로가 아니다.
- 최종 stage 1은 commitDeliverables 호출, 전체 산출물·연결·출처 연결·관리번호 시퀀스·변경 이력과 completed 상태를 동일한 write 트랜잭션에 저장한다. 오류 시 rollback하며 기존 산출물은 유지한다.
- 작업 등록 트랜잭션에서 만든 원본 snapshot과 요청 행은 별도로 이미 확정되어 있다. 실패 상태, AI 응답 ID, 사용량·보안 이벤트 등 진단 기록은 남는다. 이미 실행된 외부 AI 호출은 DB 롤백으로 취소되지 않는다.

## 변경 파일 및 DB

- lib/ai/deliverable-batch-commit.ts: 출처 검증/설계 도출 처리 공통 함수.
- lib/ai/deliverable-generation.ts: 근거 처리 및 상태 경고 DTO.
- lib/ai/deliverable-generation-prompt.ts: 발췌·요약 구분 지시.
- components/shared/deliverable-generation-dialog.tsx: 근거 검토 경고.
- scripts/test-deliverable-generation.mjs, scripts/test-artifact-detail-navigation-browser.mjs: 회귀 검증.
- README.md, AGENTS.md, CLAUDE.md, WORK_HISTORY.md 및 이 기록.
- DB 스키마 변경 없음. 실제 사용자 산출물을 새로 생성하거나 실패 요청을 재저장하지 않았다.
