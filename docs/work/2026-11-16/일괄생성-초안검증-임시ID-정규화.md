# 일괄 생성 초안 검증과 임시 ID 정규화

- 작성일: 2026-11-16 (한국시간)
- 현상: 사업계획서 일괄 생성이 '생성 문서의 형식·ID·필수값을 확인해 주세요.' 오류로 종료됨.
- 확인 원인: 실제 AI 응답 51개의 clientRef가 모두 @ 없는 임시 ID였다. 서버는 @ 접두사를 요구했으나 AI 응답 스키마는 문자열 타입만 제한했고 프롬프트도 clientRef 자체의 규칙을 명확히 설명하지 않았다. 제목·목적·개요 누락이 원인은 아니었다.

## 주요 변경

- 선언된 clientRef의 @ 누락을 정규화하고, 같은 생성의 links도 해당 임시 ID로 일관되게 변환한다. 기존 문서 ID나 선언되지 않은 참조는 임의로 바꾸지 않는다. 실제 저장 ID·관리번호 발급은 기존대로 서버가 수행한다.
- @ 유무만 다른 중복 ID도 거절한다. 빈 값이나 잘못된 문자를 임의로 보충하지 않는다.
- 기존 포괄 오류를 항목 순번·문제 필드·실패 사유를 포함하는 오류로 구분했다.
- AI 응답 수락 단계에서 수동 저장과 같은 skeleton 검증을 적용한다. 초안 필수값은 제목, 목적, 개요 및 요구사항의 유효한 분류이며 상세 완성 단계의 필수값·날짜·DB 컬럼을 임의 생성하지 않는다. 미확정 상세 문자열은 빈 문자열을 허용한다.
- 생성 지시에 임시 ID 형식과 예시, 서버 관리번호 발급, 초안 필수값·길이·미확정 상세 처리 원칙을 명시했다.
