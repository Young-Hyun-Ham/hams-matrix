# AI 챗봇 창 모드 마우스 너비 조절 구현

- 작성일: 2026-11-18 (한국시간, Asia/Seoul)
- 기준: [최신 설계 문서](../../history/2026-11-18/AI챗봇-창모드-마우스-너비조절-설계.md)를 다시 읽고 D1~D7의 권장안을 적용했다. 문서 작성 단계의 구현 금지는 이번 사용자의 구현 요청으로 전환했다.
- 상태: 구현 및 관련 검증 완료.

## 주요 변경사항

- 팝업 양쪽 8px 영역에서 마우스/터치로 너비를 조절한다. 반대 경계와 y/높이를 고정하고 최소 360px·화면 안쪽 12px를 적용한다. 작은 화면에서는 화면 제한을 우선한다.
- 키보드 좌우 10px, Shift 조합 40px, Home/End 최소/최대를 제공하고 접근성 이름·너비 범위·포커스 표시를 추가했다.
- 사용자 지정 너비를 상하/분리별 메모리에 보관한다. 닫기·패널 전환에서 복원하고 확대/축소는 현재 슬롯을 해제한다. 분리 진입은 기존 확대 프리셋으로 초기화한다.
- 창 이동과 크기 조절의 capture를 공통 관리하고 취소·포커스 이탈·viewport 변경·닫기·모드 변경에서 정리한다. 화면 축소 시 표시 너비를 제한하고 다시 넓어지면 희망 너비를 복원한다.
- 표시 너비로 입력 열의 실제 추가분(최대 100px)을 계산하며 기존 내부 콘텐츠 560px 분기와 채팅 DOM/초안을 보존한다.

## 변경 파일

- `components/ai/use-ai-window.ts`: 수동 너비·포인터 조작·키보드·경계·복원 정책.
- `components/ai/ai-workspace-layout.tsx`: 가장자리 요소·CSS 변수·접근성/크기 안내.
- `styles/ai-workspace-layout.css`: 팝업 너비·입력 열 보너스·핸들 표시.
- `scripts/check-ai-window-browser.mjs`, `scripts/check-ai-window-resize-browser.mjs`: 기존 fixture를 이용한 실제 조작 회귀 검증.
- `components/ai/README.md`, `README.md`, `AGENTS.md`, `CLAUDE.md`, `WORK_HISTORY.md`: 조작법·유지보수 지침·작업 링크.

## DB 변경 여부

없음. 스키마·마이그레이션·운영 DB를 변경하지 않는다. 사용자 지정 너비는 React 메모리 상태이며 브라우저 저장소에도 기록하지 않는다. 브라우저 회귀만 기존 격리 fixture의 임시 SQLite를 사용한다.

## 검증 결과

- `pnpm typecheck`: 통과.
- 변경 소스·검증 스크립트 ESLint: 통과.
- `pnpm build`: 통과. 정적 페이지 생성 중 기존 `Request failed Error` 메시지가 출력되었으나 전체 빌드는 정상 종료했다.
- `pnpm test:ai-targets-browser`: 통과(exit 0). 실제 양쪽 마우스 조절과 capture, 주 버튼 제한, 360px 최소·화면 12px 경계, 방향키/Shift/Home/End, 터치, 취소·capture 해제·blur·resize·닫기 종료 처리를 확인했다.
- 같은 브라우저 실행에서 수동 너비의 모드별 복원, 860px 초과 확장, viewport 축소/복원 및 높이만 변경한 위치 보정, 입력 열 0/60/100px 배분, 실제 내부 너비 559/560/561px 분기, 입력·모델·대상·첨부·DOM 보존 및 순수 조절 시 추가 AI/access 요청 없음이 통과했다.
- 기존 패널/팝업 460/560/860px 프리셋, 100/40/0px 입력 열 추가분, footer 정렬·독립 스크롤·dark/낮은 높이와 AI 대상 변경·생성·저장 실패·진행 상태·임시 대화 회귀도 통과했다.
- 브라우저 검증의 capture 종료 입력은 CDP 왼쪽 버튼과 실제 이동 좌표를 명시하도록 보정했다. 진단용 이벤트 기록은 제거했다.
- 검증 스크립트 문법 및 변경 파일 `git diff --check`, 작업 문서 링크: 통과. 스크린샷 등 임시 증거는 `matrix-navigation-browser-bSL4ex` 검증 폴더에 생성되었다.
- 초기 sandbox 실행은 node_modules 접근 제한으로 실패했으며, 권한 검토 후 검사와 빌드를 재실행했다.
