### 2.2 메뉴와 계정 영역

- `lib/menus.ts`의 `navigationMenus`가 메뉴명·아이콘·이동 경로·동작을 정의한다. 현재 상단은 대시보드·팀 공유·AI Chatbot, 하단은 요금제·설정·문서뷰어·관리자설정·도움말로 나뉜다.
- `WorkspaceShell`은 전역 관리자 여부와 `activeUser.teamSharingEnabled === true`로 메뉴를 필터링한다. 이 결과를 사이드바와 메뉴 검색이 함께 사용한다. 축소 상태에서도 동일한 필터와 순서를 유지해야 한다.
- `renderMenus()`의 일반 링크와 도움말 버튼은 `<Icon />` 다음에 메뉴명 문자열을 직접 출력한다. 축소 시 이름만 숨길 수 있도록 명시적인 텍스트 래퍼가 필요하다.
- 대시보드에는 `.nav-dot`, 팀 공유에는 `.nav-new` 배지가 있다. 축소 시 배지가 남으면 아이콘 정렬과 너비를 방해할 수 있다.
- `.sidebar-user`에는 아바타, 이름·이메일을 가진 `.user-summary` 버튼, 로그아웃 아이콘 버튼이 있다. 계정 요약 클릭은 `/settings?tab=account`로 이동한다.
- 로그아웃 버튼은 이미 존재하며 `logout()`을 호출한다. `POST /api/auth/logout` 성공 또는 401이면 사용자 상태를 비우고 `/login`으로 이동한 뒤 새로고침한다. 실패하면 사이드바 내부 `.error-message[role=alert]`에 오류를 표시하며 요청 중에는 `busy`로 버튼을 비활성화한다.
- `app/api/auth/[action]/route.ts`의 로그아웃은 세션 폐기·감사 이력·쿠키 삭제를 수행한다. 이번 UI 변경에 API나 DB 구조 수정은 필요 없다.

### 2.3 AI 메뉴·툴팁·스타일

- `components/ai/ai-conversation-menu.tsx`의 `AiChatbotToggle`은 일반 메뉴 렌더링과 별도다. 자체 `.nav-item` 버튼에 이름·펼침 화살표가 있고, `aiMenuOpen`이면 패널 안에 대화 목록을 렌더링한다. 메뉴 텍스트만 숨기면 대화 목록이 좁은 패널 안에서 잘린다.
- `components/ai/ai-workspace-layout.css`는 960px 이하에서 AI 패널을 fixed로 배치하고 `left: 210px`, 너비 계산과 backdrop에도 `210px`를 사용한다. 701~960px에서 메뉴를 축소하면 이 값이 남아 패널과 AI 창 사이가 벌어진다. 모바일에서는 별도 `left: 0` 규칙이 있다.
- 같은 AI CSS의 상단 오프셋은 73px/65px이고 현재 헤더 높이는 54px/50px이다. 기존 수치 불일치가 있으므로 이번 변경에서는 가로 오프셋을 우선 수정하고, 세로 배치까지 함께 보정할지는 결정한다.
- `.sidebar`는 `overflow-y: auto; overflow-x: hidden`이며 `z-index: 40`이다. 자식에 툴팁을 absolute로 붙이고 z-index만 높여도 스크롤 컨테이너 밖은 잘릴 수 있다.
- 확인한 공통 메뉴 구현에는 재사용 가능한 메뉴 툴팁 컴포넌트가 없다. `Icon`의 SVG는 `aria-hidden="true"`라서 텍스트를 숨길 때 링크·버튼의 접근 가능한 이름을 별도로 보장해야 한다.
- `styles/themes.css`, `styles/personal-theme.css`가 메뉴의 라이트·다크·강조색을 처리하며, `styles/accessibility.css`는 모션 감소 설정을 처리한다. 툴팁도 기존 색상 변수와 포커스 표시를 사용한다.
- `Brand`는 공용 컴포넌트다. 축소용 심벌 표시를 위해 수정한다면 로그인·게스트 등 다른 사용처에 대한 영향도 확인해야 한다.

## 3. 수정 방향: 권장 설계안

### 3.1 상태와 반응형 정책

데스크톱은 **펼침 ↔ 아이콘 축소**, 모바일은 기존 **드로어 열림 ↔ 닫힘**으로 유지하는 안을 권장한다. 모바일에도 아이콘 패널을 남기는 것은 별도 결정 사항이다.

| 상태 | 패널 표시 | 하단 계정 영역 | 헤더 버튼 | 툴팁 |
| --- | --- | --- | --- | --- |
| 데스크톱 펼침 | 기존 너비, 심벌·브랜드명·메뉴명·배지 표시 | 기존 아바타·이름·이메일·로그아웃 | 클릭하면 축소 | 메뉴 아이콘/항목에 hover·포커스 시 이름 |
| 데스크톱 축소 | 64px 제안, 심벌·메뉴 아이콘 표시 | 계정 요약·아바타 숨김, 로그아웃 아이콘 표시 | 클릭하면 펼침 | 오른쪽에 메뉴명, 로그아웃은 `로그아웃` |
| 모바일 열림 | 기존 260px 드로어·오버레이 | 기존 계정정보와 로그아웃 | 클릭하면 닫힘 | 키보드 포커스 지원, 터치 클릭은 기존 동작 |
| 모바일 닫힘 | 기존 화면 밖 숨김 | 드로어 내부이므로 보이지 않음 | 클릭하면 열림 | 숨겨진 패널의 툴팁 미표시 |

모바일 닫힘에서도 로그아웃·아이콘 노출이 필요하다는 뜻으로 요구사항을 해석한다면 위 모바일 두 행은 수정해야 한다. 이 초안은 이를 확정된 예외로 처리하지 않고 7절의 검토 사항으로 남긴다.

- 기존 `desktopSidebarOpen`과 `sidebarOpen`을 분리 유지한다. UI 계산용 축소 여부는 `!isMobile && !desktopSidebarOpen`으로 파생하고 별도 저장 상태를 추가하지 않는다.
- 새로고침 시 펼침으로 시작하는 현재 동작을 유지하는 안을 권장한다. localStorage·서버 환경설정 저장은 추가하지 않는다.
- 모바일 진입 시 데스크톱 축소 스타일은 해제되며, 데스크톱 복귀 시 이전 데스크톱 펼침/축소 상태를 사용한다.
- body 스크롤 잠금과 오버레이의 유효 조건은 `isMobile && sidebarOpen`으로 제한하는 방향을 검토한다. 모바일에서 메뉴를 연 채 데스크톱으로 전환해도 스크롤이 잠기지 않아야 한다.
- JS의 700px 판정과 CSS 미디어쿼리 경계를 일치시킨다. `isMobile`이 effect 이후 설정되는 초기 렌더링에서도 모바일 메뉴명이나 계정정보가 잘못 숨겨지지 않도록 CSS의 데스크톱 범위로 표시 규칙을 제한한다.

### 3.2 너비·정렬·레이아웃

1. `.workspace` 범위에 현재 패널 점유 너비를 나타내는 CSS 변수(예: `--workspace-sidebar-width`)를 둔다. 데스크톱 기본값 240px, 1200px 이하 214px, 960px 이하 210px, 축소 시 64px, 모바일 본문 점유값 0으로 설계한다.
2. `.sidebar` 너비와 `.workspace-body`의 `margin-left`가 같은 값을 사용하도록 한다. 모바일 드로어의 실제 너비 260px는 본문 점유값과 구분한다.
3. 데스크톱 접힘의 `translateX(-100%)`를 제거하고 너비·본문 여백을 함께 전환한다. 반응형 규칙 뒤에서 축소값이 덮이지 않도록 선택자 우선순위와 선언 순서를 확인한다.
4. 축소 상태에서는 심벌을 가운데 정렬하고 브랜드명·`WORKSPACE` 캡션·메뉴 텍스트·배지·AI 화살표를 숨긴다. 이름만 담는 클래스와 아이콘/배지 클래스를 명확히 구분하며 `.nav-item span` 또는 `.brand > span` 전체 숨김처럼 심벌까지 지우는 규칙을 피한다.
5. 메뉴·로그아웃의 클릭 영역은 최소 44×44px를 목표로 한다. 64px 너비에서는 좌우 10px 여백으로 배치할 수 있다. 현재 도움말은 35px 높이이므로 축소 상태에서 높이를 별도로 맞춘다.
6. 하단 메뉴와 계정 영역은 기존 순서를 유지한다. 높이가 충분할 때 아래에 정렬하고, 낮은 화면에서는 스크롤로 로그아웃에 도달할 수 있어야 한다. 기존 `.sidebar-content`의 `min-height: 600px`와 전체 스크롤 구조를 함께 확인한다. 화면 높이와 관계없이 로그아웃을 항상 고정 노출할지는 7절에서 결정한다.
7. AI의 701~960px fixed 패널·backdrop 가로 시작점과 너비 계산도 현재 패널 점유 변수로 맞춘다. 모바일의 시작점 0과 floating AI 창의 사용자 위치 변수는 유지한다.

### 3.3 메뉴·AI 상호작용

- 일반 메뉴는 기존 Link, 도움말은 기존 버튼을 유지한다. 축소 상태에서 메뉴를 눌러도 일반 페이지 이동·도움말 모달은 동일하게 동작하며 데스크톱 패널을 자동으로 펼치지 않는다.
- 메뉴명과 tooltip label은 `navigationMenus`의 `label`을 사용한다. 툴팁용 별도 메뉴 목록을 만들어 권한 필터나 문구가 어긋나지 않도록 한다.
- 기존 `aria-current`, 활성 배경·아이콘 색은 유지한다. 축소 시 `NEW`와 대시보드 점은 숨기는 안을 권장한다.
- AI는 축소 상태에서 아이콘을 누르면 **좌측 메뉴를 펼치고 `aiMenuOpen=true`로 대화 목록을 표시**하는 안을 권장한다. 64px 패널에 대화 목록을 표시하거나 별도 flyout을 새로 만드는 범위를 줄일 수 있다.
- `AiChatbotToggle`에 축소 여부와 펼침 콜백을 전달하는 방식으로 shell의 로컬 상태와 연결한다. AI의 `aria-expanded`는 실제 목록 노출 상태를 반영해야 한다.
- AI 목록이 열린 채 헤더로 패널을 축소하면 `aiMenuOpen=false`로 접고 목록을 언마운트하는 안을 권장한다. 이미 선택된 대화와 `aiOpen`은 유지한다. 진행 중 새 채팅 요청은 기존 언마운트·컨텍스트 확인 로직으로 오래된 결과가 자동 선택되지 않는지 검증한다.
- 메뉴 검색에서 AI를 선택하는 분기도 함께 조정한다. 데스크톱에서는 메뉴 펼침+AI 목록 열림, 모바일에서는 드로어+AI 목록 열림으로 연결한다. 현재 공통 호출인 `setSidebarOpen(true)`만으로는 데스크톱 로컬 상태를 펼칠 수 없다.
- AI 목록 내부의 이름 변경·삭제 모달이 열린 상태에서 패널을 축소할 때는 모달을 먼저 닫고 포커스를 헤더 토글로 옮기는 안을 검토한다. 언마운트된 버튼으로 포커스를 복원하지 않아야 한다.

### 3.4 계정정보·로그아웃·오류 표시

- `.sidebar-user` 자체를 숨기지 않고 축소 상태에서 `.user-avatar`와 `.user-summary`만 숨긴다. 기존 로그아웃 버튼을 재사용하고 전용 클래스·레이블·툴팁을 부여한다. 펼침/축소용 로그아웃 버튼을 중복 생성하지 않는다.
- 이름·이메일을 숨긴 버튼이 Tab 순서에 남지 않도록 처리한다. 계정 설정은 기존 하단 `설정` 메뉴를 통해서도 접근 가능하다.
- `logout()`의 API·성공/401 처리·라우터 이동·`busy` 비활성화를 유지한다. 사용자 요청에 없는 로그아웃 확인 모달은 추가하지 않는다.
- 실패 문구를 64px 안에 그대로 출력하면 읽기 어렵다. **축소 상태에서 실패하면 기존 `stores/toast.ts`의 `toast(message, true)`로 표시**하고, 펼침·모바일에서는 기존 인라인 오류 표시를 유지하는 안을 권장한다.
- 요청 도중 표시 상태가 바뀌어도 최종 오류가 현재 상태에서 읽혀야 한다. 오류를 한 곳에서 계산한 뒤 현재 유효 상태에 따라 표시하고, 전환 시 기존 오류가 축소 영역에서 잘리거나 토스트와 인라인으로 중복 안내되지 않도록 설계한다.
- 토스트는 `PreferencesRuntime`이 이미 렌더링한다. 신규 알림 시스템이나 로그아웃 API 수정은 필요 없다.

### 3.5 툴팁

- 권장 범위는 좌측 메뉴 전체와 하단 로그아웃이다. 축소 상태를 필수로 보장하고, 사용자 요청에 상태 제한이 없으므로 펼친 상태에도 적용하는 안을 기본으로 한다. 헤더 전체 아이콘·본문 아이콘으로 확대하지 않는다.
- 작은 공용 메뉴 툴팁 컴포넌트를 `components/shared/navigation-tooltip.tsx`에 두는 안을 제안한다. 추가 의존성 없이 `react-dom` portal로 `document.body`에 렌더링하고, 클라이언트 마운트 이후에만 DOM에 접근한다.
- 트리거의 `getBoundingClientRect()`를 기준으로 오른쪽 8px 정도 간격에 fixed 배치한다. 화면 상하 경계에서는 위치를 보정하고 긴 문구는 최대 너비 내 줄바꿈한다. sidebar의 overflow 속성을 바꾸어 툴팁을 해결하지 않는다.
- 마우스 hover는 약 300ms 후 노출, 키보드 포커스는 지연 없이 노출하는 안을 권장한다. 포인터가 트리거에서 툴팁으로 이동해도 유지하고, 둘 다 벗어나거나 포커스가 나가면 닫는다. 툴팁 자체에는 버튼 등 포커스 가능한 요소를 넣지 않는다.
- Escape, 메뉴 클릭, 경로 전환, 패널 상태 전환, 스크롤·리사이즈 시 닫는다. Escape로 닫은 뒤 같은 hover/포커스가 유지된 동안 즉시 다시 열리지 않도록 한다. 타이머와 전역 이벤트는 정리한다.
- `role="tooltip"`과 고유 id, 트리거의 `aria-describedby`를 연결한다. 이름을 감추어도 링크/버튼에는 `aria-label` 또는 시각적으로만 숨긴 텍스트로 메뉴명이 남아야 한다. `title`만으로 접근 가능한 이름과 툴팁을 대체하지 않는다.
- 브랜드 심벌만 남는 링크에는 `HAMS Matrix 대시보드`처럼 접근 가능한 이름을 부여한다. 심벌 툴팁 추가 여부는 선택 사항이다.
- 툴팁 레이어는 사이드바와 floating AI 창보다 위에 두되 기존 전역 토스트(`z-index: 10000`)와 모달을 방해하지 않도록 한다. 네이티브 모달이 열리면 기존 툴팁을 닫는다.
- 배경·글자·테두리는 `--surface`, `--ink`, `--line` 등 테마 변수를 사용한다. 터치 환경은 hover 툴팁에 의존하지 않고 첫 탭에서 기존 메뉴 동작을 실행한다.

영향은 `WorkspaceShell`을 사용하는 대시보드·프로젝트 작업 공간·팀 공유·설정·요금제·문서뷰어·관리자설정에 공통으로 미친다. 권한별 메뉴 노출, 메뉴 검색, 도움말 모달, AI 목록·도킹/플로팅 패널을 함께 확인해야 한다.

게스트 화면 `app/guest/[...path]/page.tsx`는 별도 인라인 aside를 사용하며 `WorkspaceShell`을 사용하지 않는다. 플래닝보드 `app/(editor)/planning-board/layout.tsx`도 별도 편집기 레이아웃이다. 두 화면은 직접 구현 범위에서 제외하되, 공용 `Brand`나 넓은 CSS 선택자를 수정하면 회귀 확인 대상이다. MarkdownViewer 내부의 자체 sidebar도 대상이 아니며 전역 `.sidebar` 유사 선택자 확장을 피한다.

## 5. 구현 순서 제안

1. 7절의 크기·모바일·AI·툴팁 정책을 사용자 검토본에 반영한다.
2. 패널 점유 너비와 표시 구조를 정리하고 데스크톱 축소/복원·본문 배치를 먼저 확인한다.
3. 하단 로그아웃과 읽을 수 있는 오류 표시, AI 펼침·검색·패널 오프셋을 연결한다.
4. 공용 메뉴 툴팁을 붙이고 키보드·overflow·테마·모바일 전환을 확인한다.
5. 아래 검증을 수행하고 실제 변경 사항·결과를 구현 이력에 기록한다.

| 접근성·터치 | 접근 가능한 이름/ARIA 관계 검사, 모바일 탭, 키보드 이동 | 아이콘만 있어도 이름 식별, 포커스 표시, 첫 탭에서 원래 기능 실행 |
| 화면 높이·브라우저 확대 | 높이 480/600px, 확대 200%, 관리자 메뉴 전체 노출 | 메뉴와 로그아웃에 스크롤 접근 가능, 툴팁이 화면 경계를 넘지 않음 |
| 테마·모션 | 라이트·다크·사용자 강조색·모션 감소 | 활성 메뉴와 툴팁 식별 가능, 포커스 유지, 모션 감소 설정 준수 |
| 별도 화면 회귀 | 게스트·로그인·플래닝보드·MarkdownViewer | 공용 브랜드와 CSS 변경으로 독립 화면의 배치가 달라지지 않음 |

구현 후 `hams-matrix`에서 `pnpm typecheck`, `pnpm lint`, `pnpm build`로 타입·정적 검사·프로덕션 CSS를 검증한다. 기능 검증은 테스트 환경에서 수행하며 실제 세션 로그아웃은 세션/감사 데이터가 변경되는 작업이라는 점을 구분한다.

기존 `scripts/test-personal-preferences-browser.mjs`는 `[aria-label="로그아웃"]`, `scripts/test-admin-compact.mjs`는 `.user-summary`, 권한 브라우저 검증은 `.sidebar` 내부 메뉴 선택자를 사용한다. 이 선택자와 기존 펼침 상태의 동작을 유지하고 관련 회귀 범위에 따라 재실행한다. 기존 브라우저 스크립트는 데이터 변경 가능성을 확인한 뒤 테스트 환경에서만 실행한다. 이번 UI를 검증하는 신규 자동화가 필요하면 레이아웃 실측·툴팁 표시·AI 상태 전환처럼 실제 사용자 동작을 확인하는 항목에 집중한다.

## 7. 결정이 필요한 사항

| 항목 | 권장안 | 대안/영향 |
| --- | --- | --- |
| 축소 패널 너비 | 64px, 메뉴와 로그아웃 44px 클릭 영역 | 56/72px 등으로 조정 가능. 본문 여백과 AI 오프셋도 같은 값으로 조정해야 한다. |
| 모바일 적용 범위 | 700px 이하는 기존 드로어 유지 | 모바일도 항상 아이콘/로그아웃을 남기면 390px 등에서 본문 폭·오버레이·스크롤 정책을 추가 설계해야 한다. R1/R2가 모든 화면에 적용되는지 검토 필요 |
| 축소 시 계정 표시 | 아바타·이름·이메일 숨기고 로그아웃만 표시 | 아바타까지 남기면 계정 진입 버튼의 크기·레이블·배치를 추가해야 한다. |
| 로그아웃 하단 고정 | 현재 전체 스크롤 구조 유지, 낮은 화면에서는 스크롤 접근 | 어떤 높이에서도 항상 보이게 하려면 메뉴 영역만 스크롤하고 계정 영역을 고정하는 구조로 확대한다. |
| AI 아이콘 클릭 | 축소 패널을 펼치고 대화 목록 열기 | 축소를 유지하며 flyout을 띄우려면 별도 위치·포커스·바깥 클릭 정책이 필요하다. |
| 툴팁 표시 상태 | 펼침·축소 모두 좌측 메뉴와 로그아웃에 적용 | 축소에만 적용하면 펼침 상태의 중복 정보는 줄지만 요구사항의 상태 범위를 명시해야 한다. |
| 툴팁 세부값 | 오른쪽 8px 간격, hover 약 300ms, 키보드 즉시 표시 | 디자인 검토 시 위치·지연·모양 조정 가능 |
| 로그아웃 실패 안내 | 축소는 기존 토스트, 펼침·모바일은 인라인 | 모든 상태 토스트 통일 또는 실패 시 자동 펼침도 가능하나 기존 동작 변화가 커진다. |
| 배지·브랜드 | 축소에서는 배지·브랜드명 숨기고 심벌 유지 | 축소 상태에도 NEW 표시가 필요하면 아이콘 위 작은 표시 등의 별도 배치를 정해야 한다. |
| 상태 저장 | 메모리 유지, 새로고침 시 펼침 | 브라우저별 저장은 localStorage·초기 렌더링 동기화 추가, 계정별 저장은 환경설정 범위 확대가 필요하다. |
| AI 세로 오프셋 | 이번에는 가로 위치만 연동 | 기존 73/65px와 헤더 54/50px 불일치 보정까지 포함하면 AI 배치 검증 범위가 늘어난다. |

검토본에서 위 정책을 확정한 뒤 구현 범위를 결정한다. 현재 문서의 권장값은 적용된 결과가 아니며, 이번 단계에서는 소스 및 DB 변경을 수행하지 않는다.
