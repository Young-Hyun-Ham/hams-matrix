# 개인 설정 인터페이스·테마 색상 및 토스트 하위 탭 개편 설계

- 작성일: 2026-10-31 (한국시간)
- 단계: 현재 소스 분석 및 설계. 이번 작업은 문서와 HISTORY 링크만 작성한다.
- 범위: 로그인 사용자의 개인 인터페이스 설정, 공통 강조 색상, 토스트 설정 및 적용 경로.

## 1. 요구사항

1. 설정 옵션은 로그인한 사용자 개인의 설정이다. 같은 팀·프로젝트에 참여하더라도 사용자마다 다른 값을 저장하고 적용한다.
2. 설정의 기존 `인터페이스 관리` 안에 `인터페이스`, `토스트` 하위 탭을 추가한다.
3. 인터페이스 하위 탭에는 기본 테마(라이트/다크)와 사이트의 현재 보라색 계열 공통 강조 색상을 변경하는 옵션을 제공한다.
4. 토스트 위치, 토스트 배경색, 토스트 폰트 색상은 토스트 하위 탭으로 이동한다.
5. 기존 개인 설정·저장값을 보존하며, 팀이나 전체 사용자에게 동일한 설정을 강제하지 않는다.

여기서 공통 컨셉 색상 변경은 사이트의 강조 색상 계열을 개인화하는 의미로 해석한다. 모든 배경·본문 색을 개별 편집하는 테마 제작기나 프로젝트별 공유 테마를 새로 만드는 작업은 포함하지 않는다.

| 테마 상태 | `stores/theme.ts`는 root의 data-theme와 메모리 theme를 변경 | 모드와 강조 팔레트를 함께 갱신해야 함 |
| 헤더 모드 전환 | `components/theme-toggle.tsx`가 saved 전체와 반대 모드를 save | 강조 색상·토스트 값을 보존하며 모드만 변경해야 함 |

현재 PATCH는 허용 키·라이트/다크·상단/하단·6자리 HEX 색상을 검증하며 version으로 동시 수정 충돌을 막는다. 누락 필드는 기존 DB 값으로 병합한다. 신규 사용자의 GET 기본 version은 0이며 저장 시 기존 정책대로 증가한다.

현재 설정은 브라우저 전역 테마를 영구 저장하는 방식이 아니다. 저장 후 `matrix-preferences:{userId}`에 캐시를 기록하지만 DB가 기준이며 런타임의 초기값은 서버에서 받는다. 이 구분을 유지한다.

## 3. 화면 설계

```text
설정
[토큰 사용량] [인터페이스 관리] [계정 설정]

인터페이스 관리
[인터페이스] [토스트]

인터페이스: 기본 테마 [라이트/다크]
             강조 색상 [색상 선택] [#HEX] [색상 예시]
             [기본 색상으로 되돌리기]

토스트:     위치 [상단/하단]
             배경색 [색상 선택] [#HEX]
             폰트색 [색상 선택] [#HEX]
             [토스트 미리보기]

공통 하단: [저장] [취소] · 개인 설정 안내 / 저장 오류
```

- 상위 인터페이스 관리 진입은 기존 `/settings?tab=interface`를 유지한다. 기본 하위 탭은 인터페이스로 한다.
- 하위 탭은 같은 폼 내부의 로컬 상태와 tablist/tab/tabpanel로 구현하는 방안을 우선 권장한다. 키보드 좌우/Home/End 이동, aria-selected/controls 관계를 제공한다.
- 링크 공유·뒤로가기에서 하위 탭 복원이 필요하면 `section=interface|toast` 같은 별도 쿼리를 사용한다. 상위 `tab`을 재사용하지 않고 다른 쿼리를 보존한다. 이 경우 서버 props와 SettingsTabs 링크 생성도 함께 검토한다.
- 두 하위 탭은 하나의 사용자 설정 draft를 공유한다. 하위 탭만 바꿨을 때 미저장 값이나 미리보기가 사라지지 않도록 한다. 저장은 두 탭의 현재 초안을 함께 저장하며 이를 화면에서 명확히 안내한다.
- 실제 설정 화면 이탈·취소 시 미리보기를 저장값으로 복구한다. 취소는 기존 저장값 복원이고 `기본 색상으로 되돌리기`는 기본 색상을 초안에 넣는 별도 동작이다. 후자는 저장 전까지 DB를 변경하지 않는다.
- 토스트 미리보기는 토스트 하위 탭에서만 제공한다. 테마 강조 색상 변경으로 토스트의 사용자 배경색/폰트색을 덮어쓰지 않는다.
- “내 계정에만 적용되는 설정입니다”를 표시한다. 프로젝트/워크스페이스 선택 여부와 무관하게 같은 계정이면 같은 설정을 사용한다.

## 4. 개인별 강조 색상과 테마 적용

### 4.1 저장값 및 파생 팔레트

- 개인 설정에 `accentColor`를 추가한다. API는 6자리 HEX(`#RRGGBB`)만 받으며 임의 CSS·변수명·스타일 문자열을 저장하지 않는다.
- 저장값은 사용자 선택 기준색 하나로 두고, 모드에 맞는 실제 primary·primary-soft·강조 버튼 위 글자색을 공통 순수 함수로 계산하는 방안을 권장한다. 라이트/다크 개별 팔레트 전체를 사용자가 입력하게 하지 않는다.
- 기본값 호환을 위해 DB의 `accent_color`는 NULL을 “사이트 기본 보라색”으로 표현하는 방안을 제안한다. API `accentColor: null`도 동일 의미로 정의하고 기존 사용자와 신규 사용자는 현재 라이트/다크 팔레트를 정확히 유지한다.
- 이 방식에서는 기본 색상 복원 시 null, 색상 입력 시 HEX를 저장한다. 단일 HEX 기본값만 고정하면 기존 다크 테마의 보라색 밝기가 바뀔 수 있으므로 기본 모드 팔레트를 별도로 보존해야 한다.
- 새 공통 팔레트 함수는 root용 CSS 토큰과 SVG/Mermaid용 실제 색상 값을 모두 반환하도록 한다. 필요 토큰은 `--primary`, `--primary-soft`, `--on-primary`이며 hover/focus/테두리가 별도 색상을 요구하면 파생 토큰으로 추가한다.
- 사용자 기준색은 채도를 유지하되 모드에 맞는 명도와 연한 배경을 계산한다. 밝은 기준색에서 흰 버튼 글자가 사라지지 않도록 검정/흰색 계열 글자색을 대비 기준으로 선택한다. 대비 부족한 색상은 제약·보정 방식과 미리보기 결과를 안내한다.
- 성공·오류·경고 같은 상태 의미 색상은 유지한다. 외부 브랜드 로고, 업로드 이미지, 사용자가 Mermaid classDef로 직접 지정한 색상도 일괄 치환하지 않는다.

### 4.2 적용 순서·우선순위

1. 서버가 로그인 사용자 설정을 읽고 새 컬럼이 NULL이면 기본 팔레트로 해석한다.
2. PreferencesRuntime.initialize가 기본 모드와 강조 팔레트를 함께 적용한다. 첫 화면에서 다른 계정의 팔레트를 재사용하지 않는다.
3. draft 미리보기 시 모드와 강조 색상을 같은 함수로 갱신한다. root의 사용자 소유 CSS 속성은 고정 다크 스타일보다 우선 적용되도록 관리한다.
4. 취소·미리보기 복구 시 저장된 모드/강조 색상/토스트 상태를 함께 복구한다. 기본색으로 복구할 때 이전 사용자의 inline 변수가 남지 않도록 명시적으로 재설정하거나 제거한다.
5. 헤더 모드 전환도 같은 팔레트 함수를 호출해 현재 계정의 강조 색상을 보존한다.

현재 테마 초기 스크립트는 라이트로 시작하고 인증 레이아웃 이후 useLayoutEffect에서 사용자 테마를 적용한다. 이 구조의 기본색 순간 노출 가능성을 점검한다. 개선이 필요하면 인증된 사용자의 검증된 초기 팔레트를 서버 렌더링 범위에도 전달하되, 정적/공유 캐시에 개인 색상을 섞지 않는다. 브라우저 공용 저장값 하나를 읽어 초기 테마로 적용하는 방식은 사용하지 않는다.

### 4.3 색상 적용 범위와 고정색 정리

- 공통 버튼·선택 탭·활성 메뉴·링크·포커스·체크/라디오 강조·공통 모달·AI 인터페이스·WBS의 강조 영역을 새 공통 토큰으로 맞춘다.
- 단순 `primary` 교체만으로 완료라고 보지 않는다. CSS에 직접 지정된 보라색 배경·그라데이션·아이콘/배지 강조색과 rgba/HEX 변형도 찾아 의미에 따라 토큰화한다. `purple`/`indigo` 클래스 이름은 이름 자체보다 실제 적용 색상을 확인한다.
- WBS 차트의 indigo 유틸리티 상당수는 이미 primary/primary-soft를 참조한다. 상태를 나타내는 초록/경고색은 유지한다. 흰색 고정 강조 버튼 글자는 새 on-primary로 검토한다.
- 아키텍처 SVG와 Mermaid는 현재 모드별 고정 팔레트를 사용하므로 개인 강조 색상도 입력으로 받게 바꾼다. Mermaid 렌더 effect가 모드뿐 아니라 팔레트 변경도 구독해야 미리보기 중 색상을 바꿨을 때 재렌더링된다.
- SVG/PNG 출력은 실제 렌더러에서 사용한 개인 팔레트를 값으로 기록한다. CSS 변수만 남겨 독립 이미지의 색이 사라지지 않도록 한다. 사용자 수동 Mermaid 스타일은 보존하고 자동 기본 강조색만 개인 팔레트로 처리한다.

## 5. 사용자 설정 격리·초안·비동기 처리

개인 설정이라는 요구는 DB의 user_id 조건뿐 아니라 클라이언트 상태와 늦은 응답까지 포함한다.

- 서버는 requireUser의 user.id만 사용한다. 요청에 다른 userId/workspaceId를 받지 않으며 관리자라도 이 API로 타인의 설정을 바꿀 수 없게 한다. 기존 게스트 조회/저장 제한을 유지한다.
- 계정 A 로그아웃→B 로그인 시 A의 강조색·기본 테마·토스트 색/위치·초안을 초기화하고 B의 서버 설정을 적용한다. 워크스페이스만 전환한 같은 사용자에게는 같은 개인 설정을 유지한다.
- 현재 store.save는 응답 후 `get().userId`로 initialize와 캐시 키를 결정한다. 요청 중 계정이 바뀌면 A의 응답을 B의 설정으로 적용할 위험이 있으므로 **요청 시작 당시 사용자 ID와 세션/초기화 세대**를 캡처하고 응답 적용 전에 비교한다. 실패 시 rollback과 busy 해제도 새 계정의 상태를 덮어쓰지 않아야 한다.
- PreferencesRuntime 초기화, 폼 이탈 cleanup, root CSS 변수 정리도 자신의 사용자/세대에만 적용한다. 이전 계정의 늦은 cleanup이 새 계정의 팔레트를 기본값으로 돌리지 않게 한다.
- 저장 요청은 변경된 필드와 기준 version을 제출하는 방안을 권장한다. 상단 ThemeToggle의 모드 저장은 강조색·토스트 초안을 임의 덮어쓰지 않도록 saved와 draft 간 정책을 맞춘다.
- 폼이 열린 동안 헤더 모드 토글로 saved.version이 바뀌는 경우를 처리한다. 권장안은 폼의 미변경 필드만 최신 저장본으로 병합하고 변경 필드는 보존하는 것이다. 사용자 의도를 구분할 수 없으면 자동 덮어쓰기 대신 충돌을 안내한다.
- 다른 브라우저/탭에서 변경되면 현재 version 충돌을 유지한다. 즉시 자동 동기화가 필수인지 별도 결정하며, 추가한다면 사용자별 storage 이벤트를 신호로 DB를 재조회한다. 캐시 값을 서버 저장본보다 우선하지 않는다.
- 저장 오류 시 기존 preview(saved) 복구 정책을 유지하되 draft는 버리지 않는다. 409에서는 새로고침 강제 대신 최신 설정 재조회·초안 보존/재적용 선택을 제공하는 방향을 권장한다.

## 6. DB/API 설계

### 6.1 DB

- `user_preferences`의 user_id PK 및 현재 컬럼/버전을 그대로 유지하고 `accent_color TEXT NULL` 컬럼을 추가하는 새 migration을 제안한다.
- CHECK 제약 또는 서버 검증으로 NULL/정규 HEX만 허용한다. 기존 행은 NULL로 남겨 현재 기본 테마 색을 보존하고 user_preferences 행이 없는 사용자의 조회에서도 동일 기본값을 반환한다.
- 새 migration 번호는 구현 시 실제 마지막 번호를 확인하여 배정한다. 이미 적용한 022/023을 수정하거나 기존 설정 테이블을 재생성하지 않는다.
- 이전 작업 기록에는 실제 DB에서 023 컬럼은 존재하지만 적용 이력이 누락되어 표준 migrate가 중복 컬럼 오류로 중단된 이력이 있다. 구현 시 현재 스키마·migration 적용 상태를 다시 확인하고 관련 없는 컬럼/이력을 추정하여 변경하지 않는다. 이번 설계 단계에서는 DB를 조회하거나 변경하지 않았다.

### 6.2 API 및 타입

- GET `/api/me/preferences` 응답에 `accentColor`를 포함한다. PATCH 허용 키·NULL/HEX 검증·누락 값 병합·INSERT/UPDATE·응답에 함께 추가한다.
- 기존 부분 PATCH 동작과 version 확인을 유지한다. 토스트만 저장했을 때 강조색이 NULL로 초기화되거나, 테마만 저장했을 때 토스트 값이 초기화되지 않도록 undefined와 null을 구분한다.
- Preferences 타입·defaults·SSR initial·서버 기본값에 필드를 동시에 추가하여 새 계정·기존 계정에서 누락 값으로 런타임 오류가 나지 않게 한다.
- 사용자별 설정으로 저장하므로 workspace 설정/app_settings/팀원 테이블에 개인 색상을 추가하지 않는다.

## 8. 검증 방법

### 개인 설정·DB·동시성

- 사용자 A/B를 같은 브라우저에서 번갈아 로그인하고 각자의 모드·강조색·토스트 값을 확인한다. 서로 다른 기기에서도 같은 계정의 저장값이 재조회되는지 확인한다.
- 같은 사용자 워크스페이스 전환 시 개인 설정 유지, 다른 사용자 전환 시 이전 계정 값 제거를 확인한다. 로그인 페이지·게스트 화면에 이전 사용자 색이 남지 않아야 한다.
- 응답이 느린 A의 저장/실패/cleanup이 B 초기화 이후 도착하도록 재현해 B의 설정·캐시·busy·CSS가 변경되지 않는지 확인한다.
- 인증 없는 요청·게스트·임의 userId·잘못된 HEX/NULL 타입·추가 필드·오래된 version을 검증한다. 토스트/테마 각각 부분 PATCH에서 다른 필드를 보존하는지 확인한다.
- 기존 행 NULL·미등록 사용자·migration 재실행 정책을 임시 테스트 DB에서 확인한다. 023의 기존 이력 불일치가 남아 있다면 별도 보고하고 임의 수정하지 않는다.

### 화면·팔레트·회귀

- 인터페이스 관리에서 인터페이스/토스트 탭의 키보드 조작·반응형·초안 보존을 확인한다. 상위 탭 이동과 저장/취소/기본색 복원을 구분하여 검증한다.
- 라이트/다크 × 기본 보라·파랑·초록·붉은색·매우 밝은/어두운 사용자 색상에서 버튼·선택 메뉴·탭·링크·포커스·모달·WBS 강조색과 글자 대비를 확인한다.
- 모드 전환 후 강조 계열이 유지되는지, 기본색 복원 시 기존 라이트/다크 보라 팔레트가 정확히 돌아오는지 확인한다.
- 토스트 위치·배경·폰트 색상·미리보기와 저장 성공/오류 알림이 기존대로 동작하는지 확인한다. 강조색 변경이 독립 토스트 색상을 덮어쓰면 안 된다.
- SVG/Mermaid가 같은 모드에서 강조색만 바꿔도 다시 그려지는지, 수동 Mermaid 스타일/상태 의미 색상이 보존되는지, 독립 이미지 출력에서 실제 색이 유지되는지 검증한다.
- 저장 후 새로고침·로그아웃/재로그인·느린 초기 로딩에서 기본색 순간 노출과 다른 사용자 색상 노출 여부를 점검한다.
- 구현 후 `pnpm typecheck`, 변경 파일 lint, `pnpm build`와 관련 개인 설정 API·사용자 격리·테마/토스트·시각화 회귀 검증을 수행한다.
