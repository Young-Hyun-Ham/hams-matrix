# AI 챗봇 채팅·입력 영역 좌우 분리 분석 및 설계

- 작성일: 2026-11-09 (한국시간, Asia/Seoul)
- 상태: 사용자 검토용 설계 초안. 사용자가 검토·직접 수정한 뒤 별도 구현 요청 시 적용한다.
- 분석 기준: 현재 작업 트리의 소스. 이미 수정된 파일과 신규 파일을 포함한 현재 구조를 확인했으며, 이전 설계 문서만으로 동작을 추정하지 않았다.
- 이번 단계 산출물: 본 문서와 `HISTORY.md`의 문서 링크만 추가한다. 애플리케이션 소스, DB, 마이그레이션, 패키지 및 설정은 변경하지 않는다.
- 표기: **확정 요구사항**은 사용자 요청이며, **권장안**은 구현을 구체화하기 위한 제안이다. 미확정 정책은 8절에 정리한다.

## 1. 요구사항과 범위

| ID | 확정 요구사항 | 완료 기준 |
| --- | --- | --- |
| R1 | AI chatbot 모듈 헤더의 전환 버튼 앞에 채팅창과 입력창을 좌우로 분리하는 버튼을 추가한다. | 헤더 버튼 순서가 `좌우 분리/상하 배치 → 패널/팝업 전환 → 확대/축소 → 닫기`가 된다. 버튼으로 기존 상하 배치와 좌우 배치를 전환한다. |
| R2 | 좌우 분리 시 기존 확대 width를 기본 적용한다. | 분리 모드 진입 시 패널은 기존 확대 비율인 작업 영역 50%, 팝업은 기존 확대 규칙인 `min(760px, calc(100vw - 24px))`를 사용한다. |
| R3 | 이번에는 설계 문서만 작성한다. | 신규 문서를 한국시간 날짜 디렉터리에 작성하고 기존 이력 목록을 보존해 링크를 추가한다. 소스·DB 구현은 수행하지 않는다. |

용어와 요구 해석:

- **전환 버튼**: `AiWorkspaceLayout` 헤더의 기존 패널/팝업 전환 버튼이다. 입력 카드 내부의 모델 선택이나 AI 대상 선택을 의미하지 않는다.
- **채팅창**: `AiConversationMessages`가 표시하는 사용자 요청·AI 답변·이전 대화·첨부·생성 상태 영역이다.
- **입력창**: textarea만 떼어내지 않고, 기존 `.matrix-ai-card` 전체를 입력 영역으로 취급하는 것을 권장한다. 모델, 현재 위치, AI 대상, 프롬프트, 첨부, 생성/중지, 오류 및 사용량을 함께 둔다.
- **좌우 방향**: 왼쪽에 대화, 오른쪽에 입력 영역을 배치하는 것을 권장한다. 채팅방 제목은 두 열 위에 공통으로 표시한다.
- **기존 확대 width**: 화면 전체 너비나 임의의 신규 고정 너비가 아니라, 현재 패널/팝업에서 이미 사용하는 확대 규칙이다. 960px 이하 패널은 현재 반응형 너비 제한이 우선하므로 별도 검토가 필요하다.
- 분할선 드래그로 비율 조정, 별도 브라우저 창 생성, 사용자별 DB 저장은 요청 범위에 포함하지 않는 것을 권장한다.

## 2. 현재 구조와 확인 결과

### 2.1 헤더와 외부 창 상태

| 파일 | 현재 구조 | 설계 영향 |
| --- | --- | --- |
| `components/ai/ai-workspace-layout.tsx` | `.matrix-ai-drawer-header`에 제목·이동 핸들과 `.matrix-ai-window-actions`를 표시한다. 현재 순서는 전환, 확대/축소, 닫기다. | 신규 버튼의 실제 수정 위치다. `ai-chatbot.tsx`의 입력 카드 헤더와 구분해야 한다. |
| 같은 파일 | `useAiWindow(panel, aiOpen)`의 `floating`, `expanded`, `position`, `dragging`으로 외부 클래스와 좌표를 구성한다. | 분리 상태와 유효 확대 상태를 한 곳에서 계산하면 헤더·창 너비·팝업 좌표를 일관되게 반영할 수 있다. |
| 같은 파일 | `<AiChatbot key={사용자:워크스페이스} />`를 하나만 렌더링한다. 선택 방·프로젝트·실제 pathname 및 설정/관리자 경로로 노출을 판단한다. | 레이아웃 전환으로 key나 노출 판정을 바꾸지 않아야 한다. |
| `components/ai/use-ai-window.ts` | `floating=false`, `expanded=false`, 초기 좌표 `{x:24,y:88}`를 로컬 상태로 갖는다. 확대 토글과 팝업/패널 전환을 제공한다. | 현재 분리 상태는 없다. 브라우저 저장소나 DB에도 창 배치를 저장하지 않는다. |
| 같은 훅 | 팝업 전환 시 `expanded ? 760 : 460`으로 최초 좌표를 산정한다. `floating/expanded/open` 변경 및 resize 시 실제 DOM 크기로 위치를 보정한다. | 분리 상태를 CSS에만 추가하면 최초 좌표 계산과 보정이 새 너비를 인식하지 못할 수 있다. 유효 확대값을 이 경로까지 전달해야 한다. |
| `stores/workspace.ts` | `aiOpen`, 선택 대화방, 실제 AI context를 관리한다. 프로젝트 또는 사용자 범위 변경 시 선택 방과 열림 상태를 초기화한다. | 창 레이아웃은 현재 이 store의 책임이 아니다. 이번 UI 요구만을 위해 전역 store나 방 DTO를 확장할 필요는 없다. |

현재 `useAiWindow`는 open 값이 false가 되어도 창 모드 상태를 별도로 초기화하지 않는다. 선택 방이 바뀌어 `AiPanel`이 다시 만들어지는 것과 상위 창 훅의 수명은 다르다. 계정 전환 시 새 레이아웃 설정까지 초기화할지는 현재 사용자 상태 초기화와 별개로 결정해야 한다.

### 2.2 현재 너비·높이·반응형 규칙

`components/ai/ai-workspace-layout.css`에서 확인한 규칙은 다음과 같다.

| 모드 | 현재 너비/위치 규칙 | 분리 설계 시 주의점 |
| --- | --- | --- |
| 데스크톱 패널, viewport 960px 초과 | 기본 그리드는 AI:본문 `3fr:7fr`, 확대 시 `1fr:1fr`다. | 50%는 좌측 메뉴를 제외한 `.workspace-content-layout` 기준이다. 내부 대화/입력의 비율과 다른 값이다. |
| 패널, viewport 960px 이하 | fixed 레이어, `min(440px, calc(100vw - var(--workspace-sidebar-width)))`다. 확대 클래스가 있어도 데스크톱 50% 그리드를 적용하지 않는다. | 분리 진입만으로 이 구간의 패널이 넓어지지는 않는다. 모바일 대응을 별도로 명시해야 한다. |
| 패널, viewport 700px 이하 | 왼쪽 0, 상단 65px, `min(440px, 100vw)`다. | 입력·헤더 버튼이 작은 화면 밖으로 밀리지 않아야 한다. |
| 팝업 | 기본 `min(460px, calc(100vw - 24px))`, 확대 `min(760px, calc(100vw - 24px))`다. | viewport가 작으면 760px보다 작아진다. 화면 안 위치 보정이 필요하다. |
| 높이 | 패널은 기본 `calc(100dvh - 73px)`, 팝업은 `min(720px, calc(100dvh - 100px))`이며 700px 이하 팝업은 `min(600px, 70dvh)`다. | 제목·헤더를 제외한 가용 높이를 두 열에 나누지 않고 공통으로 사용해야 한다. |

CSS 후반에는 기존 정의를 덮는 규칙이 있다. 실제 최종 동작은 drawer와 `.matrix-ai`의 바깥 스크롤을 막고, `.matrix-ai-panel-content`를 세로 flex로 만들어 대화만 남은 높이를 사용하게 한다. 입력 카드는 `max-height:65%; overflow-y:auto`, textarea는 기본 80px 높이와 120px 최대 높이로 제한한다. 분리 모드에서 앞부분 CSS만 변경하면 이 규칙 때문에 입력 열이 전체 높이를 활용하지 못한다.

### 2.3 채팅과 입력의 DOM·상태

`components/ai/ai-chatbot.tsx`의 구조는 다음과 같다.

```text
.matrix-ai
├─ .matrix-ai-panel-content
│  ├─ AiConversationTitle       채팅방 제목·제목 변경
│  ├─ AiConversationMessages    .matrix-ai-messages
│  └─ section.matrix-ai-card    모델·대상·textarea·첨부·생성/중지·안내
└─ dialog.matrix-ai-result      결과 크게 보기
```

- `AiPanel`은 사용자·워크스페이스·대화방 ID를 key로 사용한다. 프롬프트, 선택 모델, 이미지, 생성/중지, 오류, 결과 모달, AbortController 등은 같은 패널 인스턴스에서 관리한다.
- `useAiConversation`이 대화 조회·이전 대화·진행 요청을 관리하고, `AiConversationMessages`는 마지막 메시지 ID가 바뀔 때 끝으로 스크롤한다. 배치 변경 자체는 새 메시지 수신이 아니다.
- `useAiTarget`과 입력 카드의 AI 대상 선택은 이미 현재 소스에 존재한다. 이번 설계는 이 기능을 새로 구현하는 작업이 아니며, 우측 입력 열 안에서 함께 유지한다.
- `components/ai/ai-chatbot.css`에는 대화 영역의 `max-height:48dvh`, 아래 여백, 본문 줄바꿈, 이미지 배치, 입력 카드와 모델/대상 선택 스타일이 있다. drawer 전용 CSS가 일부 높이 규칙을 덮는다.
- `components/icon.tsx`의 공통 SVG 경로에 `window-expand`, `window-restore`, `window-popout`, `window-dock`이 있다. 분리/상하 배치 전용 아이콘은 없다. 미등록 이름은 file 아이콘으로 대체되므로 이름만 사용해서는 안 된다.

### 2.4 기존 검증 수단

- `scripts/test-navigation-browser.mjs`: 실제 브라우저에서 메뉴와 채팅 패널 동작, 800px 패널/배경 위치 등 일부 레이아웃을 검증한다. 현재 좌우 분리 전용 검증은 없다.

- `pnpm test:ai`: 대화·이미지·생성·중지 등 API 회귀 검증이다. 브라우저의 좌우 배치와 실제 너비를 확인하는 검증을 대신하지 못한다.

## 3. 수정 방향

### 3.1 UI 배치

신규 버튼은 `.matrix-ai-window-actions`의 첫 번째 자식으로 추가한다. 기존 헤더 액션과 동일한 크기·색상·키보드 포커스 스타일을 사용한다.

```text
공통 헤더: [채팅방 이름] [좌우 분리] [패널/팝업 전환] [확대/축소] [닫기]

기존 상하 배치                 좌우 분리 배치
┌─────────────────────┐      ┌─────────────────────────────────┐
│ 채팅방 제목·제목 변경 │      │ 채팅방 제목·제목 변경             │
├─────────────────────┤      ├────────────────┬────────────────┤
│ 대화 목록           │      │ 대화 목록      │ 입력 카드      │
│ 독립 스크롤         │      │ 독립 스크롤    │ 모델·AI 대상   │
├─────────────────────┤      │                │ 프롬프트·첨부  │
│ 입력 카드           │      │                │ 생성/중지·오류 │
└─────────────────────┘      └────────────────┴────────────────┘
```

**권장안:** 내부 열 비율은 대화:입력 `1:1`, 열 간격 12px로 시작한다. 외부 패널의 50%와 내부 열의 50:50은 서로 독립적인 값이다. 입력 영역에는 기존 카드 전체를 유지하고 결과 모달은 그리드 바깥의 현재 위치에 둔다.

### 3.2 상태와 확대 기본값

**권장안:** `useAiWindow`에 내부 레이아웃 상태를 추가하고 창 배치와 같은 수명으로 관리한다. 기존 상하 모드의 확대 선택과 분리 모드의 확대 선택을 구분해, 분리 해제 시 원래 너비를 복원한다.

| 상태/계산값 | 의미와 초기값 |
| --- | --- |
| `split` | 좌우 분리 설정 여부. 초기값 false다. |
| 기존 `expanded`의 내부 저장값 | 상하 모드에서 사용자가 선택한 확대 여부. 현재처럼 초기값 false다. |
| `splitExpanded` | 분리 모드의 확대 여부. **분리 모드로 진입할 때마다 true로 설정**한다. |
| 유효 확대값 | `split ? splitExpanded : 상하 모드 확대값`. 훅이 외부에 반환하는 `expanded`는 이 값으로 통일한다. |

외부 클래스 `ai-is-expanded`, 확대 버튼의 `aria-pressed`와 아이콘, 팝업 초기 좌표 계산, 확대/viewport 변경 시 위치 보정은 모두 유효 확대값을 사용한다. 분리 클래스만 붙이고 기존 expanded 상태를 false로 두는 구현은 피한다.

| 사용자 조작 | 상태 전이와 결과: 권장안 |
| --- | --- |
| 최초 열기 | 기존 상하 배치와 기본 너비로 시작한다. |
| 상하 → 좌우 분리 | split=true, splitExpanded=true. 기존 상하 확대 선택은 보존하고 현재 표시 너비에는 확대 규칙을 적용한다. |
| 좌우 → 상하 배치 | split=false. 분리 진입 전 상하 모드의 확대 선택을 사용한다. |
| 분리 중 확대/축소 | splitExpanded만 토글한다. 요구의 “디폴트”를 진입 시 기본값으로 해석해 사용자의 이후 축소는 허용한다. 공간 부족 시 3.4절의 상하 표시를 사용한다. |
| 상하 모드 확대/축소 | 기존 상하 확대 선택만 토글한다. |
| 패널 ↔ 팝업 | split과 각 모드의 확대 선택을 유지한다. 패널 확대는 50%, 팝업 확대는 최대 760px로 해당 표시 방식의 규칙을 적용한다. |
| 창 닫기 → 같은 레이아웃에서 다시 열기 | 기존 훅 수명에 맞춰 레이아웃 설정을 유지한다. 이 동작을 새 분리 진입으로 처리하지 않는다. |
| 방 전환 | 상위 창의 배치 설정은 유지하되, 메시지·초안의 방별 수명은 기존 AiPanel key 규칙을 따른다. |
| 전체 페이지 새로고침/레이아웃 재마운트 | 로컬 UI 상태이므로 기존 기본값인 상하/기본 너비로 돌아간다. |

위 정책은 구현 확정사항이 아니다. 분리 중 축소를 금지하거나 해제 시 확대 너비를 그대로 유지하려면 8절의 선택에 맞춰 상태 모델도 단순화할 수 있다.

### 3.3 동일 인스턴스 유지

- 상하/좌우마다 `<AiChatbot>` 또는 `<AiPanel>`을 조건부로 두 개 렌더링하지 않는다.
- 기존 형제 요소에 CSS Grid 영역을 지정해 배치만 바꾼다. `.matrix-ai-panel-content`에서 제목은 두 열 전체, 메시지는 왼쪽, 입력 카드는 오른쪽을 차지하도록 한다. 행은 `auto minmax(0, 1fr)`, 열은 `repeat(2, minmax(0, 1fr))`를 기본안으로 삼는다.
- `split` 또는 유효 확대값을 React key, 대화방 선택 조건, 생성 훅의 재조회 의존성에 추가하지 않는다. 버튼 조작으로 네트워크 요청·방 생성·대상 저장을 유발하지 않는다.
- textarea·제목 편집 input·첨부 컴포넌트의 DOM을 유지한다. 레이아웃 버튼 클릭 후 포커스는 버튼에 두고, 입력으로 강제 이동시키지 않는다.
- 생성/중지 중에도 배치 전환은 허용하는 것을 권장한다. 요청 ID, AbortController, 중지 재시도, target 저장 상태를 변경하지 않는다.

### 3.4 반응형 표시

**권장안:** viewport 하나가 아니라 **AI 내부 가용 너비**로 실제 좌우 표시 가능 여부를 판단한다. 외부 너비는 기존 확대 규칙을 재사용하고, 공간이 부족하면 상하로 표시한다.

- `.matrix-ai` 등에 이름 있는 inline-size query container를 두고 내부 가용 너비가 **560px 이상**일 때 분리 그리드를 적용하는 안을 제안한다. 12px 간격을 제외하면 각 열은 약 274px부터 시작한다. 임계값은 디자인 검토와 실제 브라우저 검증 후 조정한다.
- 560px 미만이면 기존 상하 배치를 사용한다. 두 열의 최소 너비를 강제로 확보해 가로 스크롤이나 화면 밖 입력창을 만들지 않는다.
- 데스크톱이라도 좌측 메뉴 확장·브라우저 확대·viewport 크기에 따라 50% 패널 내부가 임계값보다 작을 수 있다. 이 경우에도 외부 너비를 임의로 60% 또는 전체 화면으로 늘리지 않는 것을 권장한다.
- 960px 이하 패널은 기존 최대 440px 규칙 때문에 상하 표시가 된다. 팝업은 viewport 960px 이하에서도 실제 내부 너비가 충분하면 좌우 표시할 수 있다.
- 분리 설정은 좁아져도 유지한다. 다시 넓어지면 같은 설정으로 좌우 표시를 복원한다. 공간 변화만으로 확대값을 재설정하거나 네트워크 요청을 보내지 않는다.
- `aria-pressed`는 분리 **설정** 여부를 나타낸다. 버튼 tooltip/접근 가능한 설명에는 “좁은 창에서는 상하 표시”를 포함해, 설정이 켜져도 상하로 보이는 상황을 설명한다. 기본안은 CSS container query로 표시를 제어하며 측정용 JS 의존성을 추가하지 않는다.

요구를 “버튼을 누르면 모바일을 포함해 반드시 두 열로 표시”로 해석할 경우 위 폴백 정책은 적용할 수 없다. 그 경우 필요한 최소 너비와 모바일 창 확장 규칙을 구현 전에 결정해야 한다.

### 3.5 높이·스크롤·입력 편의

- 공통 헤더와 방 제목은 위에 고정하고, 메시지/입력 열은 나머지 높이를 사용한다. 상위 flex/grid 체인에 `min-height:0`, 두 열에 `min-width:0`을 유지한다.
- 실제 좌우 표시 시 메시지의 기존 아래 여백과 `max-height:48dvh` 제약을 정리해, 왼쪽 열 전체 높이를 사용하게 한다. 긴 메시지·이미지·이전 대화 조회는 왼쪽 열 안에서 스크롤한다.
- 오른쪽 입력 카드의 `max-height:65%`를 분리 표시에서 해제하고 가용 높이를 사용하게 한다. 내용이 많으면 카드 자체를 세로 스크롤해 생성/중지와 오류·사용량까지 접근할 수 있도록 한다.
- 좌우 모드에서는 textarea의 기존 80px/최대 120px 제약을 완화해 남은 공간 활용을 검토한다. 최소 높이 100px을 시작안으로 삼되 작은 높이에서는 카드 스크롤이 우선하도록 하고, 입력창 리사이즈가 카드 밖으로 넘치지 않도록 제한한다.
- 좁은 화면의 상하 표시에서는 기존 textarea/카드 높이 규칙을 유지한다. container query 내부에서만 분리용 높이 재정의를 적용해 폴백 시 높이가 잘못 남지 않도록 한다.
- 모델/대상 선택 행은 줄바꿈을 허용하고 긴 모델명·대상명·방 제목·오류 문구에 overflow를 방지한다. 이미지 미리보기는 우측 열 폭 안에서 줄바꿈한다.
- 단순 배치 전환으로 대화를 강제로 끝으로 이동시키지 않는다. 기존 마지막 메시지 변경 시 자동 스크롤은 유지하고, 이전 대화를 읽는 중 전환해도 읽던 위치가 가능한 범위에서 유지되는지 확인한다.

### 3.6 접근성과 기존 헤더 동작

- 분리 버튼은 `type="button"`, 상태에 맞는 `aria-label`/`title`, `aria-pressed`를 제공한다. 예: “AI 채팅 좌우 분리”, “AI 채팅 상하 배치로 복원”.
- 버튼의 시각적 순서와 Tab 순서를 동일하게 유지한다. Enter/Space 조작, 기존 focus-visible, 라이트/다크 테마 토큰을 재사용한다.
- 공통 `Icon`에 좌우 분리/상하 배치 경로를 추가한다. 기존 창 전환 및 확대 아이콘과 구별되는 도형을 사용하고 SVG의 기존 `aria-hidden` 규칙을 유지한다.
- 현재 확대 tooltip은 팝업에서도 “패널 30%/50%”를 표시한다. 관련 부분을 수정할 때 패널은 30%/50%, 팝업은 기본/확대 최대 460px/760px 및 viewport 제한에 맞는 문구로 정리한다.
- 분리 버튼은 기존 제목 드래그 핸들 밖의 액션 영역에 둔다. 클릭/터치가 팝업 드래그를 시작하지 않아야 한다.
- Esc, 배경 클릭, 닫기 후 메뉴 포커스 복귀, 결과 dialog의 Esc 우선 처리, 비모달 팝업에서 부모 화면 조작은 기존 동작을 유지한다.

| V9 | 긴 대화·이전 대화 조회·다수 첨부·여러 오류/상태 표시 | 왼쪽 대화와 오른쪽 카드가 각각 스크롤된다. 아래 생성/중지 버튼까지 접근 가능하고 바깥 drawer/본문에 불필요한 스크롤이 생기지 않는다. |
| V10 | 내부 폭 559/560/561px와 viewport 960/961px·700/701px 경계 | 내부 임계값과 기존 반응형 규칙을 각각 준수한다. 버튼/입력 가로 overflow가 없고 넓어지면 좌우 설정이 복원된다. |
| V11 | 390px 모바일, 짧은 높이, 브라우저 200% 확대, 메뉴 접기/펼치기 | 상하 폴백에서 입력과 헤더 액션에 접근 가능하고, 메뉴 폭 변경에 따라 내부 표시가 재평가된다. |
| V12 | 라이트/다크·키보드·reduced motion | 분리 상태·아이콘·포커스가 식별되고 기존 모션 감소 설정을 유지한다. tooltip은 실제 창 종류와 좁은 창 예외를 설명한다. |
| V13 | 팝업 드래그/방향키 이동, 결과 크게 보기, Esc, 닫기/재열기 | 기존 위치 제한·dialog 우선 닫기·메뉴 포커스 복귀가 유지된다. 결과 모달은 분리 열에 갇히지 않는다. |
| V14 | 다른 방·프로젝트·사용자로 전환 및 새로고침 | 기존 방/권한 초기화를 유지한다. 창 배치 유지·초기화는 최종 결정한 수명 정책과 일치한다. |

너비 검증은 transition 완료 후 `getBoundingClientRect()`로 측정한다. 패널 50%는 viewport가 아닌 `.workspace-content-layout` 너비와 비교하고, 팝업은 viewport 상한을 반영한다. 1~2px의 반올림 오차는 허용한다. 실제 좌우 표시는 메시지와 입력의 x좌표·폭·높이를 함께 검사해 확인한다.

### 6.3 향후 실행할 검사

- `pnpm typecheck`, 수정한 TS/TSX 파일 대상 ESLint, `pnpm build`로 타입·문법·빌드를 확인한다.
- `node scripts/test-navigation-browser.mjs`에 추가한 분리 시나리오를 실행하고, `pnpm test:ai-targets-browser`로 기존 target/초안·첨부 보존을 확인한다.
- `pnpm test:ai`는 생성/중지/첨부 흐름까지 영향을 주는 변경이 포함되었거나 기존 회귀 확인이 필요한 경우 임시 테스트 DB·모의 AI 환경에서 수행한다. 화면 레이아웃 수정만으로 운영 DB나 실제 AI 호출을 사용할 필요는 없다.
- 브라우저 검증에서 작성 중 textarea DOM 동일성, 전환 전후 값·첨부 수, 요청 수, 너비/스크롤 geometry를 확인한다. 구현 세부 클래스 이름만 비교하는 테스트는 수용 검증으로 삼지 않는다.

위 명령과 테스트 파일 수정은 모두 향후 구현 단계의 계획이며 이번 단계의 실행 결과를 뜻하지 않는다.

## 7. 영향과 주요 위험

| 항목 | 영향/위험 | 대응 방향 |
| --- | --- | --- |
| CSS 우선순위 | 후반 drawer 규칙이 grid·카드 높이를 덮으면 반쪽 높이나 이중 스크롤이 발생한다. | 최종 적용 규칙을 함께 정리하고 패널/팝업/폴백 각각 실제 높이를 검사한다. |
| 기본 확대 해석 | “기본 확대”를 항상 확대 강제로 해석하면 기존 축소 버튼과 충돌한다. | 진입 기본값과 이후 조작을 구분하고 8절에서 확정한다. |
| 팝업 경계 | 분리로 너비가 커진 후 기존 좌표를 유지하면 화면 밖으로 넘칠 수 있다. | 유효 확대값으로 초기 위치와 resize/상태 변경 보정을 통일한다. |
| 데이터/생성 보존 | 레이아웃별 조건부 컴포넌트나 key 변경은 입력·이미지·진행 요청을 초기화한다. | 같은 인스턴스와 DOM에 배치 규칙만 적용한다. |
| 실제 공간 부족 | 50% 패널이라도 2열 입력을 쓰기에는 좁을 수 있다. | 내부 가용 폭으로 폴백하고 새 외부 너비를 임의 도입하지 않는다. |
| 사용자 기대 | 분리 설정이 켜졌지만 좁아서 상하로 보이면 버튼이 오작동한 것으로 보일 수 있다. | tooltip/설명에 예외를 명시하고 최종 모바일 정책을 확정한다. |
| 기존 작업과 충돌 | 현재 관련 소스에 미커밋 변경이 존재한다. | 구현 직전 최신 diff를 확인하고 기존 target/방/메뉴 변경을 보존한다. |

## 8. 결정이 필요한 사항

확정 요구사항을 다시 승인받기 위한 목록이 아니라, 사용자 검토 시 선택할 세부 정책이다. 아래 항목은 구현 전까지 제안으로 유지한다.

| ID | 검토 항목 | 권장안 | 다른 선택의 영향 |
| --- | --- | --- | --- |
| D1 | 좌/우 방향과 입력 범위 | 왼쪽 대화, 오른쪽 기존 입력 카드 전체, 방 제목은 공통 행. | textarea만 분리하면 모델·대상·첨부·버튼의 배치를 추가 설계해야 한다. |
| D2 | 분리 해제 시 너비 | 상하 모드에서 마지막으로 선택한 기본/확대 너비를 복원한다. | 분리 후 확대를 유지하면 더 단순한 단일 expanded 상태를 사용할 수 있지만 진입 전 너비로 돌아가지 않는다. |
| D3 | 분리 모드에서 축소 허용 여부 | 진입 시 확대를 기본 적용하고 이후 수동 축소를 허용한다. | 항상 확대를 강제하려면 축소 버튼을 비활성화하거나 의미를 바꿔야 한다. |
| D4 | 모바일/좁은 패널 정책 | 기존 외부 너비를 유지하고 내부 560px 미만은 상하 표시한다. | 항상 두 열을 요구하면 모바일 사용성과 기존 440px 패널 상한의 변경이 필요하다. |
| D5 | 내부 비율·최소 폭·textarea 높이 | 1:1, 간격 12px, 분리 최소 폭 560px, textarea 최소 100px을 시작안으로 검증한다. | 대화 60%/입력 40% 등 다른 비율은 입력 컨트롤의 최소 폭과 임계값 재검토가 필요하다. |
| D6 | 창 설정의 유지 범위 | 현재 훅 수명에 맞춰 닫기/방 전환 시 유지하고 새로고침 시 초기화한다. | 계정 전환 시 분리/확대 설정도 초기화하거나 계정별 영속 저장하려면 별도 수명 처리/저장 설계가 필요하다. DB 저장은 현재 요구에 없다. |
| D7 | 고정 비율 외 추가 조작 | 이번에는 고정 비율 버튼 전환만 제공한다. | 분할선 드래그·열 순서 교체·단축키는 별도 요구와 접근성/포인터 처리 설계가 필요하다. |

본 문서는 구현 지시가 확정되기 전 검토 자료다. 사용자가 문서를 수정한 뒤 구현을 요청하면 그 최종 문서를 기준으로 변경과 검증 범위를 확정한다.
