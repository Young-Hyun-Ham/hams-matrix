- 작성일: 2026-11-04 (한국시간, Asia/Seoul)
- 대상: `hams-matrix/app/(editor)/planning-board`
- 상태: 검토용 설계. 사용자가 문서를 검토·수정한 뒤 별도로 구현을 요청한다.
- 분석 기준: 작성 시점의 작업 디렉터리 최신 소스. 기존 미커밋 변경과 신규 파일을 포함한다.
- 선행 문서: [플래닝보드 API 경로·로그인 인증 정리](플래닝보드-API경로-로그인인증-정리.md)
- 이번 단계의 변경 범위: 이 문서 및 `HISTORY.md`만 작성한다. 애플리케이션 소스, 테스트 코드, 패키지, DB와 데이터는 수정하지 않는다.

## 1. 요구사항

| 10 | 빨간 배경·흰 숫자의 1~30 번호 이모티콘 | 1부터 30까지 모두 제공하고, 숫자가 도형 안에서 읽히도록 중앙에 배치한다. |

### 1.1 공통 유지 조건

- 기존 페이지·레이어 구조, 이미지, 댓글·메모, 저장·변경 이력, 실행 취소·다시 실행, 검토 상태와 접근 권한을 유지한다.
- 라이트·다크 모두 공통 UI 토큰을 사용한다. 문서의 텍스트색·배경색과 번호 이모티콘의 빨강·흰색은 테마 전환으로 바꾸지 않는다.
- 이동·크기 변경·텍스트 수정·이모티콘 추가는 문서 편집이다. 메모처럼 즉시 별도 API에 저장하는 기능으로 만들지 않는다.
- 요청에 없는 회전, 자동 배치, 요소 간 스냅, 다중 요소 비례 확대·축소, 신규 외부 이모티콘 서비스는 기본 범위에 넣지 않는다.

## 2. 현재 구조와 확인 근거

아래 경로는 `app/(editor)/planning-board/` 기준이다.

### 2.1 문서 상태와 선택

- `components/planning-board-editor.tsx`가 `layers`, `sizes`, `positions`, `layerText`, `layerImages`, `layerStyles`를 관리한다. `stores/editor-provider.tsx`의 화면 범위 Zustand 상태를 이용한다.
- `selected`는 대표 선택 ID, `selectedIds`는 선택 목록, `selectionAnchor`는 트리 범위 선택 기준이다. `selectLayer()`에는 single/toggle/range 모드가 이미 있다.
- `components/left-panel.tsx`에는 다중 선택 목록과 선택 모드가 전달된다. 반면 `CanvasEditor`에는 `selected`와 단일 ID 콜백만 전달되므로 캔버스에는 다중 선택 표시·영역 선택이 없다.
- `CanvasEditor` 내부의 `box`와 선택 표시 클래스도 대표 요소 하나만 기준으로 계산한다.
- 문서 스냅샷 변경을 감지하여 최대 40개 Undo/Redo 이력을 관리하며, 350ms 타이머로 가까운 변경을 묶는다. 긴 드래그를 반드시 한 작업으로 취급하는 명시적 제스처 트랜잭션은 없다.

### 2.2 캔버스 좌표와 조작

- `components/canvas-editor.tsx`는 선택 도구 `cursor`, 손 도구 `hand`, 줌 10~300%, 스크롤 및 `panOffset`을 관리한다.
- 페이지는 작업 공간 좌표, 하위 요소는 실제 배치 부모 기준 좌표로 렌더링된다. 중첩 컨테이너의 `.custom-layer-children`에는 별도 여백과 클리핑이 있다.
- 선택 요소의 DOM `getBoundingClientRect()`를 작업 공간 배율로 환산하여 선택 박스를 계산한다. 저장 위치가 없는 요소는 이동 시작 시 `offsetLeft/offsetTop`을 사용한다.
- `beginMove()`는 배율로 나눈 포인터 이동량을 사용하며, 하위 요소는 부모 영역, 페이지는 음수 좌표 방지를 기준으로 제한한다.
- `beginResize()`는 `nw/ne/sw/se`만 지원한다. 최소 크기 24×18을 기본으로 하되 부모 잔여 공간이 더 작으면 그 범위 안으로 제한한다.
- 상·하·좌·우의 `.move-edge`는 현재 크기 조절이 아닌 이동을 실행한다. `.resize-overlay`는 `pointer-events: none !important`이고 가장자리와 모서리만 이벤트를 받는다. 따라서 overlay에 `beginMove`가 연결되어 있어도 중앙에서는 해당 경로로 이동을 시작할 수 없다.
- 편집 캔버스에는 방향키 이동 핸들러가 없다. 미리보기의 키보드 페이지 이동과 왼쪽 트리의 이름 편집 키 처리는 별도 기능이다.

### 2.3 텍스트 옵션과 렌더링

- `components/right-panel.tsx`의 콘텐츠는 textarea로 입력받고 `layerText[id]`에 원문 문자열로 저장한다. 저장 단계에서 개행을 제거하는 구조는 아니다.
- 캔버스는 `.custom-layer-content`에 텍스트 노드를 넣고, 미리보기는 `.preview-element-content`에 넣는다. 텍스트 전용 개행 보존 CSS가 없고 공통 flex 정렬을 사용한다.
- `components/types.ts`의 `LayerStyle`에 `textAlign: left/center/right`와 `backgroundColor`가 이미 있다. 캔버스·미리보기·문서 코덱도 이 값을 전달한다.
- 콘텐츠 아래 정렬 버튼은 없으며, 타이포그래피에는 크기·행간·글자색·굵기만 있다. 배경색은 `!isText`인 모양 영역에 있어 텍스트에서 수정할 수 없다. `isText`는 text/button을 함께 취급한다.
- 미리보기 콘텐츠는 flex 중앙 정렬이므로 `textAlign` 값만 변경해서는 왼쪽·오른쪽 정렬이 기대대로 보이지 않을 수 있다.

### 2.4 우클릭 메뉴

- `openOrderMenu()`는 메뉴 위치만 저장한다. 우클릭 위치의 요소 ID를 새로 선택하지 않는다.
- 메뉴는 페이지 및 선택 overlay에서 열리고, 추가·순서·삭제는 현재 `selected`/`selectedLayer`를 사용한다. 다른 요소 위에서 우클릭하면 이전 선택이 메뉴 대상으로 남을 수 있다.
- 포털은 `.planning-root` 아래에 생성하므로 기존 공통 테마를 적용할 수 있다. 화면 가장자리에서 메뉴와 하위 메뉴 위치를 보정하는 로직도 있다.

### 2.5 이모티콘·저장·내보내기

- 툴바에 메모 추가는 있으나 이모티콘 추가 기능은 없다. 메모는 별도 상태와 `/memos` API를 사용한다.
- 기존 `ElementKind`는 page/section/layer/text/image/clipboard/button/checkbox/radio/select/icon이다. SVG/MUI 아이콘 레지스트리는 있지만 Unicode 이모티콘 분류나 번호 배지 목록은 없다.
- `addLayer()`는 기본 요소를 부모에 추가한 뒤 크기·위치·선택을 설정한다. 텍스트·스타일·삽입 좌표를 한 번에 지정하는 프리셋 인자는 없다.
- `lib/server/document-validation.ts`는 기존 요소 종류, 스타일 필드, 문서 크기 5MiB, 최대 2,000개 요소·30페이지·깊이 12단계, 텍스트 최대 10,000자를 검증한다.
- `db/migrations/032_planning_boards.sql`의 `planning_boards.document_json`과 revision 스냅샷에 문서가 저장된다. 현재 `schemaVersion`은 1이다.
- `lib/document-codec.ts`와 `planning-board-editor.tsx` 안에 AI 문서 변환 로직이 각각 있다. text/backgroundColor/textAlign은 양쪽 모두 기존 필드로 전달된다.
- `components/editor-data.ts`는 캔버스 DOM과 계산된 CSS를 복제하여 HTML5/React/Astro/Svelte 코드와 CSS를 만든다. `whiteSpace`는 복사하지만 `overflowWrap`은 현재 복사 목록에 없다.
- JSX 텍스트 직렬화는 개행을 포함한 텍스트를 그대로 escape한다. JSX의 공백 처리와 포맷 과정까지 확인해야 한다. 오른쪽 패널의 한 줄 복사는 각 줄의 trim/join으로 작성되어 콘텐츠 개행 손실 위험도 있다.

## 3. 공통 수정 설계

### 3.1 선택 상태와 조작 상태 분리

- 대표 선택 `selected`, 선택 집합 `selectedIds`는 편집기 상위에서 함께 관리하고 캔버스·트리가 같은 값을 사용한다.
- 빈 선택을 허용할지 기존 기본 페이지 선택으로 돌아갈지 통일한다. 권고안은 빈 영역 클릭·영역 선택 결과가 없으면 해당 페이지 선택으로 돌아가는 방식이다.
- 선택 API에 목록 교체/추가를 명시하는 콜백을 추가한다. 트리의 range 동작에 사각형 선택을 억지로 끼워 넣지 않는다.
- 캔버스의 임시 상태는 `idle / marquee / moving / resizing / panning`처럼 상호 배타적으로 관리한다. 활성 포인터 ID, 시작 좌표·문서 스냅샷, 대상 ID를 보관한다.
- 여러 요소를 선택하면 각 요소 윤곽과 공통 선택 경계를 표시한다. 다중 선택의 크기 변경 핸들은 기본적으로 숨기고, 우측 패널에는 선택 개수와 대표 요소 편집 범위를 표시한다.
- 여러 요소 이동 시 선택된 조상 아래의 자손은 이동 대상으로 다시 계산하지 않는다. 부모 이동으로 따라가는 자손이 두 번 이동하는 것을 방지한다.

### 3.2 좌표·권한·이력의 공통 처리

- 화면 좌표, 작업 공간 좌표, 배치 부모 좌표 변환을 공통 유틸리티로 분리한다. 작업 공간의 실측 rect와 실제 scale을 사용하여 스크롤·팬·페이지 위치·중첩 컨테이너 여백을 함께 반영한다.
- 방향키는 화면 픽셀이 아닌 문서 픽셀에 1을 더한다. 드래그만 화면 이동량을 배율로 나눈다.
- 이동/크기 변경은 ID별 위치·크기 patch를 한 번에 상위 상태에 반영한다. 여러 요소의 상대 간격을 보존하고, 부모 경계에 닿으면 모든 대상에 적용 가능한 공통 이동량으로 제한한다.
- 문서 편집 가능 여부는 기존 `canEdit`을 따른다. 저장 중·AI 생성 중·검토 중·READ 권한 및 잠금 요소는 수정하지 않는다. 필요 시 잠긴 조상까지 공통 판정한다.
- 현재 일부 캔버스 함수는 상위 콜백의 `canEdit`에 의존하므로 이벤트 시작과 실제 변경 콜백 모두에서 권한·대상 잠금을 확인한다.
- 드래그 도중 권한 상실·문서 전환·요소 삭제가 발생하면 조작을 중단하고 캡처·리스너를 정리한다. `pointerup`, `pointercancel`, blur, unmount도 정리한다.
- 선택 변경만으로 문서 저장 필요 상태나 Undo 항목을 만들지 않는다. 이동·크기 변경·프리셋 추가는 한 제스처에 Undo 한 번이 되도록 명시적 이력 묶음을 도입한다. 기존 350ms 입력 그룹과 중복 기록되지 않게 한다.

## 4. 요구사항별 수정 방향

### 4.1 방향키 1px 이동

- 캔버스에 포커스 가능한 편집 영역을 두고 선택/클릭 시 포커스를 전달한다. 전역에서 모든 방향키를 가로채지 않는다.
- ArrowLeft/Right/Up/Down을 각각 `(-1,0)/(1,0)/(0,-1)/(0,1)`로 처리한다. 여러 요소 선택 시 이동 가능한 최상위 선택 요소를 같은 delta로 이동한다.
- textarea/input/select/contenteditable, 레이어 이름 편집, 댓글·메모 입력, 열린 모달·메뉴, 한글 조합 입력에서는 기존 키 동작을 유지한다.
- Ctrl/Meta/Alt 조합은 1px 이동에서 제외한다. 기존 순서 메뉴에 표시된 Ctrl+방향키 안내와 충돌하지 않게 한다. Shift+10px 가속은 추가 제안이며 기본 요구사항에 포함하지 않는다.
- 실제 처리한 경우에만 `preventDefault()`로 스크롤을 막는다. 경계에서 변화가 없으면 불필요한 이력·dirty 상태를 만들지 않는다.
- 키를 길게 누를 때 브라우저 repeat 입력마다 1px 이동하고, 한 번의 키 누름~뗌은 하나의 Undo 작업으로 묶는 것을 권고한다.

### 4.2 드래그 영역으로 다중 선택

- 선택 도구에서 페이지 빈 배경 또는 작업 공간의 빈 영역을 좌클릭 드래그하면 선택 사각형을 표시한다. 손 도구에서는 기존 팬만 실행한다.
- 시작점에서 화면 기준 3px 이상 움직였을 때 제스처로 판단하여 일반 클릭과 구분한다. 모든 방향으로 드래그할 수 있도록 min/max 좌표로 사각형을 계산한다.
- 권고 범위는 시작/대상 페이지 하나의 보이는 하위 요소이다. 작업 공간에서 시작하면 사각형이 처음 교차한 페이지를 대상으로 고정하는 정책을 검토한다. 복수 페이지 동시 선택은 별도 결정 사항이다.
- 권고 판정은 선택 사각형과 요소의 실제 보이는 경계가 교차하면 포함이다. 숨김·template·잠긴 요소 및 잠긴 조상 아래 요소는 영역 선택에서 제외한다. clipping으로 완전히 가려진 요소도 제외한다.
- 부모와 자손이 동시에 포함되는 경우 부모를 대표 이동 대상으로 정규화하되 선택 표시·트리 표시 정책도 일치시킨다.
- 일반 영역 선택은 선택 목록 교체, Shift+영역 선택은 기존 집합에 추가하는 것을 권고한다. 드래그 끝의 click 이벤트가 다중 선택을 페이지 단일 선택으로 덮어쓰지 않게 한다.
- 사각형은 공통 `--primary`, `--primary-soft`로 그리고 문서 데이터에는 저장하지 않는다. Escape/pointercancel은 시작 전 선택을 복원한다. 자동 스크롤은 기본 범위 밖이며 현재 보이는 영역에서 우선 동작시킨다.

### 4.3 가장자리 한 축 크기 조절

- 방향 타입을 `n/e/s/w/nw/ne/sw/se`로 확장한다. 상·하는 `ns-resize`, 좌·우는 `ew-resize`, 모서리는 기존 대각선 커서를 사용한다.
- 기존 `.move-edge`의 이동 역할을 가장자리 resize hit area로 교체한다. 화면 기준 약 6~8px의 조작 영역을 확보하고, 모서리 핸들이 가장자리보다 우선하도록 한다.
- 오른쪽: `width`만, 왼쪽: `width`와 `x`, 아래쪽: `height`만, 위쪽: `height`와 `y`를 변경한다. 반대쪽 가장자리 위치는 고정한다.
- 수평 변경에서 `y/height`, 수직 변경에서 `x/width`는 시작값을 유지한다. 축 반전, 최소 크기 이하, 부모 바깥으로의 크기 변경을 막는다.
- 페이지/하위 요소의 기존 경계 정책과 잠금을 유지하고, 중첩 부모·줌 상태에서도 같은 수식을 적용한다. 여러 선택 요소를 함께 리사이즈하는 기능은 포함하지 않는다.

### 4.4 텍스트 개행 표시

- 텍스트 내용은 `layerText`의 원문을 유지한다. `<br>` 문자열 치환이나 HTML 주입을 하지 않고 React 텍스트 노드로 표시한다.
- 텍스트 콘텐츠에 `white-space: pre-wrap`과 긴 문자열 줄바꿈 정책을 적용한다. CRLF/LF, 연속 빈 줄, 공백·탭, 한글 입력을 검증한다. 탭은 고정 폭 정책을 정한다.
- 캔버스와 미리보기에서 동일한 텍스트 전용 내부 블록을 사용한다. 폭 100%, 높이·overflow 규칙을 정리하여 공통 flex 중앙 정렬의 영향을 제거한다.
- 기본은 사용자가 지정한 박스 크기를 유지한다. 텍스트가 높이를 넘으면 기존 클리핑을 유지하고 H 조절로 드러내는 방식이며, 내용에 맞춘 자동 높이 증가는 별도 결정 사항이다.
- 코드 내보내기의 CSS 복사 목록에 필요한 `overflowWrap`/`wordBreak` 등 실제 적용 속성을 반영한다. React/Astro/Svelte의 텍스트 직렬화는 개행이 컴파일 과정에서 축약되지 않도록 대상 문법에 맞는 문자열 표현 등으로 보존한다.
- 한 줄 복사도 문자열 내부의 `\n`과 공백을 보존해야 한다. 단순 trim/join을 유지할 수 없는 텍스트는 안전한 직렬화 또는 해당 복사 모드 제한을 검토한다.

### 4.5 콘텐츠 아래 정렬 버튼

- 1차 권고안은 텍스트의 왼쪽/가운데/오른쪽 정렬 3개 버튼이다. 선택 값은 기존 `LayerStyle.textAlign`에 저장하고 `onLayerStyle()`을 재사용한다.
- 버튼에는 의미 있는 aria-label과 `aria-pressed`를 제공하고, 선택 표시·hover·focus는 공통 테마 토큰을 사용한다. readOnly/locked에서는 실제 disabled 처리도 적용한다.
- 텍스트 블록의 폭을 요소의 내부 가용 폭 전체로 확보하여 각 줄이 같은 기준으로 정렬되게 한다. 요소의 X/Y는 변경하지 않는다.
- 수직 위치는 기존 중앙 배치를 유지하는 것을 권고한다. 상/중/하 정렬까지 요청 범위에 넣을지는 검토 후 결정한다.
- 요구사항이 요소 박스 자체를 캔버스 또는 부모의 좌/중/우에 배치하는 의미라면 별도 위치 정렬 명령이 필요하다. 그 경우 `textAlign`이 아니라 `positions`를 수정하며, 기준은 전체 캔버스가 아닌 소속 부모 내부 영역을 권고한다.

### 4.6 타이포그래피 배경색

- 텍스트 타이포그래피에 '배경색' 입력과 '투명' 동작을 추가한다. 기존 `layerStyles[id].backgroundColor`를 사용하므로 신규 DB 컬럼이나 스타일 필드는 필요하지 않다.
- 미지정 상태를 UI 기본 흰색으로 강제 저장하지 않는다. '투명'은 `transparent`로 명시하고 색상 입력은 마지막 유효 HEX 색상을 별도로 표시할 수 있다.
- 적용 범위는 글자 각각의 형광펜 배경이 아닌 텍스트 요소 박스 전체이다. 타이포그래피 변경 Undo/Redo·저장·AI 문서 변환·미리보기·내보내기에 같은 값을 전달한다.
- 현재 text/button이 타이포그래피를 공유한다. 두 종류에 같은 UI를 제공하는 권고안과, text만 표시하는 안을 결정 항목에 남긴다.
- 다크 UI와 문서 색상을 분리하여 흰 글자/빨간 배경, 투명 배경 등이 테마에 의해 덮이지 않게 한다.

### 4.7 마우스 위치 기준 우클릭

- 가장 안쪽의 보이는 `data-layer-id` 요소를 hit test하여 대상 ID를 먼저 확정한다. 필요하면 `elementsFromPoint()`로 선택 보조선·overlay를 건너뛴다. 겹침은 실제 보이는 최상단 요소를 우선한다.
- 권고안은 우클릭한 요소를 단일 선택하고 메뉴를 여는 방식이다. 다중 선택 안에서 우클릭했을 때 집합을 유지하는 정책은 별도 결정 사항이다.
- 메뉴 상태에 `targetId`를 저장하고 옵션을 그 ID로 계산한다. `setSelected()` 직후 이전 렌더의 `selected`를 참조하는 문제를 피한다.
- 각 명령 실행 시 대상의 존재·권한·잠금을 재확인한다. 우클릭으로는 이동이나 문서 변경 이력을 만들지 않는다.
- 페이지 빈 배경은 해당 페이지 메뉴를 연다. 페이지 밖 빈 작업 공간에서는 이전 요소 메뉴를 열지 않는다. 메모·입력 컨트롤·툴바·패널은 별도 동작을 유지한다.
- 메뉴는 현재 포털·화면 경계 보정·바깥 클릭 닫기를 재사용하고 Escape 닫기, 포커스 복원, READ 상태의 수정 명령 비활성화를 정리한다.

### 4.8 선택 요소 중앙 드래그 이동

- 선택된 실제 요소의 본문에서 pointerdown으로 이동을 시작하는 구조를 권고한다. overlay 전체를 `pointer-events:auto`로 바꾸어 중첩 자식 요소를 가리지 않는다.
- 커서/처리 우선순위는 모서리 resize → 가장자리 한 축 resize → 선택된 본문 move → 빈 배경 marquee → 손 도구 pan으로 명시한다.
- 선택된 컨테이너 안에서 자식 요소를 클릭하면 자식을 선택할 수 있어야 한다. 컨테이너 자신의 빈 내부만 이동 시작 영역으로 취급한다.
- 선택되지 않은 요소의 첫 클릭은 선택을 수행하고, 이미 선택된 요소의 중앙 드래그가 이동을 수행하는 방식을 권고한다. 첫 클릭과 동시에 이동시키는 정책은 결정 사항이다.
- 드래그 임계값 이전에는 단순 클릭으로 처리하고, 이동 후 뒤따르는 click으로 선택이 축소되지 않게 한다. 다중 선택 내부 요소를 잡으면 공통 delta로 선택 집합을 이동한다.
- 텍스트·폼 컨트롤은 설계 도구의 선택과 실제 입력이 충돌하지 않게 편집 캔버스에서 규칙을 통일한다. 메모 textarea와 미리보기의 실제 입력은 그대로 유지한다.
- 페이지 본문 전체를 이동 영역으로 만들면 영역 선택과 충돌한다. 페이지 본문은 영역 선택에 사용하고 페이지 이동은 제목/라벨 등 명시적 영역에 연결하는 것을 권고한다.

### 4.9 이모티콘 버튼·패널과 기본 목록

- 캔버스 상단 메모 추가 버튼 바로 옆에 '이모티콘 추가' 아이콘 버튼을 배치한다. 클릭 시 버튼 아래에 패널을 열며 `aria-expanded`, `aria-controls`를 제공한다.
- 기본 탭 권고안은 '번호', '표정', '손동작', '기호', '업무'이다. tablist/tab/tabpanel 구조로 선택 상태와 좌우키 탭 이동, Enter/Space 항목 선택, Escape 닫기를 지원한다.
- 초기 목록 예: 표정 😀 🙂 😅 😢 😡, 손동작 👍 👎 👏 🙏, 기호 ✅ ❌ ⚠️ ⭐ ❤️, 업무 📌 📝 📅 💡 🔍. 각 항목은 고정 ID·표시 문자열·한국어 이름을 가진 로컬 목록으로 관리한다.
- 기본 탭은 가장 많이 사용하는 '번호'를 권고한다. 패널에는 탭과 격자·스크롤 영역을 두고 화면 경계 보정, 바깥 클릭 닫기, 다른 팝오버와의 중복 열림을 정리한다.
- 권고 삽입 방식은 항목 클릭 즉시 활성 페이지의 현재 보이는 영역 중앙에 추가하는 것이다. 페이지 가용 영역으로 보정하며 페이지가 화면 밖이면 페이지 중앙으로 대체한다. 연속 추가는 약간씩 위치를 어긋나게 하여 겹침을 줄인다.
- 삽입은 항상 활성 페이지의 직접 자식으로 하는 것을 기본으로 제안한다. 잠긴 페이지·페이지 없음·편집 불가에서는 추가를 차단한다. 중첩 컨테이너 삽입이나 다음 클릭 위치 배치는 별도 결정 사항이다.
- 추가 후 새 요소를 선택하고 저장 필요 상태·Undo 한 건을 만든다. 툴바 팝오버로 포커스가 이동해도 기존 활성 페이지를 잃지 않게 한다.
- UI는 공통 surface/ink/line/primary/primary-soft/hover 토큰으로 라이트·다크를 모두 지원한다. 이모티콘 자체는 문서 콘텐츠이므로 테마 색 반전을 하지 않는다.

### 4.10 빨간 배경·흰 숫자 1~30

- Unicode의 원문자나 키캡 이모티콘은 색상·두 자리 숫자 지원이 일정하지 않으므로 사용하지 않는다. 일반 텍스트 숫자와 배경 스타일을 조합한 번호 배지 프리셋을 제공한다.
- 1~30을 모두 별도 항목으로 제공한다. 기본 도형은 원형, 크기 32×32 문서 px, 배경 `#dc2626`, 글자 `#ffffff`, 굵기 700, 크기 16, 가로·세로 중앙을 권고한다. 10~30도 잘리지 않도록 내부 padding과 줄바꿈을 정리한다.
- 저장 형태는 `kind: "text"`, `name: "번호 12"`, `layerText[id]: "12"`, `sizes[id]`, `positions[id]`, `layerStyles[id]`의 기존 필드를 사용한다. 원형은 `borderRadius:16`, `textAlign:"center"` 등으로 표현한다.
- 번호 배지는 이후 일반 텍스트처럼 이동·크기·글자·색상 편집이 가능하다. 자동 다음 번호, 중복 번호 차단, 1~30 외 숫자 입력 제한은 기본 범위에 넣지 않는다.
- 사각/둥근 사각형을 기본으로 할지, 번호 편집을 제한할지는 검토 항목이다. 번호 배지라는 별도 영구 타입이 필요할 때에만 스키마 확장을 다시 설계한다.

## 5. 데이터·API·DB 영향

### 5.1 권고 데이터 모델

- 일반 이모티콘과 번호 배지는 모두 기존 text 요소 프리셋으로 저장한다. 탭 분류·프리셋 ID·패널 열림 여부는 UI 목록/상태이며 문서 JSON에 추가하지 않는다.
- 일반 이모티콘은 Unicode 문자열과 기존 fontSize/backgroundColor/textAlign을 사용한다. 브라우저의 이모티콘 폰트 fallback을 이용하며 운영체제별 모양 차이는 허용한다. 이미지 업로드나 외부 CDN에 의존하지 않는다.
- 프리셋 추가 명령은 Layer·문자열·크기·위치·스타일을 하나의 작업으로 반영하도록 `addLayer()`를 확장하거나 별도 명령을 둔다. 비동기 state 직후의 selected ID를 사용하지 않고 새 ID를 명시적으로 전달한다.
- 선택 사각형·hover·선택 집합·조작 중 포인터 상태는 저장 문서에 추가하지 않는다. 여러 요소 이동 결과만 기존 positions에 반영한다.
- 스키마 버전 1과 기존 API endpoint·권한·낙관적 버전 검사를 유지한다. AI 변환의 클라이언트/서버 양쪽에서 기존 텍스트·개행·색상 보존을 확인한다.

### 5.2 DB 및 마이그레이션

- 권고안에서는 DB 테이블·컬럼·마이그레이션 변경이 필요하지 않다. 기존 `document_json`과 revision JSON에 기존 필드로 저장할 수 있다.
- 과거 문서를 일괄 갱신하거나 revision 스냅샷을 수정하지 않는다. 새 문서와 이전 문서 모두 누락된 스타일에 기본값을 적용한다.
- 이모티콘을 별도 `kind: emoji`로 구분하거나 수직 정렬 등 새 영구 필드를 추가하기로 결정하면 types/validator/AI schema/양쪽 codec/preview/기본 크기·생성 로직까지 범위가 넓어진다. 이 경우 DB JSON·schemaVersion 호환 정책을 구현 전에 다시 확정한다.
- 이번 설계 단계에서는 DB 연결·테스트 DB 생성·마이그레이션·데이터 수정도 수행하지 않는다.

## 7. 검증 방법과 수용 시나리오

### 7.1 좌표·선택·조작

1. 각 방향키 입력에 X/Y가 정확히 1px 변하고 반대 축은 유지되는지 확인한다. 50/100/200% 줌, 팬·스크롤, 중첩 부모, 페이지 위치 변경 후 반복한다.
2. 입력란·레이어 이름·메모·댓글·한글 IME·모달에서는 방향키가 커서 이동 등 본래 기능을 유지하는지 확인한다. Ctrl/Meta 조합이 이동을 유발하지 않아야 한다.
3. 사각형을 4방향으로 드래그하고 교차·비교차·경계 접촉·클리핑·숨김·잠금 요소를 검증한다. Shift 추가 선택과 드래그 종료 후 선택 유지, 트리 동기화, Escape 취소도 확인한다.
4. 선택된 부모/자손을 함께 포함해 이동해도 자손이 두 배 이동하지 않는지, 서로 다른 부모의 요소 이동에서 상대 간격이 유지되는지 확인한다.
5. 상/하 resize는 W/X, 좌/우 resize는 H/Y가 변하지 않아야 한다. 위/왼쪽 resize에서 반대편 경계가 고정되는지 수치로 확인한다. 최소 크기·부모 경계·4개 모서리도 회귀한다.
6. 중앙 move/가장자리 resize/모서리 resize/빈 영역 선택/손 도구 pan 커서를 실제 포인터 위치에서 확인한다. 선택 컨테이너가 자식 클릭을 가리지 않아야 한다.
7. 다른 요소·겹친 요소·중첩 자식·페이지 빈 영역·선택 보조선 위에서 우클릭하여 메뉴 대상 ID와 실제 순서 변경/삭제 대상이 같은지 확인한다.
8. 드래그 중 pointercancel, 창 포커스 이탈, 권한 변경, 화면 전환 후 리스너·임시 overlay가 남지 않는지 확인한다. READ/잠금/검토 중에는 문서가 변하지 않아야 한다.
9. 긴 드래그·키 repeat·프리셋 추가가 Undo 한 번으로 복구되고 Redo로 동일하게 재현되는지 확인한다. 선택만 변경한 경우 저장 필요 상태가 생기지 않아야 한다.

### 7.2 텍스트·이모티콘·저장

| 검증 항목 | 입력/조작 | 기대 결과 |
| --- | --- | --- |
| 개행/빈 줄 | `첫째 줄\n\n셋째 줄`, CRLF, 긴 한글·영문, 연속 공백 | 캔버스·미리보기·원본 코드 내보내기에서 줄/공백 보존. |
| 정렬 | 여러 줄에 좌/중/우 버튼 적용 | 박스 위치는 유지하고 각 줄의 텍스트 정렬 변경. |
| 배경 | 색상 지정 → 투명 → Undo/Redo | text 배경과 저장된 스타일이 일치하며 다른 요소는 변하지 않음. |
| 이모티콘 패널 | 탭 전환, 키보드 이동, Escape/바깥 클릭 | 포커스·선택·닫힘 동작 정상, 화면 밖으로 패널이 잘리지 않음. |
| 기본 이모티콘 | 각 분류에서 추가 | 새 ID의 text 요소로 생성, 활성 페이지 안에 배치, 트리 선택 동기화. |
| 번호 이모티콘 | 1/9/10/20/30 및 전체 30개 목록 검사 | 빠진 번호 없음, 빨간 배경·흰 숫자, 두 자리 중앙 표시와 크기 조절 정상. |
| 저장/호환 | 추가·이동·스타일 변경 후 저장/재조회/이력 | 문자와 모든 기존 필드 보존, 이전 문서도 정상 로드, DB 스키마 변경 없음. |
| 내보내기 | HTML5/React/Astro/Svelte + CSS, 원본/한 줄 복사 | 개행·이모티콘·배경·정렬 보존, 선택 사각형·핸들·패널은 결과에서 제외. |
| 테마 | 라이트↔다크, 패널·버튼 hover/focus/disabled | UI는 공통 테마색, 문서 및 번호의 지정 색은 동일. |

- 순수 좌표/선택 함수는 실제 경계·중첩·축 유지 조건을 검증하는 테스트를 추가한다. 구현을 그대로 따라 쓰는 단순 테스트는 피한다.
- 향후 구현 후 실행: `pnpm typecheck`, 변경 파일 ESLint, `pnpm build`, `pnpm test:planning-board`, `pnpm test:planning-board-browser`.
- 기능 검증은 임시 DB·가짜 사용자·격리 브라우저를 사용하며 실사용 데이터나 유료 AI 호출에 의존하지 않는다.
- 현재 전체 브라우저 검증에는 앞선 작업에서 `mobile template imported` 대기 시간 초과가 기록되어 있다. 구현 검증 시 먼저 원인을 확인하고, 조작 기능의 집중 검증 결과와 전체 회귀 결과를 구분한다.
- 이번 단계에서는 소스 정적 분석과 문서·링크 확인만 수행한다. 위 명령과 DB를 사용하는 검증은 구현 단계에서 실행한다.

## 9. 향후 구현 순서

1. 문서 검토 결과에 따라 8절의 정책을 확정하고 구현 시작 시 이 문서의 최신 내용을 다시 읽는다.
2. 공통 선택·좌표·일괄 patch·이력 처리부터 정리한다.
3. 방향키, 영역 선택, 가장자리 resize, 중앙 move, 우클릭을 같은 이벤트 우선순위로 연결한다.
4. 텍스트 개행·정렬·배경을 캔버스/미리보기/내보내기에 함께 반영한다.
5. 기존 text 프리셋 기반 이모티콘 패널과 번호 1~30을 추가하고 테마·접근성·저장/이력을 연결한다.
6. 집중 검증과 전체 회귀를 수행한 뒤 실제 변경 파일·DB 변경 여부·결과·미완료 사항을 별도 작업 기록에 남긴다.
