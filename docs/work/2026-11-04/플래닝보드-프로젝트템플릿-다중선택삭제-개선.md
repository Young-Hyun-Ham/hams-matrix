# 플래닝보드 프로젝트 템플릿·다중 선택 삭제 개선

- 작성일: 2026-11-04 (한국시간)
- 기준: [최신 설계 문서](../../history/2026-11-04/플래닝보드-프로젝트템플릿-다중선택삭제-개선.md)를 다시 읽고 구현했다.

## 주요 변경사항

- 프로젝트 owner 전용 템플릿 생성 모달과 프로젝트 범위 목록·조회·적용 API를 추가했다. 계정 master만으로 생성 권한을 부여하지 않으며 현재 보드 전체의 미저장 스냅샷을 사용한다.
- 기본/커스텀 템플릿을 목록에서 구분하고 생성 직후·focus·같은 프로젝트 창 알림으로 갱신한다. 템플릿 작업의 403/404는 현재 화면 접근 오류와 구분한다.
- 템플릿 이미지는 원본 화면과 독립 보관하고 적용 시 대상 화면 자산으로 복제한다. 생성 멱등성·이름 중복·pending/ready·실패 보상·권한 재확인을 적용했다.
- 선택 내부 우클릭에서 집합을 유지하고 개수와 삭제만 표시한다. 캔버스·트리 Delete도 동일한 재귀 삭제를 사용한다. 자손의 모든 map을 정리하고 한 번의 Undo로 복원한다.
- 잠금/잠긴 자손/마지막 페이지 등 제약이 섞이면 전체 삭제를 차단한다. 다중 선택 디자인 패널은 요청 문구만 표시하고 코드 탭은 유지한다.
- 문서의 미확정 항목은 권고안으로 구현했다. 프로젝트 템플릿 총수는 누적 생성을 제한하도록 100개로 정했고, 이름은 NFC·trim·소문자 key로 중복 검사한다. 수정/삭제 관리 UI는 요청 범위 밖이다.

## DB 변경 여부

- 기존 DB에 **033만** 트랜잭션으로 적용했다. `planning_project_templates`, `planning_project_template_assets`와 범위 FK·유일키·인덱스를 추가하고 적용 이력을 확인했다.
- 기존 보드/화면/이미지 데이터 및 이전 migration은 변경하지 않았다. 다른 미적용 migration을 함께 실행하지 않았다.
- 기능 검증의 사용자·문서·이미지는 임시 DB와 저장소 대역에만 생성한다. 실사용 템플릿 데이터나 이미지 복제는 실행하지 않았다.

## 검증 결과

- `pnpm typecheck`: 통과.
- `pnpm test:planning-board`: 통과. 프로젝트 역할/워크스페이스·프로젝트 격리, 생성 재시도·이름 충돌, 원본 삭제 후 이미지 적용·저장, 검토/스토리지 실패/복사 중 소유자 변경, 자손 일괄 삭제 map 정합성과 기존 회귀를 검증했다.
- `pnpm build`: 통과. 정적 생성 중 기존 일반 `Request failed Error` 로그 5건이 있으나 빌드 자체는 성공했다.
- 변경 소스·검증 스크립트 ESLint: 오류/경고 없이 통과.
- `pnpm test:planning-board-browser`: 전체 통과. 다중 선택 메뉴의 집합/개수, 삭제·캔버스/트리 Delete·repeat 방지·한 번 Undo 복구와 우측 속성 DOM 숨김을 실제 Chrome에서 확인했다.
- 실제 생성 모달→목록 즉시 반영→같은 프로젝트의 다른 화면 적용→대상 화면 이미지 복제→Undo/Redo→다른 프로젝트 목록/직접 조회 차단을 확인했다. 템플릿 404가 편집기 전체를 숨기지 않는 것도 확인했다.
- 기존 인증·권한·오류 복구·편집 보존·화면 범위 분리·이미지·5종 내보내기·저장·미리보기·READ·테마·화면 실행 링크 회귀도 통과했다.
- 브라우저 증거 폴더: 임시 경로의 `matrix-planning-board-browser-IRpXPI`. 생성 모달과 이미지가 포함된 적용 화면 스크린샷을 확인했다.
- 작업 전 파일 해시와 비교하여 기존의 다른 변경사항과 설계 문서를 보존했음을 확인했다.
