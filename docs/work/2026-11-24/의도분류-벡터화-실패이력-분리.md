# 의도분류 콘솔 벡터화 실패 이력 분리

- 사용자 확인: 실패 대상은 AI 답변이나 RAG 검색 대체가 아닌 프로젝트 벡터화 생성 작업이다.
- 좌측 메뉴에 실패 이력을 추가하고 `view=failures` 직접 진입을 지원한다. 분류 이력과 별도 화면에서 실패한 벡터화 작업만 조회한다.
- `project_rag_jobs.status='failed'` 기준으로 작업 당시 설정 버전, 모델, 생성/종료 시각, 오류 코드, 처리 현황과 검색본/작업 ID를 반환한다. 재개 후 검색본이 성공해도 과거 실패 작업은 유지한다. 설정 버전을 임의의 검색본 순번으로 바꾸지 않는다.
- 실패 이력은 전체 기간이 기본이며 KST 생성일 검색과 생성 시각/작업 ID 커서로 20건씩 조회한다. 분류 목록은 실패 상태 검색본을 참조하는 이벤트를 제외한다. 검색 대체 사유만 있는 분류를 벡터화 실패로 간주하지 않는다.
- 기존 owner/현재 workspace/프로젝트/이력 플랜 검증과 private, no-store 정책을 유지한다. 개인 질문, API 키, 암호문, 저장소 경로를 추가 반환하지 않는다. 새 폴링이나 DB migration은 없다.
- 격리 DB API 검증: 실패 작업 필터, 완료 작업 제외, 동일 시각 커서 중복 방지, KST 기간, 잘못된 입력, 타 프로젝트 격리, non-owner 거부, 기존 분류 목록의 실패 검색본 제외와 기존 회귀 통과.
- 통과: `pnpm test:intent-classifications`, `pnpm test:project-rag`, `pnpm typecheck`, 변경 파일 ESLint, `pnpm build`.
- 통과: `pnpm test:intent-classifications-browser` — 실패 메뉴 활성화, 실패 목록/페이지 이동, 320px 화면 및 기존 분류 상세/검색 참조/테마/권한 회귀. `.auth-tests/intent-console/failure-history-mobile.png` 화면 확인 완료.
