# 프로젝트 문서함

프로젝트 마지막 탭에서 하위 폴더 생성·이름 변경·빈 폴더 삭제 및 여러 파일 업로드·다운로드를 제공합니다. 기존 프로젝트 권한을 적용하며 조회 전용 사용자는 업로드와 폴더 변경을 할 수 없습니다.

## 설정

서버 `.env`에 `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`과 `R2_ENDPOINT`(계정의 S3 API 엔드포인트)를 설정합니다. `R2_ENDPOINT`가 없으면 `CLOUDFLARE_ACCOUNT_ID`로 구성합니다. `R2_TOKEN`은 S3 요청에 사용하지 않습니다. 접근 키에는 해당 버킷의 객체 읽기·쓰기 권한이 필요합니다. 버킷은 비공개로 유지합니다.

`pnpm db:migrate`로 `014_project_documents.sql`을 적용합니다. 기존 데이터는 변경하지 않습니다.

## 저장 방식과 범위

- 폴더와 파일 메타데이터는 Turso, 실제 파일은 R2에 보관합니다.
- 객체 키는 `workspaces/{workspaceId}/projects/{projectId}/documents/{fileId}`입니다. 이름 변경 시 객체를 이동하지 않습니다.
- 업로드·다운로드는 인증된 Next.js API를 통과하므로 브라우저용 R2 CORS 설정은 필요 없습니다. 파일당 20MiB, 빈 파일은 허용하지 않습니다. 서버 메모리와 호스팅 요청 크기·시간 제한에 유의하세요. 호스팅 제한이 더 작다면 직접 업로드 방식으로 전환해야 합니다.
- 동일한 파일명은 별도 문서로 보관하며 덮어쓰지 않습니다.
- 폴더 삭제는 비어 있을 때만 가능합니다. 파일은 관리 열에서 확장자를 포함한 이름 변경과 삭제를 할 수 있습니다. 삭제 확인 후 R2 객체와 DB 메타데이터를 제거하며, 복구 기능은 제공하지 않습니다. 파일 이동은 제공하지 않습니다.
- 파일명 더블클릭으로 새 탭에서 ONLYOFFICE 문서 편집기를 엽니다. 별도 문서 서버 설정과 편집·저장 범위는 [ONLYOFFICE 연결](ONLYOFFICE.md)을 참고하세요.
- 파일 이름 변경은 메타데이터만 수정하고 R2 객체 키와 파일 내용은 유지합니다. R2 삭제 실패 시 DB 메타데이터를 유지해 재시도할 수 있습니다. R2 삭제 후 DB 커밋 이전에 프로세스가 중단되면 목록에 파일이 남을 수 있으며 삭제를 재시도할 수 있습니다.
- 파일 다운로드는 `attachment`와 `application/octet-stream`으로 제공하며 프로젝트 및 워크스페이스 범위를 확인합니다.
- 업로드 후 DB 저장 실패 시 R2 객체 삭제를 시도합니다. 프로세스 강제 종료 등으로 남는 객체는 향후 정리 작업이 필요할 수 있습니다.
- 감사 기록은 기존 `DB_LOGGING_ENABLED` 설정을 따릅니다.
