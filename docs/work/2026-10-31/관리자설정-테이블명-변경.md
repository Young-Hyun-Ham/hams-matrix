# 관리자 설정 테이블명 변경

- 작성일: 2026-10-31 (한국시간)
- 요청: `app_settings`를 `admin_setting`으로 변경하고 기존 컬럼과 데이터를 보존한다.

## 주요 변경사항

- `029_rename_admin_setting.sql`에 `ALTER TABLE app_settings RENAME TO admin_setting`을 추가했다. 기존 마이그레이션 002는 신규 DB의 순차 설치와 이전 이력 보존을 위해 수정하지 않았다.
- 서버 설정 조회, 관리자 로깅 설정 변경, 감사 로그 조건 SQL을 새 테이블명으로 변경했다. 전역 설정의 의미, API 경로와 응답 형식은 유지했다.
- 테스트·운영 업그레이드 스크립트와 운영 안내 문서를 변경했다. 업그레이드 스크립트는 변경 전후 테이블명을 구분해 설정 보존 여부를 비교한다.
- 기존 설계/작업 기록과 사용자 작성 PROMPT.md의 과거 명칭은 보존했다. 이전 스키마를 검증하는 테스트 및 마이그레이션에는 의도적으로 이전 명칭이 남아 있다.

## 변경 파일

- DB: `db/migrations/029_rename_admin_setting.sql`
- 운영 소스: `lib/settings.ts`, `lib/audit.ts`, `app/api/admin/settings/logging/route.ts`
- 스크립트: `scripts/upgrade-accounts.mjs`, `scripts/test-admin-setting-rename.mjs`, `scripts/test-accounts-plans.mjs`, `scripts/test-auth.mjs`, `scripts/test-documents.mjs`, `scripts/check-projects.mjs`, `scripts/check-artifacts.mjs`
- 안내/기록: `.env.example`, `README.md`, `docs/AUDIT.md`, 본 문서, `WORK_HISTORY.md`

## DB 변경 여부

- 실제 연결 DB에 029를 트랜잭션으로 적용하고 `schema_migrations`에 기록했다.
- 변경 전후 모든 행과 컬럼 정의가 동일하고, 인덱스 개수가 같으며, 이전 테이블이 제거되었음을 확인한 뒤 커밋했다. 기존 인덱스 이름은 보존했다.
- 기존 DB에 023 토스트 마이그레이션 적용 이력이 누락된 상태이므로 전체 마이그레이션을 재실행하지 않고 이번 029만 적용했다. 이 기존 불일치는 수정하지 않았다.

- `pnpm typecheck`: 통과.
- 변경 소스/스크립트 대상 ESLint: 통과.
