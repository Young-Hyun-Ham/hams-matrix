# 대시보드 의도분류 버튼 배치와 조회 화면 스타일 구현

- 작성일: 2026-11-24 (한국시간, Asia/Seoul)
- 기준: [최신 설계](../../history/2026-11-24/대시보드-의도분류-버튼배치와-조회화면-스타일-설계.md)를 다시 읽고 구현했다.
- 상태: 구현·관련 UI 검증 완료. 가드레일 전체 브라우저 회귀의 범위 밖 HITL 정렬 실패는 아래에 별도 기록했다.

## 주요 변경사항

- 의도분류 버튼과 조건부 새창 재열기를 전용 행으로 묶고 검색본 요약은 아래로 분리했다. 두 버튼은 공통 `button small`을 사용한다.
- 대시보드 카드에서 첫 버튼은 왼쪽, 재열기는 오른쪽 끝에 정렬한다. 문서의 권고안대로 긴 문구는 유지하며 실제 폭이 부족할 때만 재열기를 오른쪽 다음 줄로 보낸다. 상태 안내는 재열기 아래에 표시한다.
- 브라우저 검증에서 재클릭 안내 문구가 버튼 행을 불필요하게 넓히는 문제를 확인하여 안내를 버튼 너비 안에서 줄바꿈하도록 보정했다.
- 공통 `ConsoleWindowButton`에 기본값이 있는 `buttonClassName`만 추가했다. 기존 권한 검사·15초 확인 유효기간·팝업 옵션·null handle 재시도·모달 닫힘 흐름은 보존한다.
- 의도분류 조회에 전용 좌측 탐색, 상단 헤더, 검색본 상태, 필터 카드와 목록·상세 카드를 적용했다. 관제센터의 배경·테두리·글꼴·간격·1439/1100/1023/640px 반응형 기준을 따른다. 359px 이하에서는 필터를 한 열로 표시한다.
- 좌측 메뉴는 현재 기능인 분류 이력만 제공하며 공통 셸 추출은 하지 않았다. 조회 화면 내부 상태를 카드 안으로 정리하고 기존 서버 권한 차단·공통 boundary 표현은 유지했다.
- 기존 필터 초안·적용 조건·커서·선택 이벤트·URL, owner 접근 제한, Query 정책, ThemeToggle/PreferencesRuntime을 유지한다. 가드레일 메뉴·통계·15초 데이터 폴링은 추가하지 않았다.
- 기존 다른 미커밋·미추적 변경은 보존했다.

## 변경 파일

- UI: `components/ai/project-rag-control.tsx`, `components/ai/intent-classifications-page.tsx`, `components/shared/console-access.tsx`.
- CSS: `styles/ai-project-rag.css`, `styles/pages/dashboard/dashboard-page.css`, `styles/pages/projects/intent-classifications/intent-classifications.css`.
- 검증: `scripts/intent-classifications-browser.mjs` — 구조 변경 선택자, 320~1440px 배치, 필터 초안·선택·테마 보존, 대시보드 재열기 정렬·긴 요약 검증. SSR 이후 실제 모달 열림·프로젝트 후보 로드를 기다리도록 보강하고 실패 시 합성 화면 증거를 남긴다.
- 검증: `scripts/test-dashboard-browser.mjs` — 새 대화의 기본 팝업·확대 상태와 무관하게 패널 축소/확대를 검증하도록 기존 전제를 보정. SSR 직후 클릭 유실을 막도록 프로젝트 만들기 모달의 실제 열림을 기다린다.
- 문서: `README.md`, `AGENTS.md`, `CLAUDE.md`, `styles/README.md`, `WORK_HISTORY.md`, 이 작업 기록.

## DB 변경 여부

- 구성 DB의 스키마·데이터·마이그레이션 변경 없음. 구성 DB 대상 변경·마이그레이션 명령을 실행하지 않았다.
- API/서비스/DTO/Query key/워커/AI 호출 경로 변경 없음. 회귀 검증은 기존 임시 SQLite·합성 계정·모의 공급자를 사용한다.

- 통과: `pnpm test:intent-classifications` — 실제 조회·권한 API, KST·커서, 최소 메타데이터, 관리자+owner 및 권한 회수.
- 통과: `pnpm test:dashboard` — 요약·권한·KST·기존 API 회귀.
- 통과: `pnpm test:project-rag` — 벡터화·실패 재개·권한·원자 발행·검색·FK 회귀.
- 통과: `pnpm test:ai-guardrail-approvals` — 기존 승인·재개·HITL·동시 대기·권한·FK 회귀.
- 통과: `pnpm typecheck`, 최종 CSS 보정본의 `pnpm build` 및 변경 파일 ESLint. 빌드의 TypeScript 검사도 통과했다.
- 통과: 최종 빌드의 `pnpm test:dashboard-browser` — 카드/작업 화면 RAG 모달·KST·SSR·필터·권한·오류·모바일/테마·AI 패널 회귀. 초기 AI 창 상태 가정과 SSR 직후 클릭 타이밍을 보강한 뒤 최종 전체 실행을 통과했다.
- 확인: 의도분류 화면의 320~1440px 수평 넘침 없음, 필터 초안·선택 이벤트 DOM·URL 보존, 공통 테마 토글, 라이트/다크 및 모바일 메뉴 이미지 검토.
- 통과: 최종 빌드의 `pnpm test:intent-classifications-browser` — 콘솔 셸, 320~1440px, 초안·선택·테마 보존, 긴 요약 및 재열기 최초/권한 확인 문구의 버튼 양끝 정렬, 양쪽 모달 진입, owner/non-owner, 팝업 null handle/재클릭, 실제 새창, 관리자 프로젝트 선택, 권한 회수 흐름.
- 통과: 이번 변경 대상의 `git diff --check` 및 문서 링크 존재·이력 링크 1건 확인.
- 실패: `pnpm test:ai-guardrail-approvals-browser` — `scripts/guardrail-approval-browser.mjs`의 `HITL actions align to the left edge` 검사에서 중단했다. 관제 진입·overview 및 승인/명시 재개 흐름 이후 챗봇 HITL 정렬 검사다. 해당 챗봇·HITL 소스와 테스트는 이번 작업에서 변경하지 않았다. 일반 가드레일 승인 회귀는 통과했다.
- 환경: 샌드박스의 node_modules 읽기 제한으로 ESLint/빌드 EPERM 및 타입 검사 TS6053이 발생하여 샌드박스 밖 동일 검증으로 재실행했다. pnpm shim의 spawn EPERM은 `node node_modules/eslint/bin/eslint.js` 직접 실행으로 우회하여 통과했다.
- 기존 전체 `git diff --check`는 `PROMPT.md`의 기존 trailing whitespace를 보고한다. 해당 파일은 수정하지 않는다.

## 미완료 및 재개 정보

- 요청한 버튼 배치·공통 스타일·의도분류 콘솔 개편과 문서 갱신의 미완료 사항은 없다. DB 적용 작업도 없다.

- 의도분류 UI 증거 이미지는 `.auth-tests/intent-console/`, 기존 대시보드 증거는 `.auth-tests/dashboard/`에 생성한다. 모두 합성 테스트 데이터다.
