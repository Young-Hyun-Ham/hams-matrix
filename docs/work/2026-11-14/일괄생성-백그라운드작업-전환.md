# 일괄 생성 백그라운드 작업 전환

- 작성일: 2026-11-14 (한국시간)
- 요구사항: 긴 RFP·첨부 문서 생성이 120초 제한으로 중단되지 않도록 HTTP와 생성을 분리한다. 창 닫기·새로고침과 독립적으로 처리하고 진행 조회, 중지, 작업자 재시작 복구를 지원한다.

## 주요 변경

- 시작 API는 원본 확인·스냅샷·작업 등록 후 HTTP 202를 반환한다. continue API는 중복 검토 선택을 저장할 뿐 AI를 실행하지 않는다.
- 기존 생성 요청 테이블을 영속 대기열로 사용한다. 독립 Node 작업자가 running/validating/stop_requested 작업을 처리하고, 중복 검토는 사용자 선택 전까지 대기한다. 여러 작업자의 조건부 lease 획득으로 중복 실행을 방지한다.
- 작업자의 AI 생성은 전체 대기 시간 제한을 해제한다. 일반 탭 AI의 기존 120초 제한은 유지한다. 생성 접수 통신은 최대 30초, 개별 응답 조회는 10초로 제한하고, 작업자는 일시적 상태 조회 장애를 재시도한다.
- 작업 잠금은 180초이며 체크포인트에서 20초 간격으로 갱신한다. 브라우저 HTTP 연결의 AbortSignal을 작업 실행에 사용하지 않는다.
- 원래 사용자·workspace 기준으로 최신 사용자와 권한을 확인한다. 활성 workspace 변경이 원래 작업의 실행 범위를 바꾸지 않는다. 원본/기존 산출물 버전·관리자 정책·최종 원자 저장 검증은 유지한다.
- AI 응답 ID와 접수 시도 여부를 payload에 저장한다. 사용량 추적 키는 작업의 고정 키를 사용한다. 재시작하면 만료된 lease를 획득하여 기존 AI 응답을 조회하고 유료 생성을 재요청하지 않는다. 접수 여부가 불확실하고 응답 ID를 복구할 수 없으면 자동 재생성을 막는다.
- 중지 시 실제 AI 응답 상태와 취소를 확인한다. 취소 확인에 실패하면 stop_requested를 유지하여 재시도한다. 권한 상실·처리 실패 시에도 진행 중인 외부 응답을 정리한다.
- 생성 모달은 열려 있는 진행 작업만 3초 간격으로 조회한다. 종료/중복 검토 상태에서는 주기 조회를 멈추고, 모달을 다시 열면 서버의 본인 최신 작업을 확인한다. sessionStorage가 없어도 복구한다. 완료 시 관련 산출물/프로젝트/대시보드 캐시를 무효화한다.
- 사용자 요청으로 복원한 개요 페이지와 사용자가 주석 처리한 guard.inspect 부분은 변경하지 않았다.

## 실행 및 배포

- Node.js 24 이상 필요. 의존성 추가 없음. 네이티브 TypeScript 로더를 사용하므로 운영 작업자에 TypeScript 개발 의존성을 설치할 필요가 없다.
- pnpm dev / pnpm start는 웹과 독립 작업자를 함께 실행하며, 웹이 실행되는 동안 비정상 종료한 작업자를 재시작한다. 현재 실행 중인 기존 dev 서버는 재시작해야 이 실행 구성이 적용된다.
- 작업자만 별도로 실행: pnpm worker:deliverables. 동시 처리 기본 2개, DELIVERABLE_WORKER_CONCURRENCY로 1~8개 지정 가능. 웹과 동일한 DB/R2/AI 환경 구성을 사용한다. 환경 값은 기록하지 않는다.
- 서버리스 웹 배포에서는 별도의 상시 실행 Node 작업자가 필요하다. 웹의 after 훅이나 브라우저 연결 수명에 의존하지 않는다.
- OpenAI store:false를 유지한다. [공식 Background mode 문서](https://developers.openai.com/api/docs/guides/background)에 따르면 이 경우 응답은 임시 조회 기간 이후 삭제될 수 있다. 장기 작업자 중단으로 응답이 만료되면 복구 실패를 표시하며 자동 재과금하지 않는다. 앱의 전체 대기 제한을 제거해도 제공자 처리/출력/보관 한도는 유지된다.
- 이전 failed/cancelled 요청을 자동 재실행하지 않는다. 새 요청을 등록해야 한다. 관리자 변경 건수 제한도 그대로 적용한다.

## 변경 파일

- lib/auth.ts: 원래 workspace의 사용자 조회.
- lib/ai-server.ts, lib/ai/background-response.ts: 작업자 전용 무제한 대기, 응답 ID 기록/조회, 상태 조회 재시도.
- lib/ai/deliverable-generation.ts, lib/ai/deliverable-worker.ts: 영속 대기열 처리, 선택 저장, 잠금 갱신, 복구·취소.
- app/api/projects/[projectId]/deliverable-generations/route.ts 및 [requestId]/continue/route.ts: 접수와 실행 분리, 최신 작업 조회.
- components/shared/deliverable-generation-dialog.tsx: 진행 조회와 재진입 복구.
- scripts/deliverable-worker-loader.mjs, deliverable-worker.mjs, run-with-deliverable-worker.mjs: 작업자 런타임과 실행 관리.
- scripts/test-deliverable-generation.mjs, test-deliverable-background.mjs, test-artifact-detail-navigation-browser.mjs: 회귀 검증.
- package.json, README.md, AGENTS.md, CLAUDE.md, WORK_HISTORY.md 및 이 기록.

## DB 변경 여부

스키마 변경과 새 마이그레이션 없음. 기존 project_deliverable_generation_requests의 payload_json에 aiAttempted/aiResponseId를 저장한다. 기존 자료와 사용량 기록을 보존한다. 검증은 임시 DB와 합성 AI 응답으로 실행한다.

- test:deliverable-generation: 통과. 기존 생성·원자 저장 회귀, 요청 등록 시 AI 미호출, 다중 작업자 중복 방지, 20초 경과 후 lease 갱신, 만료 lease 복구, 응답 ID 재사용, 중지와 접수 불명 자동 재생성 차단을 확인했다.
- test:deliverable-background: 통과. 가상 시간으로 120초 초과 대기, 일시적 조회 장애 재시도, 기존 응답 조회 시 POST 미호출, 일반 AI 120초 제한 유지, 제공자 취소 확인을 검증했다. 외부 AI 호출 없음.
- 독립 작업자 --check: 통과. Node 네이티브 로더 실동작 확인.
- 실제 독립 작업자 프로세스가 임시 DB의 저장 대기 작업을 완료하는 회귀도 통과했다. API 키 없이 저장 단계만 실행했다.
- 최종 프로덕션 빌드(타입 검사 포함) 통과. 기존 정적 페이지 생성 중 Request failed Error 로그가 출력되었지만 빌드는 정상 완료했다.

## 미완료 사항과 한계

- 실제 사용자 문서를 이용한 유료 AI 호출은 실행하지 않는다. 제공자 보관 만료와 접수 직후 응답 ID 저장 전 프로세스 종료는 자동 복구가 제한된다.
- 웹과 작업자는 @next/env를 통해 동일한 환경 파일 우선순위를 사용하며 테스트의 외부 서비스 환경 변수는 합성 값으로 덮어쓴다.
- 원본 추출은 작업 등록 HTTP에서 수행한다. 장시간 AI 실행만 작업자로 분리했다.
