# AI 도구 실행 단계 조율 및 DB 테이블 일괄 등록 개선

- 작성일: 2026-11-05 (Asia/Seoul)
- 상태: 구현 및 검증 완료.

## 주요 변경사항

- `maxChanges`는 변경 산출물 수로 유지하고 `maxToolRounds`를 별도로 도입했다. 기본 12회, 관리자 설정 범위 2~40회이며 최종 설명까지 포함한다. 기존 정책 JSON은 새 항목이 없어도 기본값을 사용한다. 기존 변경 건수 설정은 보존한다.
- 관리자 가드레일 화면에 실행 단계 설정을 추가했다. 기존 정책처럼 초안 저장 후 적용해야 새 요청에 반영된다. 마지막 왕복은 `tool_choice=none`으로 최종 설명을 요청하고 매 단계 남은 실행 예산을 제공한다.
- 같은 도구 오류 또는 변경 없는 동일 조회가 3회 반복되면 중단한다. 마지막 오류·미저장 여부를 안내하고, 정상 답변으로 종료하는 경우에도 해결되지 않은 도구 오류는 서버 안내에 포함한다.
- `[ai-tool]` 진단 로그에 요청 ID·단계·도구명·소요 시간·성공 여부·상태·변경안 건수만 기록한다. 도구 인자, 제안요청서, 요청/답변 원문, 비밀번호·API 키는 기록하지 않는다.
- DB 설계에 `save_database_tables`를 추가했다. 한 배치 1~100개의 신규 정의서를 검증하며 항목 수를 일반 등록과 합산해 `maxChanges`를 적용한다. 내용이 크면 AI가 5~10개씩 묶고 남은 실행 예산을 고려하도록 안내한다.
- 배치 내 고유 `clientRef`를 `reference.tableId=@clientRef`로 참조할 수 있다. 전방·순환·자기 참조 FK를 포함한 전체 그래프를 검증하고, 최종 저장 시 서버가 발급한 실제 테이블 ID로 변환한다. 컬럼 ID는 입력한 고유 ID를 보존한다. 별칭은 일반 `links`나 다른 배치의 참조로 사용하지 않는다.
- 기존 필드/컬럼/PK·UK/FK·자료형/연결 검증, 프로젝트 및 CREATE 권한, 관리번호, 변경 이력·감사 기록 함수를 재사용한다. 전체 테이블 행을 저장한 뒤 FK 링크를 기록하므로 신규 순환 참조도 처리된다. 요청 중지와 최종 권한 검증을 유지한다.
- 사전 검증은 롤백 전용 트랜잭션이다. 실패한 배치는 변경안에 추가하지 않는다. 최종적으로 모든 성공 변경안·대화·이미지를 기존 하나의 트랜잭션에서 저장한다. 최종 저장 중 실패·중지 시 전체 요청을 롤백한다.
- `pendingCount`, `remainingChanges`, `pendingChanges`를 제공해 아직 저장되지 않은 테이블을 재조회·재등록하는 반복을 줄였다.

## DB 변경 여부

- 스키마 변경·마이그레이션·운영 데이터 직접 변경 없음. 정책의 기존 JSON 저장 구조를 사용하며 새 항목은 조회/검증 시 기본값을 병합한다.
- 검증에서만 별도 임시 DB에 합성 정책·테이블을 생성했다.

## 검증 결과

- 변경 파일 ESLint 및 프로덕션 빌드(타입 검사 포함): 최종 변경까지 통과. 빌드의 정적 페이지 생성 과정에는 기존 `Request failed Error` 로그가 있으나 종료 코드는 0이다. 변경 범위 `git diff --check`도 통과했다.
- `pnpm test:ai-tool-execution`: 통과. 정책 기본값·경계값, 6회 초과 정상 실행, 최종 답변 전용 단계, 반복 조회/오류, 시간 제한, 100개 테이블 사전 검증/저장, 전방·순환·자기 참조 FK, 배치 오류/중지 롤백, 변경 건수·권한·명시적 등록 의도를 확인했다.
- 실제 채팅 route·정책 로딩·가드레일·토큰 추적·최종 트랜잭션 경로에서 조회 → 100개 일괄 등록 → 최종 설명의 AI 3회 왕복을 검증했다. 합성 모델 응답 기준 약 1.1초로 완료하고 산출물 100건과 대화 저장을 확인했다. 실제 모델 생성 속도·정확도를 의미하지 않는다.
- 전체 프로젝트 탭 RFP 컨텍스트 회귀 및 기존 0~100건 변경 한도 회귀: 통과.
- 기존 HTTP AI 전체 회귀 `node scripts/test-ai.mjs`: 전체 통과. 실제 CRUD·동시 버전·권한·범위·이력·대화방·이미지·토큰·중지·첨부·가드레일·원자 롤백을 확인했다.
- 별도 정책의 실행 단계 20회가 실제 채팅 요청에 전달되는지 확인했다. 운영 정책·데이터는 변경하지 않았다.

## 제한 및 미완료 사항

- 기존 생성 흐름과 취소 기능을 유지한다. 도구 왕복 전체 120초, 요청 전체 140초 기한을 늘리지 않았다. 100건은 허용 상한이며 모든 모델·문서 크기에서 완료를 보장하지 않는다.
- 현재 모의 공급자 기준 100건 저장 경로가 시간 내 통과하므로 별도 장기 작업 큐는 도입하지 않았다. 실제 모델·대형 문서에서 시간 제한에 반복 도달한다면 영속 작업 큐와 진행/재개 UI를 별도 설계해야 한다. 기존 외부 모델 백그라운드 응답/중지는 유지한다.
- 일괄 도구는 DB 정의서 신규 등록에 한정한다. 다른 산출물과 수정·삭제는 기존 도구를 사용한다.
- 구현 범위 내 미완료 사항 없음. 기존 다른 수정사항은 보존했다. 실제 모델의 대형 문서 생성 성능과 별도 장기 작업 큐는 위 제한에 따른 후속 범위다.
