# Matrix 플래닝보드

화면설계서의 `/planning-board?projectId=...&screenId=...` 링크에서 새 창으로 엽니다. 편집기 및 미리보기, 템플릿, 서버 서비스는 이 폴더에서 관리하며 API 진입점은 `app/api/planning/`에 둡니다.

- `components/`: 원본 편집기·캔버스·레이어·속성·아이콘·협업·공통 모달 UI
- `stores/editor-provider.tsx`: 창별 Zustand 편집 상태와 서버 권한 갱신
- `lib/server/`: 범위별 인증·권한, 유효성 검사, 원자적 저장·검토·AI, 비공개 자산
- `app/api/planning/[...path]/route.ts`: 설계서의 `/api/planning/projects/{projectId}/screens/{screenId}/...` 경로를 한 Route Handler에서 분배
- `preview/`: 저장본 조회 및 원본 창·동일 출처·nonce가 일치하는 미저장 스냅샷 미리보기
- `data/templates/`, `styles/`, `types/`: 기능 전용 자원

Firebase·SSO 데이터는 자동 이전하지 않습니다. 기존 화면의 필드·관리번호·상태·연결은 유지하며 보드 본문 저장은 화면 버전과 경량 참조만 함께 갱신합니다. 보드의 검토 상태는 Matrix 화면 상태와 별도입니다.

API 진입점은 `app/api/planning/[...path]/route.ts`이며 서버 서비스는 이 기능의 `lib/server/`에 둡니다. 독립 창과 미리보기는 서버 layout에서 Matrix 세션을 확인하고 공통 `useWorkspace.user: User | null`을 초기화합니다. AI 정책·화면 권한·구성원은 `usePlanningAccess`로 별도 관리합니다. 권한 갱신 실패 시 편집 상태를 보존하고 화면과 요청을 차단하며 재확인을 제공합니다. 기존 문서의 이미지 URL은 조회·저장 입력에서 새 API 주소로 정규화하므로 DB 일괄 변환은 필요하지 않습니다.

검증: `pnpm test:planning-board`, 빌드 후 `pnpm test:planning-board-browser`. 두 검증은 임시 DB 및 외부 서비스 대역을 사용하며 유료 AI 호출을 하지 않습니다.

`styles/dark-theme.css`는 Matrix 테마 토큰으로 헤더·좌우 패널·캔버스 도구/격자·팝오버·미리보기 UI의 다크 스타일을 공통 관리합니다. 라이트 스타일은 기존 `editor.css`를 유지하며, 설계 문서의 페이지·요소·이미지·메모 배경색을 자동으로 반전하거나 저장하지 않습니다.

선택 도구에서 페이지 빈 배경을 드래그하면 한 페이지의 보이는 요소를 교차 기준으로 다중 선택합니다. Shift 드래그는 기존 선택에 추가합니다. 선택된 요소 중앙은 이동, 상·하·좌·우 경계는 한 축 크기 조절, 모서리는 두 축 크기 조절입니다. 캔버스에 포커스가 있을 때 방향키로 문서 좌표 1px씩 이동하며, 입력란에서는 커서 이동을 유지합니다. 여러 요소는 함께 이동하고 그룹 크기 조절은 제공하지 않습니다. 페이지는 선택 후 제목 라벨로 이동합니다.

텍스트 콘텐츠의 개행과 공백을 보존하고 가로 좌/중/우·세로 상/중/하 정렬 및 배경색/투명을 지원합니다. `LayerStyle.verticalAlign`은 선택 필드이며 이전 문서는 중앙 정렬로 표시합니다. 기존 JSON 스키마 버전 1과 테이블을 유지하고 새 필드는 문서 및 변경 이력에 저장합니다. 긴 텍스트는 지정한 박스 안에서 잘리므로 높이를 조절합니다. 코드 내보내기는 콘텐츠 공백을 보존하며 마크업의 한 줄 복사는 제한합니다.

메모 옆 이모티콘 버튼에서 번호/표정/손동작/기호/업무 탭을 열 수 있습니다. 번호 1~30은 빨간 배경·흰 숫자의 32×32 원형 프리셋입니다. 이모티콘과 번호는 활성 페이지에 기존 text 요소로 추가되고 일반 요소처럼 수정·저장·실행 취소할 수 있습니다. OS별 기본 이모티콘의 그림 모양은 다를 수 있습니다. 현재 `data/screens/`의 문서 JSON 템플릿과 기존 AI pages 형식 모두 불러올 수 있습니다.

프로젝트 owner는 좌측 `…` → `템플릿 생성`에서 현재 보드 전체(미저장 편집 포함)를 프로젝트 템플릿으로 저장할 수 있습니다. 계정 역할 master만으로는 생성 권한이 부여되지 않습니다. 헤더 목록은 기본 템플릿과 현재 프로젝트의 커스텀 템플릿을 구분합니다. 프로젝트 화면 READ 구성원은 목록을 보고, UPDATE 구성원은 검토 중이 아닌 화면에 적용할 수 있습니다. 다른 프로젝트의 템플릿은 조회/적용할 수 없습니다.

`033_planning_project_templates.sql`은 프로젝트 템플릿과 전용 이미지 테이블을 추가합니다. 원본 이미지는 템플릿 자산으로 독립 보관하고 적용 시 대상 화면의 pending 이미지로 복제합니다. 원본 화면 삭제로 템플릿이 깨지지 않으며, 적용 자체는 보드 저장을 하지 않습니다. 이름은 프로젝트 안에서 NFC/trim/대소문자 정규화 후 중복을 막습니다. 프로젝트당 최대 100개, 템플릿당 이미지 최대 50개(각 8MiB), 문서 5MiB의 한도를 사용합니다. 실패한 pending 템플릿은 다음 생성에서 만료 정리를 재시도합니다.

다중 선택 내부를 우클릭하면 선택 집합을 유지하고 선택 개수 아래 삭제만 표시합니다. 선택 밖의 요소는 단일 선택 메뉴를 엽니다. 캔버스/트리 focus에서 Delete도 같은 일괄 삭제를 실행하며 입력란/IME/모달에서는 실행하지 않습니다. 잠금 자손이나 마지막 페이지가 포함되면 전체 작업을 차단하고, 삭제는 자손의 모든 속성 map까지 한 번에 정리해 Undo 한 번으로 복구합니다. 이미지 바이너리는 이력 복원을 위해 즉시 삭제하지 않습니다. 여러 개 선택한 디자인 패널은 안내 문구만 표시하고 코드 탭은 유지합니다.
