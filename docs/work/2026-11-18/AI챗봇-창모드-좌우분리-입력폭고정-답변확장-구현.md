# AI 챗봇 창 모드 좌우 분리 입력 폭 고정·답변 확장 구현

- 작성일: 2026-11-18 (한국시간, Asia/Seoul)
- 기준: [최신 설계 문서](../../history/2026-11-18/AI챗봇-창모드-좌우분리-입력폭고정-답변확장-설계.md)를 다시 읽고 D1~D6의 권장안을 적용했다. 문서 작성 단계의 구현 금지는 이번 구현 요청으로 전환했다.
- 상태: 구현 및 관련 검증 완료.

## 주요 변경사항

- 팝업 좌우 분리에서 오른쪽 질문 입력 카드 전체 폭을 386px로 고정하고 왼쪽 질문·답변 영역에 창 너비 증감분 전체를 배분한다. 마우스·키보드·터치·프리셋·viewport 변화에 동일한 정책을 적용한다.
- 내부 콘텐츠 638px 이상에서 입력 386px·간격 12px·답변 최소 240px로 표시한다. 더 좁으면 상하 배치로 전환하고, 넓혀지면 좌우로 복귀한다. 패널의 기존 560px 경계와 입력 우선 배분은 유지한다.
- 기존 팝업 입력 열 보너스 계산을 제거했다. 외부 창 프리셋·수동 너비 슬롯·최소 360px·화면 12px 여백·이동·높이·capture 종료 동작은 보존했다.
- CSS만으로 배치를 변경해 새로운 React 상태·측정 훅·API·저장소를 추가하지 않았다. 같은 채팅 DOM·초안·첨부·모델·대상과 독립 스크롤을 유지한다.
- README·유지보수 안내의 기존 입력 열 배분 설명을 패널과 팝업으로 구분해 갱신했다. 설계 문서와 과거 작업 기록은 수정하지 않았다.

## 변경 파일

- `styles/ai-workspace-layout.css`: 팝업 고정 입력 열과 638px 쿼리, 패널 560px 규칙의 적용 범위 분리.
- `scripts/check-ai-window-browser.mjs`: 팝업 답변 확장·패널 입력 확장 기대값, 모드별 콘텐츠 경계 검증.
- `scripts/check-ai-window-resize-browser.mjs`: 실제 카드·대화 pane 폭 측정, 양쪽 크기 조절·키보드·터치의 입력 고정과 답변 증감, 새 경계 검증.
- `README.md`, `AGENTS.md`, `CLAUDE.md`, `components/ai/README.md`: 사용자 안내·수치·유지보수 정책 갱신.
- `WORK_HISTORY.md`: 본 작업 기록의 상대 링크와 작성일 추가.

## DB 변경 여부

없음. DB 스키마·마이그레이션·운영 데이터·API를 변경하지 않았다. AI 대상 브라우저 검증만 기존 fixture의 합성 계정·임시 SQLite·모의 AI를 사용한다. 공유 답변 브라우저 검증은 DB·실제 AI 없이 모의 응답을 사용한다.

- `pnpm build`: 통과. 컴파일·TypeScript·정적 페이지 생성 완료. 정적 페이지 생성 중 기존 `Request failed Error` 메시지가 있었으나 전체 빌드는 정상 종료했다.
- 변경한 검증 스크립트 ESLint·`node --check`: 통과. CSS·스크립트 Prettier 정렬 완료.
- `pnpm test:ai-targets-browser`: 최초 실행 통과. 실제 860→1000→1100px 확대와 역방향 축소, 왼쪽 핸들, 키보드 조절에서 입력 386px 고정·답변 증감 전체 반영을 확인했다. DOM·초안·첨부·모델·대상 보존, 크기 조절 중 추가 AI/access 요청 없음도 통과했다.
- 같은 실행에서 팝업 콘텐츠 559/560/561px 상하 표시와 637/638/639px 경계, 패널 559/560/561px 경계, 외부 460/560/860px 프리셋, viewport 제한·수동 너비 복원·footer·독립 스크롤·어두운 테마·낮은 높이와 기존 AI 대상 회귀를 통과했다.

- `pnpm test:shared-answers-browser`: 통과. 등록 확인·멱등성·승인 버전·원문 미리보기·오래된 근거 캐시 차단·새 답변 생성 전환을 확인했다.

- 전체 `git diff --check`는 기존 `PROMPT.md`의 trailing whitespace를 보고했다. 이 파일은 이번 작업에서 수정하지 않았다. 이번 변경 파일의 `git diff --check`, 신규 파일 공백 검사, 작업 문서·README·AGENTS·CLAUDE·WORK_HISTORY의 새 링크와 날짜 검증은 통과했다.
