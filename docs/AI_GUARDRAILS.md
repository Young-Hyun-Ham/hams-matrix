# AI 가드레일 운영

## 관리자 화면

사이드바의 **AI 가드레일 관리** 또는 `/admin/ai-guardrails`에서 관리합니다. 현재 로그인 워크스페이스의 `owner/admin`만 화면과 API를 사용할 수 있습니다. 가입 유형인 `accountRole=owner`를 서비스 전체 관리자 권한으로 사용하지 않습니다.

`pnpm db:migrate`로 `017_ai_guardrails.sql`까지 적용한 뒤 서버를 재시작합니다. 현재 적용 대상은 **AI Chatbot**입니다. 아키텍처/WBS 이미지 생성 API는 별도 경로이며 이 설정의 적용 대상이 아닙니다.

1. 정책을 수정하고 **초안 저장**을 누릅니다. 현재 적용 정책은 바뀌지 않습니다.
2. **정책 테스트**에서 정상 요청과 공격 예문을 검사합니다. 현재 편집 중인 초안을 사용하며 문서를 변경하지 않습니다. 파일 선택 또는 테스트 내용 입력창의 Ctrl/⌘+V로 이미지를 첨부할 수 있습니다. 텍스트 없이 첨부만으로도 검사할 수 있습니다.
3. **저장한 초안 적용**으로 새 버전을 활성화합니다.
4. 이전 설정은 적용 이력에서 **새 버전으로 복원**할 수 있습니다. 기존 적용 버전은 수정·삭제하지 않습니다.

다른 관리자가 초안이나 활성 버전을 변경하면 409로 저장을 거부합니다. 변경 내용을 확인한 뒤 새로고침합니다. 한 요청에서는 시작 시 확정한 정책 버전을 사용합니다. AI 사용 허용 해제는 새 정책을 적용한 후 진행 중 요청의 다음 체크포인트에도 반영됩니다.

## 기본값과 적용 범위

- 기본 정책은 차단 모드, 입력/참고 자료/출력 검사 활성화, 등록·수정·삭제 최대 3건입니다.
- 규칙 검사는 지시 탈취·정보 유출 유도, API 키/개인 키/주민등록번호 패턴, 사용자 지정 차단 문구, 설정한 외부 링크 제한을 확인합니다. 전체 개인정보 탐지나 모든 프롬프트 인젝션 차단을 보장하지 않습니다.
- 감시 모드는 선택 검사에서 탐지한 위험을 기록하고 통과시킵니다. 인증·워크스페이스/프로젝트 격리·도구 스키마·실제 서버 비밀정보·위험한 활성 마크업·검사 크기 제한·필수 검사 실패는 감시 모드에서도 우회하지 않습니다.
- 명확한 직접 지시 탈취와 고위험 규칙은 차단 모드에서 막습니다. 문서 속 의심 문구 등 중간 위험은 기록합니다. 인젝션 분석이나 교육 자료도 정상 사용일 수 있으므로 실제 업무 예문을 함께 테스트합니다.
- 임의 정규식이나 관리자 작성 시스템 프롬프트를 실행하지 않습니다. 차단 문구는 문자열 비교, 허용 도메인은 정확한 호스트명 비교입니다. 하위 도메인은 각각 등록합니다.

## AI 분류와 이미지

정책 테스트는 PNG/JPEG/WebP 이미지, UTF-8 TXT/MD/Markdown/CSV/JSON/LOG/YAML/YML/XML, PDF, Word DOCX 첨부를 지원합니다. 이미지는 최대 3장·PNG 변환 후 장당 2MiB·각 변 4096px입니다. 문서는 최대 3개·개당 4MiB·합계 8MiB이며 서버에서 본문을 추출합니다. 파일 선택과 클립보드 이미지는 동일한 이미지 검증 경로를 사용합니다. 첨부 목록에서 미리보기·삭제가 가능합니다.

PDF는 최대 50페이지, 파일당 추출 본문은 최대 100,000자입니다. DOCX의 본문·머리말·꼬리말·각주·미주·주석 텍스트를 읽으며 DTD나 외부 파일을 불러오지 않습니다. PDF 텍스트 레이어와 DOCX의 추출 텍스트만 검사하므로 문서 내 삽입 이미지·개체·매크로 검사나 OCR을 수행한 것으로 간주하지 않습니다. 텍스트가 없는 스캔 PDF, 손상·암호화 파일, 지원하지 않는 형식은 통과시키지 않고 안내합니다. 구형 `.doc` 파일은 DOCX로 변환해 첨부합니다.

테스트 결과에는 이미지·문서 수, 추출 문자 수, 이미지 내용 검사 여부를 표시합니다. 조회 전용 정책에서 AI 검사를 실행하지 않은 이미지는 **내용 미검사**로 표시하며 DB 변경 제한과 구분합니다. 선택한 검사 단계에서 텍스트/이미지와 문서 본문을 검사해 가장 엄격한 판정을 반환합니다. 첨부 원본·추출 본문은 정책 테스트의 DB 로그에 저장하지 않으며 결과에도 본문을 반환하지 않습니다.

AI 분류는 기본 비활성입니다. 활성화할 때 사용 가능한 모델을 선택하고 정책 테스트를 실행합니다. 분류기는 업무 도구 없이 고정 지시와 JSON Schema를 사용하며, 응답을 서버에서 다시 검증합니다. 잘못된 JSON·API 장애·시간 초과는 검사를 건너뛰지 않고 차단합니다. 탐지 점수는 보정된 확률이 아닙니다.

기본 이미지 정책은 **조회 전용**입니다. 현재 첨부뿐 아니라 이전 대화에 전달되는 이미지가 있으면 변경 도구를 제공하지 않습니다. 이미지 자체를 검사 완료했다고 처리하지 않습니다. **첨부 차단**은 이전 이미지도 차단하며, **AI 검사 후 허용**은 이미지 지원 분류 모델이 필요합니다. 이 모드의 이미지 검사는 일반 입력/참고 자료 검사 토글을 꺼도 생략하지 않습니다. 지원하지 않는 모델이면 실패 시 차단합니다. 한 검사에 최대 12장, 데이터 URL 합계 12MiB를 넘으면 차단합니다.

입력, 이전 대화, 프로젝트 자료, 조회 도구 결과, 도구 인자, 최종 답변을 각각 검사합니다. 검사 데이터는 지시가 아닌 신뢰하지 않는 자료로 전달합니다. 모델 분류도 완벽하지 않으므로 최종 권한·스키마 검사와 함께 사용합니다.

## 변경안 저장과 중지

`save_artifact`는 실제 검증 경로를 짧은 트랜잭션으로 실행하고 롤백해 변경안을 확인합니다. AI 대기 중에는 트랜잭션을 유지하지 않으며, 임시 변경안은 모델에 `pending=true`로 전달합니다. 임시 ID나 관리번호는 후속 변경의 대상으로 제공하지 않습니다. 같은 항목의 여러 단계 변경은 버전 충돌로 거부될 수 있으므로 한 번의 수정으로 요청합니다.

최종 출력이 검사를 통과하면 권한·현재 버전을 다시 확인한 뒤 **모든 변경안·대화·첨부를 한 트랜잭션으로 저장**합니다. 중지·출력 차단·버전 충돌·대화 저장 오류가 발생하면 아직 확정하지 않은 변경은 전부 폐기합니다. 실제 관리번호와 저장 결과는 서버가 답변에 추가합니다. 전체 생성·검사는 140초의 공통 기한을 사용하고, 각 AI 호출은 최대 120초입니다. 원격 취소 확인 지연은 별도입니다.

## 로그와 사용량

- `ai_guardrail_configs`: 워크스페이스별 초안과 활성 버전 포인터
- `ai_guardrail_policies`: 변경 불가능한 적용 버전, 적용 관리자·시간·복원 원본
- `ai_guardrail_events`: 요청 ID, 사용자·워크스페이스, 정책 버전, 검사 단계, 판정, 규칙 ID, 소요 시간. 원문 요청·이미지·답변과 모델의 자유 서술 사유는 복제하지 않습니다. 일반 DB 감사 로그 비활성 여부와 관계없이 기록합니다. 관리자 화면은 최근 100건을 표시합니다.
- `ai_generation_requests.guardrail_version`: 생성 요청이 사용한 정책 버전
- `ai_token_usage.purpose`: `generation`은 업무 생성, `guardrail`은 AI 분류 검사. 같은 요청 ID로 합산할 수 있으며 호출 순번 1000 이상은 분류 검사입니다. 차단되거나 중지되어도 이미 발생한 사용량을 보존합니다. 계정 사용량 통계는 검사 토큰을 전체 합계의 일부로 별도 표시합니다. 미확인 사용량은 추정하지 않습니다.

## 검증

`pnpm build`, `pnpm typecheck`, `pnpm test:ai`를 사용합니다. 통합 테스트는 임시 SQLite DB와 모의 OpenAI를 사용하므로 실제 유료 호출은 하지 않습니다. 관리자/워크스페이스 격리, 정책 초안·적용·복원·경합, 입력/간접/출력 차단, 민감정보 기본 보호, 분류 장애, 검사 토큰, 검사 중 취소, 출력 차단과 대화 저장 실패 시 원자적 롤백을 검사합니다. 첨부 테스트는 실제 PDF/DOCX 파서로 본문·머리말 추출, 이미지 전달, 혼합 첨부 판정, 제한과 손상 파일을 확인합니다. 실제 모델의 탐지 품질은 운영 업무 예문과 별도의 공격 평가로 확인해야 합니다.

참고: [OWASP 가이드](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html), [OpenAI 에이전트 안전](https://developers.openai.com/api/docs/guides/agent-builder-safety), [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs).

### 검사 구현과 범위

`lib/ai/global-compliance.ts`는 워크스페이스 정책과 분리한 서버 규칙 모듈이다. AI Chatbot의 입력·참고 자료·도구 결과·출력 검사와 관리자 정책 테스트가 공유하는 `createGuardrailSession.inspect`에서 실행한다. 다음 탐지는 `critical`로 판정하므로 정책이 감시 모드여도 차단한다.

- `global_human_review_required`: 채용·대출·보험·의료 등 중대한 결정, 사람의 검토·승인 배제, AI의 최종 자동결정 표현이 동시에 명시된 텍스트.
- `global_untrusted_boundary`: 참고 자료 또는 도구 결과가 시스템·개발자 지시나 보안 정책을 무시·우회·비활성화하라고 명시한 텍스트.

관리자 설정의 **글로벌 규제 준수** 탭에서 기준과 통제를 확인한다. 샘플 버튼은 정책 테스트 탭에 검사 단계와 예문을 채운다. **검사 실행**을 누르면 편집 중인 초안을 사용해 서버 판정을 확인할 수 있다. 실제 AI 사용에는 활성 정책을 사용하며, 글로벌 규칙은 정책 토글과 별도로 적용된다. 판정은 기존 `ai_guardrail_events`에 규칙 ID만 기록하며 원문은 보관하지 않는다. DB 스키마 변경은 없다.

문자열 패턴은 명시적 위험 요청만 다루므로 간접 표현·이미지 속 지시·맥락별 법 적용 여부를 완전히 판단하지 못한다. 법적 분류, 사람의 승인·이의제기 절차, RACI 책임자 지정, 중지 운영, 정기 평가와 감사 보존 정책은 조직 운영 절차에서 검토해야 한다. 규칙 변경 시 이 문서와 샘플 예문·회귀 검사를 함께 수정한다.
