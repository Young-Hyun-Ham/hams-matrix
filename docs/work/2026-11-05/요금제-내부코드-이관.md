# 요금제 내부 코드 Pro·Team 이관

- 작성일: 2026-11-05 (한국시간, Asia/Seoul)
- 요청: 표시명뿐 아니라 실제 `plans.code`도 `free / pro / team / business`로 변경하고 정상 동작하도록 이관한다.
- 상태: 소스 변경·연결 DB 이관 및 관련 검증 완료.
- 이번 요청은 [이전 구현](요금제-명칭변경-팀공유-옵션-구현.md)의 내부 코드 유지 결정을 대체한다. 이전 기록·설계 문서는 당시 결정의 이력으로 보존한다.

## 주요 변경사항

| 기존 코드 | 최종 코드 | 상품 |
| --- | --- | --- |
| `free` | `free` | Free |
| `plus` | `pro` | Pro, 기존 Plus 상품 |
| `pro` | `team` | Team, 기존 Pro 상품 |
| `business` | `business` | Business |

- `PlanCode`, 요금제 정렬, 본인 구독 변경 및 관리자 회원/요금제 API의 코드 검증을 새 코드로 통일했다. UI는 카탈로그의 코드/표시명을 사용하므로 새 값을 전달한다.
- 기존 `pro`와 새 `pro`가 충돌하지 않도록 `plans`와 `user_subscriptions`를 새 테이블에 원본 코드 기준으로 복사하고 한 트랜잭션에서 교체하는 `035`를 추가했다. 외래키를 끄지 않고 적용 가능한 구조이며, CHECK·외래키·구독 인덱스·가입 시 Free 구독 생성 트리거를 복원한다.
- 가격·할인·프로젝트/토큰/이미지/첨부 한도·추천·이력·팀공유 옵션·수정자를 상품별로 보존한다. 구독은 코드만 대응 상품으로 옮기며 청구 주기·수정자·수정 시각을 유지한다.
- 모든 요금제 버전이 이관 전 최대 버전보다 커지도록 갱신한다. 모든 회원의 `management_version`도 1 올려 이관 전에 열린 관리자 화면의 오래된 코드 선택을 거부한다. 구버전 `pro`를 새 상품으로 무조건 해석하는 호환 alias는 추가하지 않는다.
- 과거 로그 JSON·로그 자원 코드·사용량 예약의 정책 버전은 원본을 보존한다. 레거시 워크스페이스의 `plan`/`subscription_plan`은 회원 구독과 다른 모델이므로 수정하지 않는다. 세션도 삭제하지 않는다.
- 기존 회귀 테스트의 활성 구독 fixture를 새 코드로 변경하고, 이관 직전 fixture는 옛 코드를 유지해 실제 업그레이드를 검증한다. `plus` 아이콘 등 상품과 무관한 문자열은 그대로 둔다.

## DB 변경 여부

**연결된 DB에 `035_plan_codes_pro_team.sql` 적용 및 `schema_migrations` 등록 완료.**

- 적용 전에 실제 테이블·트리거·인덱스·외래키 참조와 034 적용 여부를 확인했다.
- 쓰기 트랜잭션 안에서 이관하고, 각 상품의 기존 설정 전체 및 모든 구독 행의 원본→새 코드 매핑을 비교한 뒤 커밋했다. 구독의 청구/수정 메타데이터, 회원 버전, 이력·예약 건수와 외래키도 확인했다.
- 커밋 후 새 연결로 코드/명칭 4개, 남은 `plus` 구독 0건, 외래키 위반 0건, 035 적용 이력을 재확인했다.
- 기존 미적용 `023_toast_colors.sql`은 실행하거나 이력을 변경하지 않았다. 이번에는 035만 적용했다.
- 비밀번호·API 키·토큰·DB 접속 정보는 이 기록에 포함하지 않는다.

## 미완료 사항 및 사용 안내

- 요청 범위의 미완료 사항은 없다.
- 열린 요금제·관리자 화면은 새로고침 후 이용한다. 오래된 화면에서 전송한 요청은 400/409로 거부될 수 있으며, 새 코드로 정보를 다시 조회해야 한다.
- 별도 환경은 034 다음에 035를 적용한 뒤 새 애플리케이션을 실행한다. 실제 서비스 프로세스 재시작·외부 배포는 이번 작업에서 수행하지 않았다.
