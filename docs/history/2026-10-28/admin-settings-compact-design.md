# 관리자설정 화면 밀도·탭·상세 모달 개선 분석 및 설계

- 작성일: 2026-10-28 (Asia/Seoul)
- 상태: 검토용 설계. 이번 단계에서는 본 문서와 `HISTORY.md`만 변경한다. 소스·설정·테스트 코드·DB·마이그레이션은 변경하지 않는다.
- 분석 기준: 현재 관리자 페이지, 공통 설정 탭, 회원/이력 상세, 가드레일/플랜 컴포넌트와 공통/테마 CSS를 다시 읽고 첨부 이미지 3개와 비교했다. 실제 브라우저의 computed style 측정은 하지 않았으며 CSS 충돌 원인은 소스 분석에 근거한다.
- 관련 문서: [좌측 메뉴·개인 설정·관리자설정 설계](navigation-settings-admin-design.md), [구현 기록](../../work/2026-10-28/navigation-settings-admin-work.md)
- 아래에서 사용자 요구와 구체적인 구현 제안을 구분한다. 수치는 검토 가능한 초안이며 최종 결정 항목은 9절에 정리한다.

## 1. 요구사항과 범위

| 번호 | 사용자 요구 | 설계 방향 |
| --- | --- | --- |
| 1 | 관리자설정 상단의 “관리자설정” 텍스트 제거, 관리자설정 전체 글자를 약 9pt로 축소, 버튼도 작게 변경 | 중복 페이지 제목 제거, 관리자 전용 글자·행간·컨트롤·여백 기준 수립 |
| 2 | 탭을 Windows 파일 탐색기 헤더 같은 느낌으로 변경하되 탐색기 색상은 적용하지 않음 | 서로 이어진 탭 스트립과 선택 탭/본문 연결 표현. 기존 보라색·라이트/다크 테마 유지 |
| 3 | 회원 상세 모달의 과도한 여백 수정, 제목 크기에 맞는 헤더와 헤더/본문 구분용 그림자 | 두 상세 모달에 공통으로 사용할 헤더/본문 컨테이너 정의 |
| 4 | 닫기 버튼을 글자 크기에 맞추고 헤더 높이 축소 | 내용 너비 버튼, 작은 padding, 전역 최소 높이 해제 |
| 5 | 기본 정보 본문과 헤더 사이에 적당한 위 여백 | 본문 래퍼의 일정한 상단 padding으로 확보 |
| 6 | 가드레일 정책 옵션의 체크박스를 앞에, 옵션 제목을 뒤에 배치 | 현재 DOM 순서를 유지하면서 CSS 충돌을 해소하고 체크박스/문구를 한 행으로 배치 |
| 7 | 이력 상세 모달도 회원 상세와 같은 디자인 적용 | 동일한 헤더·버튼·그림자·본문 padding·스크롤 규칙 사용 |

적용 범위는 `/admin/settings`의 요금제·회원 관리·AI 가드레일 관리·이력 관리와 그 안의 상세 모달이다. 가드레일 내부 정책 설정·정책 테스트·적용/검사 이력, 첨부 영역, 로딩·오류·안내, 표·검색·페이징도 관리자 화면 크기 기준에 포함한다.

일반 `/settings`, 게스트 화면, 로그인, 프로젝트 화면과 다른 공통 모달의 디자인은 유지한다. 계정 권한·가드레일 정책·플랜/회원 수정·검색/페이징·이력 반환 및 민감 필드 제외 동작도 유지한다. API와 DB 변경은 필요하지 않다.

## 2. 현재 구조와 문제 원인

### 2.1 페이지 제목과 공통 탭

- `app/(workspace)/admin/settings/page.tsx`가 `.settings-page` 안에 `관리자설정 · 현재 탭` 형태의 `h1`을 출력한다.
- `components/workspace-shell.tsx`도 상단 breadcrumb에 같은 조합의 메뉴명을 출력한다. 본문 제목만 제거하면 상단에는 여전히 “관리자설정”이 남을 수 있다.
- 요금제의 `PlanAdmin`에는 별도 `요금제 관리` 제목, 가드레일에는 `WORKSPACE SECURITY`와 28px 제목이 있어 상단 정보가 반복되고 높이를 차지한다.
- `components/settings-tabs.tsx`는 링크에 공통 `.button`/`.primary`를 사용하고 `gap:8`, `margin:20px 0`, 줄바꿈을 인라인으로 지정한다. 분리된 버튼 묶음이어서 연결된 탭 헤더처럼 보이지 않는다.
- 이 컴포넌트와 `styles/settings.css`는 일반 개인 설정과 공유한다. 공통 스타일을 일괄 축소하면 개인 설정에도 영향을 준다.

### 2.2 글자와 컨트롤 크기

| 현재 위치 | 소스의 주요 값 | 영향 |
| --- | --- | --- |
| `app/globals.css` | body 14px, `.button` 최소 높이 42px, padding 11px 17px | 본문만 작게 해도 버튼이 크게 남음 |
| 공통 `.button.small` | 최소 높이 34px, padding 7px 11px, 글자 12px | 목록 상세 버튼도 별도 조정 필요 |
| `styles/settings.css` | input/select padding 10px, 표 셀 12px 8px, 모바일 버튼 최소 높이 40px | 입력/표/모바일 영역 높이를 별도로 축소해야 함 |
| `components/admin/plan-admin.tsx` | 내부 styled-jsx: 카드 padding 22px, label margin-bottom 14px 등 | 페이지 상속만으로 간격이 줄어들지 않음 |
| `components/admin/guardrail-admin.css` | 바깥 padding 32px, 제목 28px, 요약 padding 20px, grid gap 24px, legend 18px | 가드레일에서 특히 많은 세로 공간 사용 |
| `components/admin/admin-lists.tsx` | 필터/페이징 간격과 로깅 카드 padding 등이 인라인 | CSS만으로 조절하기보다 관리자용 클래스로 이동 필요 |

9pt는 CSS 기준 12px이다. 실제 물리 크기는 디스플레이 배율·브라우저 확대에 따라 달라진다. 전역 body 크기를 바꾸지 않고 관리자 범위에 12px 기준을 적용한다.

### 2.3 회원/이력 상세 모달

두 상세는 `components/admin/admin-lists.tsx`의 동일한 `<dialog>`에서 분기한다.

- `styles/settings.css`의 `.settings-page .workspace-dialog`가 dialog 전체에 20px padding을 준다.
- `styles/dialog.css`의 `.dialog-header`가 다시 20px 24px padding을 준다. 제목과 닫기 버튼 주위에 바깥/안쪽 여백이 누적된다.
- 제목은 공통 CSS의 16px, line-height 1.6을 사용하고, 닫기 버튼은 공통 `.button`의 최소 높이 42px을 적용받는다.
- 헤더 다음에 오류/로딩, 회원 `h3`·문단·폼 또는 이력 `pre`가 바로 나온다. 전용 본문 래퍼가 없어 헤더 아래 간격과 콘텐츠 정렬을 한 곳에서 관리할 수 없다.
- 공통 헤더는 아래 border만 있고 요청한 영역 구분용 그림자가 없다.
- 현재 dialog는 `max-height:85dvh`이며 공통 너비 제한을 사용한다. 본문만 스크롤하는 구조를 명시하지 않았다.
- 이력은 이미 허용 필드만 반환한 상세 객체를 JSON 텍스트로 표시한다. 이번 변경은 표시 컨테이너 개선이며 이력 API/포맷 변경이 아니다.

### 2.4 체크박스가 문구 위에 나오는 CSS 충돌

`guardrail-admin.tsx`의 DOM은 이미 `label.guardrail-toggle > input[type=checkbox] + span(제목, 설명)` 순서다. DOM 재정렬만으로 해결할 문제가 아니다.

| 규칙 | 의도와 충돌 |
| --- | --- |
| `.guardrail-grid` | fieldset을 2열 grid로 만들려 함 |
| `.settings-page fieldset` | 더 높은 명시도로 `display:flex; flex-wrap:wrap`을 적용해 위 grid를 덮어씀 |
| `.guardrail-grid label` | label을 flex로 배치하려 함 |
| `.settings-page fieldset label` | 더 높은 명시도로 `display:grid; flex-basis:100%`를 적용함 |
| `.guardrail-grid .guardrail-toggle` | `flex-direction:row`는 지정하지만 `display:flex`를 직접 재선언하지 않음. display가 grid로 바뀌면 가로 flex 배치가 작동하지 않음 |
| `.settings-page input` | checkbox/radio도 일반 입력의 padding 대상에 포함됨 |

이 조합은 이미지의 “큰 카드 위쪽 중앙 체크박스 + 아래쪽 문구” 형태를 설명한다. 실제 구현에서는 computed style의 `display`, `grid-template-columns`, `flex-basis`, checkbox 크기를 확인해 확정한다. 같은 규칙이 가드레일의 “허용 변경 작업” 체크박스와 요금제 `.check`에도 영향을 줄 수 있어 함께 확인한다.

## 3. 관리자 전용 밀도 기준

관리자 페이지 루트에 `.admin-settings-page` 같은 전용 클래스를 추가하고 전용 스타일 파일 `styles/admin-settings.css`를 두는 안을 권장한다. 기존 `.settings-page`와의 관계를 명확히 하고 개인 설정에는 축소 규칙이 적용되지 않게 한다.

| 항목 | 제안값 | 적용 방식 |
| --- | --- | --- |
| 본문·탭·표·버튼·입력·설명·상태 메시지·JSON | 12px (약 9pt) | 제목/legend/small/pre의 별도 px 지정까지 점검 |
| 섹션/모달 제목 | 12px, font-weight 600~700 | 크기 대신 굵기와 간격으로 구분 |
| 기본 행간 | 1.4~1.5 | 긴 설명/JSON 가독성 확보 |
| 일반 버튼 | 높이 약 26px, 최소 24px, padding 4px 8px | width:auto, inline-flex, flex-shrink:0 |
| 입력/select | 높이 약 28px, padding 4px 8px | textarea는 줄 수/내용에 맞는 높이 유지 |
| 체크박스 | 14px 안팎, padding 0, flex-shrink:0 | 일반 input 축소 규칙과 분리 |
| 표 셀 | 상하 6px, 좌우 8px | 회원/이력과 가드레일 내부 표에 동일한 밀도 적용 |
| 카드/폼 | padding 10~12px, gap 8~12px | 중첩 padding 제거 |
| 섹션 간격 | 12~16px | 설명 문구의 기본 문단 margin도 정리 |
| 관리자 본문 가장자리 | 필요 시 12~16px | 전역 `.main-content`를 수정하지 않고 관리자 경로에 한정 |

제목에만 16/28px가 남거나 `small`이 지나치게 작아지는 혼합을 피한다. 글자 전체를 약 9pt로 맞추되 강조는 weight로 표현한다. 사용자 확대/축소와 포커스 표시를 막지 않는다. 높이를 고정해 긴 버튼 문구를 자르지 않는다.

모바일에서도 기존 40px 최소 높이를 그대로 두면 축소 요청이 반영되지 않으므로 관리자 범위에서 재정의한다. 터치 환경의 최소 높이를 32px로 둘지는 검토 항목으로 둔다. 표 가로 스크롤과 필터 줄바꿈은 유지한다.

### 상단 제목 처리

- 본문에 보이는 `관리자설정 · 현재 탭` 제목 행을 제거하고 탭 헤더를 본문의 첫 주요 요소로 배치한다.
- 접근성용 페이지 제목이 필요하면 화면에 공간을 차지하지 않는 숨김 제목으로 제공한다.
- 상단 breadcrumb는 관리자 경로에서 현재 탭명만 표시하는 안을 권장한다. “관리자설정” 중복 문구를 없애면서 현재 위치는 유지한다.
- 좌측 메뉴의 “관리자설정” 명칭은 진입점이므로 유지한다.
- `요금제 관리`, `AI 가드레일 관리` 같은 탭과 중복되는 내부 큰 제목은 관리자 안에서 생략/축소하되 워크스페이스명·정책 상태·새로고침과 필요한 안내는 남긴다.
- 전역 topbar 높이·검색·계정 버튼의 전면 재설계는 이번 범위에 포함하지 않는다.

## 4. 파일 탐색기 헤더 느낌의 탭 설계

탐색기의 “같은 헤더 위에 정렬된 탭, 현재 탭과 본문이 연결되는 경계”를 차용한다. 탐색기의 흰색/회색/파란색 팔레트, 리본 메뉴, 주소창, 창 제어 버튼은 도입하지 않는다.

| 요소 | 제안 |
| --- | --- |
| 탭 스트립 | 가로로 이어지는 낮은 높이의 단일 헤더, 아래쪽 공통 경계선 |
| 비선택 탭 | 기존 canvas/surface 배경, muted 글자, 가는 구분선 |
| 선택 탭 | surface 배경, ink 글자·굵기, 상단 보라색 강조 또는 얇은 보라색 경계, 하단 경계를 본문 배경과 연결 |
| 테두리 | 위 모서리만 작은 곡률 4~6px, 일반 둥근 버튼 외형 제거 |
| 탭 간격 | 0~2px, padding 약 6px 10px, 높이 약 28~30px |
| 본문 연결 | 탭 아래 내용과 공통 경계 정렬. 탭 스트립과 본문 사이 불필요한 20px margin 제거 |
| 좁은 화면 | 1줄 가로 스크롤 권장. 선택 탭이 가려지지 않게 표시. 내용 잘림/2줄 탭 섞임 방지 |

색은 기존 `--primary`, `--surface`, `--canvas`, `--line`, `--ink`, `--muted`를 사용한다. 선택 상태는 색만으로 구분하지 않고 경계·굵기·본문 연결로 함께 표현한다.

`SettingsTabs`에는 관리자용 variant를 추가하는 방식을 권장한다. `/settings`의 기본 variant는 유지하며 관리자 variant에서는 기존 인라인 margin/gap/flexWrap과 `.button.primary` 의존성을 제거한다.

관리자 최상위 탭은 URL로 이동하는 현재 링크 방식과 `aria-current`를 유지한다. 시각적으로 탭처럼 바뀌었다는 이유만으로 `role=tab`을 붙이지 않는다. 실제 tablist로 바꾸려면 방향키/선택/tabpanel 연결까지 별도 구현해야 한다. 이번에는 링크 탐색·직접 URL·새로고침·뒤로가기를 유지하는 안을 권장한다.

가드레일 내부 3개 탭은 최상위 탭과 혼동하지 않게 작은 하위 탭으로 유지한다. 높이/글자/간격은 축소하고 기존 tablist/tabpanel 동작은 보존한다.

## 5. 회원·이력 상세 공통 모달 설계

현재 동일한 dialog에서 두 내용을 분기하므로 우선 동일 DOM 골격과 클래스를 적용한다. 다른 화면까지 범위를 넓히는 전역 dialog 수정은 피한다. 재사용이 필요하면 `components/admin/admin-detail-dialog.tsx`로 추출할 수 있으나 단순 외형 수정을 위한 필수 조건은 아니다.

```text
┌──────────────────────────────────┐
│ 회원 상세 / 이력 상세       [닫기] │  작은 공통 헤더
├·········· 얕은 그림자 ···········┤
│  위 여백 12px                    │
│  기본 정보 / JSON 상세            │
│  …본문만 스크롤…                 │
└──────────────────────────────────┘
```

### 5.1 골격과 치수

| 영역 | 제안값/동작 |
| --- | --- |
| dialog 외곽 | padding 0, 기존 너비 제한을 우선 유지, 최대 높이 85dvh 이내, viewport 여백 확보 |
| 헤더 | 좌우 12px, 상하 8px, display:flex, align-items:center, gap 8px |
| 헤더 제목 | margin 0, 12px, line-height 1.4, weight 600~700 |
| 닫기 버튼 | 글자 12px, 좌우 8px/상하 3~4px, 높이 약 24~26px, width:auto, 전역 min-height 42px 해제 |
| 헤더 높이 | 대략 40~44px. 고정 height보다 제목·버튼·padding 합으로 결정 |
| 헤더/본문 구분 | 얇은 line border와 아래 방향의 작은 box-shadow, 헤더 배경은 기존 surface |
| 본문 | padding 12px, 첫 항목 margin-top 0. 헤더 이후 12px가 일관되게 확보됨 |
| 본문 스크롤 | 헤더는 남기고 body에 overflow:auto, min-height:0 적용. 그림자가 잘리지 않도록 레이어/overflow 위치 확인 |
| 본문 간격 | 문단 간 6~8px, 섹션 간 12~16px. 기본 margin에 의존하지 않음 |

그림자는 예를 들어 아래 방향 2~4px 범위의 낮은 불투명도로 시작하고 라이트/다크에서 확인한다. 강한 바깥 그림자로 헤더 자체가 크게 보이지 않게 한다. 기존 모달 외곽 그림자와 헤더/본문 구분 그림자는 별도로 다룬다.

### 5.2 회원 상세

- `기본 정보`가 헤더 바로 밑에 붙지 않도록 `.admin-detail-body`의 top padding으로 간격을 준다.
- 이름·계정·직무·가입/수정 시각의 줄 간격을 일정하게 한다. 긴 ID/이메일은 `overflow-wrap:anywhere`로 처리한다.
- 기본 정보와 `회원 플랜·역할` 사이만 의도적인 섹션 간격을 둔다.
- 플랜/역할 label과 select는 같은 12px 기준과 작은 간격을 사용한다. 읽기 전용 역할도 동일한 정렬을 사용한다.
- 저장 버튼은 왼쪽 정렬의 내용 너비로 배치한다. fieldset 전체 너비에 맞춰 버튼이 늘어나지 않게 한다.
- 기존 admin의 역할 읽기 전용, master 보호, 저장 중 비활성화, 버전 충돌·재조회 처리를 유지한다.

### 5.3 이력 상세

- 회원 상세와 동일한 헤더·닫기 버튼·그림자·본문 padding을 사용한다.
- JSON은 현재의 텍스트 `pre` 표현을 유지한다. `font-size:12px`, line-height 약 1.45, margin 0으로 맞춘다.
- `white-space:pre-wrap`, 긴 ID/경로의 줄바꿈을 유지한다. 큰 JSON은 모달 본문 안에서 스크롤하며 헤더가 사라지지 않게 한다.
- 상세 정보의 한글 표/트리 변환, 필드 추가, JSON 문법 강조는 별도 요청이 없어 추가하지 않는다.
- 로딩·오류·재조회 버튼도 같은 본문 래퍼 안에 넣어 정상/실패 상태에 따라 여백이 바뀌지 않게 한다.
- Escape 닫기·네이티브 dialog 포커스 제한·닫은 뒤 원래 버튼 포커스 복귀·목록 상태 보존을 유지한다.

## 6. 가드레일 체크박스 배치 개선

목표 구조는 다음과 같다. 설명은 제목 아래에 두되 제목의 시작선에 맞춘다.

```text
[✓] AI Chatbot 사용 허용
    해제한 정책을 적용하면 진행 중 요청도 다음 검사 시 중단합니다.
```

1. DOM 순서 `input + 문구 span`과 label 전체 클릭 동작을 유지한다.
2. 관리자 안의 `fieldset.guardrail-grid`를 명시적으로 grid로 복원한다. 넓은 화면 2열, 좁은 화면 1열을 유지하되 카드 간격은 8~12px로 줄인다.
3. `.guardrail-toggle`에는 가로 `display:flex` 또는 `grid-template-columns:auto minmax(0,1fr)`를 명시한다. 부모 fieldset의 layout과 label의 layout을 각각 지정한다.
4. 체크박스는 고정된 작은 크기와 padding 0을 적용하고 제목 첫 줄에 정렬한다. 문구 span은 `min-width:0`으로 긴 한글이 정상 줄바꿈되게 한다.
5. 일반 입력 스타일은 checkbox/radio를 제외하도록 범위를 정리하거나, 관리자 전용 체크박스 규칙으로 명시적으로 상쇄한다. 개인 설정 입력의 외형은 유지한다.
6. “허용 변경 작업”의 등록/수정/삭제와 요금제의 이력 생성/추천 표시도 체크박스가 먼저 나오는 가로 label 규칙으로 확인한다.
7. 로딩 순서에 의존하거나 `!important`를 늘리지 않는다. 관리자 variant와 명확한 대상 selector로 기존 공통 규칙의 명시도를 제어한다.
8. checked/change/disabled·정책 데이터·저장/게시/테스트의 요청 본문은 변경하지 않는다.
