# 헤더 알림 카운터 조회 및 패널 분리

- 작성일: 2026-11-11 (한국시간)
- 요구사항: 15초 주기에는 카운터만 조회하고 목록은 패널을 열 때 조회. 일반/계약 알림에 빨간 배지와 바깥 클릭 닫기 적용.

## 주요 변경사항

- `/api/super-admin/notifications/count` 추가. 기존 master 권한과 수신자 범위를 유지하며 `{ unread }`만 반환한다. 목록 SELECT를 실행하지 않는다.
- 계약알림은 카운터만 15초마다 갱신하고, `/api/super-admin/notifications` 목록은 패널 열기·재열기 때 조회한다. 서버 초기 hydration도 목록 대신 카운터를 사용한다. 읽음 처리는 재시도 없이 기존 PATCH를 사용하고 정확한 카운터를 다시 조회한다.
- 일반 알림에 `/api/me/notifications/count` 추가. 기존 일반 알림인 팀 가입 신청의 pending 건수를 표시한다. owner는 현재 workspace의 신청, 그 외 구성원은 본인 신청 범위로 기존 목록과 동일하게 계산한다. 팀 공유 미지원 시 0이며 주기 조회는 실행하지 않는다.
- 일반 알림 목록은 패널 열기 때 기존 `/api/team/requests`로 조회한다. 모든 일반 알림 유형을 새로 만드는 기능은 포함하지 않는다.
- 두 버튼 우측 상단에 공통 빨간 카운터 배지 적용. 960px 이하에서는 계약알림을 툴팁이 있는 아이콘으로 표시하고 줄바꿈을 막아 배지를 가리지 않는다. 0건은 배지를 숨긴다. 두 패널 모두 바깥 pointerdown·Escape·버튼 재클릭·링크 이동으로 닫힌다.
- 일반 Query 정책을 유지하되 명시적 패널 열기 시 목록은 최신 조회한다. 카운터만 가시 탭에서 15초 폴링하며 포커스 복귀/업무 변경 시에도 재확인한다. 목록은 폴링·포커스·재연결로 자동 재조회하지 않는다.

## 검증 결과

- 카운터 응답·권한·사용자/workspace 경계·읽음/처리 후 감소: 격리 DB 테스트 통과.
- `pnpm typecheck`, `pnpm build`, `pnpm test:product-administration`, `pnpm test:query-audit` 통과. 기존 정적 생성 Request failed 로그가 있으나 빌드 종료 코드 0.
- 변경 파일 ESLint 오류 0. 기존 브라우저 스크립트 openMismatch 미사용 경고 1건 유지. 변경 파일 diff check 통과.
- fetch 분류 84개 파일·173개 호출, 미분류 0.
- 브라우저 초기 실패는 임시 SQLite 잠금 충돌과 기존 계정 폼의 hydration 대기 누락이었다. 테스트 DB만 WAL·busy_timeout/timeout을 설정하고 이벤트 연결을 기다리도록 보완한 뒤 최종 전체 재실행 통과. 운영 DB 설정은 변경하지 않았다.
- 최종 `pnpm test:product-administration-browser --production` 통과: 16초 동안 목록 요청 0건·두 카운터 갱신, 열기/재열기 때 목록 각 1회, 두 패널 바깥 클릭 닫기, 읽음 저장과 배지 감소, 빨간색·우측 상단 위치 확인. 최종 캡처도 확인했다.
- 반응형 보완 후 프로덕션 빌드 재통과.
