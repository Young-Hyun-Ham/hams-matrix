# AI 페이지별 프롬프트 / CRUD

## 관리자 가드레일

관리자 화면·정책 버전·입력/참고 자료/도구/출력 검사·AI 분류·이미지 정책·검사 토큰·운영 제한은 [AI 가드레일 운영](../../docs/AI_GUARDRAILS.md)을 참고합니다. 변경 도구는 `pending=true` 변경안만 만들며 최종 검증 후 대화·첨부와 함께 원자적으로 저장합니다. 중지/출력 차단/최종 설명 실패 시 미확정 변경은 폐기합니다.

- 실행 단계는 `policy.maxToolRounds`(기본 12, 2~40)로 지정하며 `maxChanges`(변경 항목 수)와 분리합니다. 마지막 단계는 도구를 끄고 최종 답변을 요청합니다. 동일 조회/오류 3회는 구체적 원인과 미저장 안내로 종료합니다.
- DB 설계 `save_database_tables`는 신규 테이블 여러 개를 한 호출로 검증하며 배치 내 FK 별칭을 실제 ID로 변환합니다. `pendingCount`/`remainingChanges`/`pendingChanges`로 저장 확인 반복을 막습니다. 기존 권한·검증·원자 저장·중지는 유지합니다.
- `pnpm test:ai-tool-execution`: 임시 DB·모의 AI로 100개 정의서, FK, 정책·반복·롤백·실제 채팅 경로를 검증합니다.

## 생성 중지와 사용량 갱신

- `pnpm db:migrate`로 `016_ai_generation_requests.sql`까지 적용합니다. 생성 중 버튼은 **중지**로 바뀌며, 확인창에서 승인하면 해당 사용자·워크스페이스·방·요청 ID에 대해서만 중지합니다. 요청 시작 전에 중지가 도착해도 이후 유료 호출을 막습니다.
- Responses API를 `background:true, store:false`로 호출합니다. 서버는 500ms 간격으로 상태를 조회하고 제공된 `usage`를 즉시 `ai_token_usage`에 갱신합니다. 중지 API는 활성 응답 ID에 `/responses/{id}/cancel`을 호출합니다. 생성 경로도 중지 상태를 확인하고 취소를 재확인합니다. 브라우저 요청 중단만으로 완료 처리하지 않습니다.
- 각 도구 실행 전과 DB 커밋 전에 중지 여부를 확인합니다. 변경안은 최종 검증 후 대화와 함께 저장하며, 확정 전 중지하면 폐기합니다. 이미 완료한 요청은 중지로 되돌리지 않습니다. `ai_generation_requests.actions_json`에는 실제 확정한 변경을 남깁니다. 중지와 결과 저장의 경합은 DB 상태 전환으로 구분합니다. 취소 확인 실패 시 중지 재시도를 표시합니다.
- 토큰은 문자 수로 추정하지 않습니다. 모델이 생성 중 사용량을 제공하지 않으면 NULL/미확인으로 남고, 수신한 중간 사용량과 완료·취소 시 사용량만 기록합니다. 입력에는 프롬프트 외에 지침·대화 이력·도구 결과·이미지가 포함될 수 있고, 도구 실행으로 AI를 다시 호출하면 각 호출의 입력·출력이 따로 집계됩니다. 중지해도 이미 사용한 토큰 기록을 삭제하지 않습니다.
- `usage_known=1`은 제공받은 사용량이 있음을, `usage_final=1`은 최종 상태에서 사용량을 수신했음을 뜻합니다. 최종 사용량이 누락되어도 이전 스냅샷을 지우지 않으며, 최종 미확인으로 구분합니다. 채팅 화면은 1초, 통계 화면은 보이는 동안 5초 간격으로 갱신합니다. 정확한 중간/취소 사용량 제공 여부와 원격 중지 지연은 OpenAI에 따릅니다.
- 백그라운드 응답은 `store:false`여도 OpenAI가 조회를 위해 일시 보관합니다. 참고: https://developers.openai.com/api/docs/guides/background
- 검증: `pnpm build`, `pnpm test:ai`. 외부 유료 API 대신 모의 공급자와 임시 DB로 실시간 스냅샷, 최종 사용량, 미확인 보존, 중지 재시도, 권한과 생성 재개를 확인합니다.

## 계정 설정의 토큰 사용 통계

- `011_ai_token_usage.sql`을 `pnpm db:migrate`로 적용합니다. 도입 이전 기록은 추정치로 채우지 않습니다. `ai_token_usage`는 사용자·워크스페이스·프로젝트·채팅방·메시지·요청·호출 순번별 실제 사용량을 기록합니다. 프로젝트명·방 제목 스냅샷과 논리 ID를 보관하므로 채팅방을 삭제해도 사용량 기록은 남습니다. 원문 프롬프트·이미지는 추가 복제하지 않고 입력/최종 결과 글자 수를 저장합니다.
- `lib/ai/token-usage.ts`: 유료 호출 전에 미확인 행을 확보하고, Responses API의 `usage.input_tokens`, `output_tokens`, `total_tokens`, `input_tokens_details.cached_tokens`, `output_tokens_details.reasoning_tokens`를 검증해 저장합니다. 미수신·잘못된 숫자·네트워크 오류는 NULL/미확인으로 보존합니다. 중간 도구 호출·미완성 응답도 사용량이 확인되면 기록합니다. 같은 응답 ID는 트랜잭션과 유니크 인덱스로 중복 집계를 막습니다.
- `lib/ai-server.ts`의 호출 추적 콜백이 각 도구 실행 단계의 AI 호출을 별도 기록합니다. 한 질문의 사용량은 `request_id`로 합산할 수 있습니다. `chat_saved`와 `result_characters`는 대화/이미지 저장 트랜잭션에서 함께 갱신하며, 대화 저장 실패 시에도 이미 발생한 사용량은 보존합니다.
- `GET /api/ai/usage?from=YYYY-MM-DD&to=YYYY-MM-DD&group=monthly|weekday|daily`는 현재 로그인 사용자·워크스페이스의 통계만 반환합니다. `projectId`(빈 값은 공통 작업 공간)·`convId`를 추가 필터로 지원합니다. 날짜는 한국 시간(Asia/Seoul)이며 최대 367일 범위를 검증합니다. 월별·월~일 요일별·일별로 사용 없는 구간도 0으로 채웁니다. 미확인은 확인된 토큰 합계에서 제외하고 건수를 함께 반환합니다.
- `ai-token-statistics.tsx/css`: 계정 설정 모달의 기본 `토큰 사용량` 탭. 연도·월·프로젝트·채팅방 필터, 입력/출력/합계/질문 및 호출 수, 입력·출력 누적 막대 그래프, 마우스·키보드 선택 상세값, 통계 표, 캐시·추론·미확인 건수를 표시합니다. `프로필` 탭에서 기존 이름 변경 기능을 유지합니다. 모달 헤더와 탭은 고정하고 본문만 스크롤합니다.
- 캐시·추론은 입력·출력의 부분집합이며 합계에 재가산하지 않습니다. 금액이나 글자 수 기반 추정 토큰은 표시하지 않습니다. 참고: https://developers.openai.com/api/docs/guides/token-counting
- `scripts/check-ai-token-usage.mjs`는 `pnpm test:ai`에서 실행합니다. 다단계 호출·실패/미완성/미확인·중복 응답·KST 자정 경계·사용자 격리·기간 검증·채팅방 삭제 후 보존을 검사합니다. 외부 AI만 모의 처리하고 별도 임시 DB/가짜 키를 사용합니다.

- `lib/ai/resolve-target.ts`에서 저장된 AI 대상의 권한을 검증하고 실행할 페이지 지침을 결정합니다. 실제 화면 위치와 AI 대상은 별도로 전달합니다.
- `lib/ai/page-prompts.ts`: 화면별 `instruction`, 조회할 `reads`(kind), 데이터 원본 `source`, 쓰기 대상 `kind`를 정의합니다. `pageInstructions`에는 도구 사용·등록/수정/삭제·필수값·실행 결과 보고에 대한 공통 규칙이 있습니다.
- `lib/ai/page-data.ts`: 프로젝트/팀/이력/산출물별 실제 조회 쿼리. WBS·아키텍처·요구사항·화면·DB·프로그램·검증은 공통 `project_artifacts`의 kind로 구분합니다. 관련 문서와 `artifact_links`를 함께 조회합니다. 이력은 `artifact_revisions`, 대시보드는 `projects`/`project_members`, 팀은 `workspace_members`/`team_join_requests`를 사용합니다.
- 편집 탭(7종): `read_page`, `save_artifact(CREATE/UPDATE/DELETE)`. 기존 `mutateArtifact`를 재사용하여 권한, 버전 충돌, 필수값, 관계, FK, 삭제 제한, 변경 이력과 감사 로그를 동일하게 적용합니다. 수정 시 생략한 필드·연결·구조는 보존합니다.
- 개요·추적표·통합검수·변경이력·산출물·대시보드·팀은 현재 조회 도구를 제공합니다. 기존 화면에 없는 프로젝트 수정/삭제, 팀 권한 변경, Excel 파일 생성, 검수 승인 기능을 도구가 실행했다고 주장하지 않도록 구분합니다.
- 'SCR-001의 명칭을 회원 조회로 수정해줘', 'SCR-001 삭제해줘', '아래 내용으로 화면을 등록해줘'처럼 작업과 대상을 명시합니다. 단순 초안·설계 요청은 저장하지 않습니다. 수정/삭제 대상의 정확한 명칭 또는 관리번호가 필요하며 한 요청의 최대 변경 건수는 활성 가드레일 정책을 따릅니다(기본 3건, 관리자 설정 범위 0~100건).
- AI가 변경한 뒤 store의 `aiDataVersion`을 갱신하여 현재 프로젝트 화면을 다시 조회합니다. 실행 중 AI 설명이 실패해도 커밋한 항목의 실제 결과를 반환합니다.
- 모델/키: 서버 전용 `OPENAI_API_KEY`, 선택적 `OPENAI_MODELS`/`OPENAI_MODEL`. Responses API 함수 호출을 사용하고 원본 응답·도구 결과를 이어 전달합니다. 참고: https://developers.openai.com/api/docs/guides/function-calling
- placeholder·제목은 `lib/ai-context.ts`에서 수정합니다.
- 채팅방과 대화는 사용자·워크스페이스·프로젝트·`conv_id`별로 관리합니다. 대화는 최신 50건부터 불러오고 이전 기록을 추가 조회할 수 있습니다.
- 검증: `pnpm test:ai`. 실제 HTTP·인증·임시 SQLite에서 외부 AI만 모의 처리합니다. 실제 생성 비용은 발생하지 않습니다.

- 레이아웃: `ai-workspace-layout.tsx/css`. 데스크톱에서 본문 안쪽을 채팅 30% / 페이지 70%로 나누고 300ms로 전환합니다. 960px 이하에서는 본문 위 레이어로 표시합니다. 닫기 버튼·Escape로 접으며 같은 방을 다시 선택하면 대화와 작성 중인 입력을 유지합니다. 모션 감소 설정도 따릅니다.

## 프로젝트별 채팅방

### 대화방별 AI 대상

- 입력 위 `현재`는 실제 화면, `AI 대상`은 이 방에서 처리할 위치다. 새 방은 현재 화면으로 시작하며, 같은 프로젝트의 다른 화면으로 이동해도 선택한 대상은 유지한다. 프로젝트/계정/워크스페이스 전환의 기존 방 초기화는 유지한다.
- `lib/ai-target-pages.ts`가 공통 key·표시명·지원 범위, `lib/ai/resolve-target.ts`가 서버의 대상 권한·프롬프트 선택을 관리한다. 프롬프트·조회 데이터·쓰기 kind는 저장된 대상 하나를 기준으로 결정한다.
- 영속 방은 `targetPage/targetVersion`을 반환한다. PATCH에 `targetPage/expectedTargetVersion`을 보내 즉시 저장하며, 생성 중·중지 미확인·버전 충돌은 409다. 대상 변경만으로 최근 활동순을 바꾸지 않는다.
- POST `/api/ai/chats`는 `targetPage/expectedTargetVersion/sourceContext`를 받는다. `sourceContext.pathname/tab`은 실제 화면 출처이며 메시지에 기록하고, 서버 저장 target은 프롬프트·도구·결과 제목에 사용한다. 구형 pathname/tab 요청은 미초기화 방을 한 번 초기화할 수 있지만 저장된 target과 다르면 409를 반환한다.
- `036_ai_conversation_targets.sql`은 마지막 유효 메시지 위치를 복원하고 기존 이력·이미지를 보존한다. 기록 없는 방은 첫 열기에 현재 위치를 CAS로 초기화한다. 오래된 메타데이터 응답은 최신 target 버전을 덮어쓰지 않는다.
- 문서함은 현재 위치를 보존하되 미지원 표시 후 지원 대상을 선택해야 생성할 수 있다. 설정/관리자 등의 기존 AI 노출 정책은 유지한다. 공통 방은 대시보드/팀 공유 범위이며 팀 공유 자격을 재검증한다.
- 이력 미저장 `temporary-*` 방은 기존 정책대로 메모리에서만 대상을 유지한다. 대상 변경으로 임시 프롬프트·이미지·모델을 초기화하지 않으며 과거 요청 재사용은 현재 target을 유지한다.
- 검증: `pnpm test:ai-targets`, `pnpm test:ai-target-migration`, 빌드 후 `pnpm test:ai-targets-browser`. 모두 합성 데이터·임시 DB를 사용하고 외부 AI는 모의 처리한다.

- 좌측 프로젝트 행은 들여쓰기 없이 표시하며 오른쪽 화살표로 새 채팅·목록을 접고 펼칩니다. 접어도 열린 대화는 유지합니다. 목록의 높이 제한/개별 스크롤을 제거하고 사이드바 한 곳에서만 스크롤합니다.
- 각 방 오른쪽 `…` 메뉴는 `ai-conversation-room.tsx`에서 본문에 포털로 표시해 사이드바 경계에 잘리지 않습니다. 바깥 클릭·Esc·스크롤로 닫히며 방향키/Home/End로 항목을 이동합니다. 옵션 조작은 방 선택과 분리됩니다.
- `고정`/`고정 해제`는 `010_ai_conversation_options.sql`의 `is_pinned`에 저장합니다. 고정 그룹을 먼저 표시하고 각 그룹 안에서 최근 활동순으로 정렬합니다. 고정 조작만으로 마지막 활동 시각을 바꾸지는 않습니다.
- 목록의 `제목 변경`은 입력 모달에서 저장하며 목록·열린 패널 제목을 함께 갱신합니다. `삭제`는 확인창을 거쳐 방·대화·첨부 이미지 전체를 하나의 트랜잭션으로 삭제합니다. 현재 방을 삭제하면 패널을 닫고 선택을 해제하며 다른 방 삭제 시 현재 대화는 유지합니다.
- `PATCH /api/ai/conversations/[convId]`에 `title` 또는 불리언 `isPinned`를 전달합니다. `DELETE`에는 `projectId`를 전달합니다. 두 메서드 모두 출처·로그인 사용자·워크스페이스·프로젝트 권한을 검사합니다. 답변 생성 중인 방은 409로 삭제를 거부하며, 트랜잭션 안에서 잠금 상태를 다시 확인합니다.
- `scripts/check-ai-conversation-options.mjs`는 `pnpm test:ai`에서 실행합니다. 고정 순서·새 조회 시 유지·제목/고정 동시 수정·다른 사용자 접근·삭제 시 이미지 정리·실패 롤백·다른 방 보존을 확인합니다.

- `ai-conversation-menu.tsx`: AI Chatbot 메뉴는 하위 목록만 접고 펼칩니다. 최초 진입이나 메뉴 펼치기만으로 채팅방을 생성하거나 채팅창을 열지 않습니다. `새 채팅` 클릭 시 DB에 먼저 저장하고 해당 방을 엽니다. 기존 방은 목록에서 선택하여 엽니다.
- `ai-conversation-title.tsx`: 채팅창 상단의 `제목 변경`에서 1~100자 제목을 저장합니다. 좌측 목록과 패널/팝업 제목도 함께 갱신합니다.
- `009_ai_conversations.sql`: `ai_conversations` 추가 및 기존 `ai_prompt_chats.conv_id` 연결. 기존 요청마다 독립된 방을 만들며 기존 메시지 ID·프로젝트·이미지 암호문·AAD·키를 그대로 보존합니다. DB 트리거도 메시지와 방의 사용자·워크스페이스·프로젝트 일치를 검증합니다. `pnpm db:migrate`로 적용합니다.
- `GET/POST /api/ai/conversations`: 프로젝트별 방 조회 / 명시적 생성. `PATCH /api/ai/conversations/[convId]`: 제목 변경. 프로젝트가 없는 대시보드·팀 화면은 공통 작업 공간의 방을 사용합니다.
- `GET /api/ai/chats?projectId=...&convId=...`: 선택한 방의 최신 대화 10건을 조회하고 맨 아래에 표시합니다. 위로 스크롤하면 `before` 커서로 이전 10건씩 추가하며 읽던 위치를 유지합니다. 이전 대화 버튼으로도 조회·오류 재시도가 가능합니다. 사용자 요청과 AI 답변 한 쌍을 1건으로 계산합니다. `POST /api/ai/chats`에도 `convId`가 필수입니다. 서버에서 로그인 사용자와 프로젝트 접근 권한을 검증합니다.
- 사용자 요청과 AI 답변을 대화 순서대로 표시합니다. 전송 성공 후 입력과 첨부를 비우고 대화는 유지합니다. `결과 크게 보기`로 기존 모달을 열며, 닫기·복사 성공 시 입력/첨부 초기화 동작도 유지합니다. 복사 실패 시에는 내용을 보존합니다.
- `lib/ai/conversations.ts`: 최근 20회, 텍스트 약 60,000자 이내의 대화와 최근 첨부 3장을 이전 문맥으로 전달합니다. 이미지 복호화는 서버에서만 수행합니다. 전체 대화는 DB에 보관하며 문맥 제한으로 삭제하지 않습니다. 현재 화면·탭의 시스템 지침과 최신 요청 기준 CRUD 권한/의도 검증을 매번 적용합니다. 참고: https://developers.openai.com/api/docs/guides/conversation-state
- 같은 방의 중복 생성 요청은 DB의 만료 가능한 잠금으로 차단하고 실패 후 해제합니다. 프로젝트·계정 전환 시 방 선택과 채팅창을 초기화합니다. 패널 확대·팝업 전환 시에는 같은 채팅 인스턴스를 유지합니다.
- 검증: `node scripts/test-ai-conversation-migration.mjs`, `pnpm test:ai`. 이전 기록 이관, 방 생성·이름 변경·권한·프로젝트 분리·문맥 전달·페이지 분기·이전 대화 조회·잠금 복구를 검사합니다.
- 페이징 검증: `node scripts/test-ai-chat-pagination.mjs`는 실제 인증·GET API와 임시 SQLite로 10건 경계·순서·첨부 메타데이터·권한을 검사합니다. `node scripts/test-ai-chat-pagination-browser.mjs`는 실제 React 대화 훅·메시지 컴포넌트를 Chrome에서 실행해 초기 하단 위치·자동 이전 조회·스크롤 유지·중복 요청·오류 재시도·방 전환을 검사합니다. 조회 응답과 프레임워크 주변 기능만 모의하며 외부 AI나 운영 DB는 사용하지 않습니다.

## 캡처 이미지 첨부

- 프롬프트 입력창에 Ctrl/⌘+V로 PNG/JPEG/WebP를 붙여넣습니다. 브라우저에서 PNG로 변환하여 메타데이터를 제거하고 미리보기·삭제·확대 보기를 제공합니다. 일반 텍스트 붙여넣기는 유지합니다.
- 최대 3장, 변환 후 장당 2MB, 가로/세로 각각 4096px입니다. 글 없이 이미지만 보내면 현재 화면·탭에 맞는 기본 분석 요청을 사용합니다.
- `lib/ai/chat-images.ts`: PNG 형식/크기 검증, AES-256-GCM 암호화·인증 복호화. 암호문·12바이트 IV·16바이트 인증 태그를 Base64 문자열로 `ai_chat_images`에 저장합니다. 사용자·워크스페이스·프로젝트·기록·이미지 ID와 메타데이터를 AAD에 결합합니다.
- `.env`의 `AI_IMAGE_ENCRYPTION_KEY`는 **32바이트 난수의 Base64**입니다. `node scripts/setup-ai-image-key.mjs`로 생성합니다. 키 값은 출력하지 않으며 이미 설정된 값은 보존합니다. 키를 잃으면 기존 이미지를 복호화할 수 없으므로 별도로 보관하고 배포 환경에도 같은 키를 설정합니다. OpenAI API 키와 별개의 키입니다.
- `008_ai_chat_images.sql` 마이그레이션을 적용합니다. 프롬프트와 암호화된 이미지들은 한 트랜잭션으로 저장합니다.
- 기록 목록은 암호문·평문을 포함하지 않고 이미지 메타데이터와 조회 주소만 반환합니다. `GET /api/ai/chats/[chatId]/images/[imageId]`에서 로그인 사용자·워크스페이스·프로젝트 접근 권한을 확인하고 복호화합니다. 이미지는 `private,no-store`로 응답합니다.
- 기록의 결과 창에서 캡처를 다시 보거나 '프롬프트·이미지 다시 사용'으로 입력창에 복원할 수 있습니다.
- OpenAI에는 `input_text`와 `input_image`를 함께 전달합니다. 이미지 안의 명령은 실행 지시로 취급하지 않습니다. 참고: https://developers.openai.com/api/docs/guides/images-vision
- `pnpm test:ai`: 이미지 전달·암호화·복호화·권한·위변조·저장 롤백을 검사합니다. `node scripts/test-ai.mjs --no-image-key`는 키 미설정 시 이미지 저장이 거부되고 텍스트 요청은 유지되는지 확인합니다. 임시 DB·가짜 키·모의 AI를 사용합니다.

## 채팅 패널 확대 / 팝업

- 헤더 버튼: 좌우 분리/상하 배치 → 팝업/패널 전환 → 확대/축소 → 닫기. 기본 패널은 30%, 확대하면 50%이며 다시 누르면 30%입니다.
- 좌우 분리 진입 시 기존 확대 너비를 기본 적용합니다. 패널은 작업 영역의 50%, 팝업은 최대 760px(화면 너비에서 24px을 뺀 값 이내)입니다. 왼쪽은 대화, 오른쪽은 모델·AI 대상·첨부·생성/중지를 포함한 입력 카드이며 방 제목은 공통 행입니다.
- 분리 중에도 수동 축소할 수 있으며, 상하 배치로 복원하면 상하 모드에서 마지막으로 선택한 너비로 돌아갑니다. 분리 해제 후 재진입할 때는 다시 확대합니다. 패널/팝업 전환 및 닫기/재열기·방 전환에서는 창 배치를 유지하고, 전체 새로고침 시 초기화합니다. 창 설정을 DB에 저장하지 않습니다.
- 내부 가용 너비 560px 이상에서 대화:입력을 약 60:40 비율로 좌우 표시하고 입력 카드는 최소 240px을 확보합니다. 모델 선택은 폭 108px의 작은 컨트롤로 표시합니다. 더 좁으면 분리 설정을 유지한 채 상하 표시하며 넓어지면 좌우 표시를 복원합니다. 960px 이하 패널의 기존 최대 440px 제한도 유지합니다. 대화와 입력 카드는 각각 스크롤합니다.
- 팝업은 배경 차단막이 없는 비모달 창입니다. 본문은 전체 너비로 복원되고 부모 화면의 버튼·입력을 계속 사용할 수 있습니다. 메뉴의 접기/펴기 기능도 유지합니다.
- 제목을 마우스/터치로 드래그하거나, 제목에 포커스를 둔 뒤 방향키(10px)·Shift+방향키(40px)로 이동합니다. 확대 및 viewport 변경 시 화면 안으로 위치를 보정합니다.
- 같은 DOM과 채팅 인스턴스를 유지하여 입력·이미지·기록·진행 중 요청이 전환 시 사라지지 않습니다. 프로젝트/사용자가 바뀔 때의 기존 초기화 규칙은 유지합니다.
- 팝업의 Esc는 채팅 내부에 포커스가 있을 때만 닫습니다. 부모 화면에서 Esc를 눌러도 채팅 창을 닫지 않습니다.
