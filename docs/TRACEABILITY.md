# 프로젝트 산출물과 추적성

WBS·아키텍처·DB·검증 결과를 포함하는 현재 통합 규칙은 [통합 산출물 체계](INTEGRATED_DELIVERABLES.md)를 참조하세요. 아래는 최초 3종 문서의 기본 추적성 설계입니다.

## 현재 범위

프로젝트 상세(`/projects/[projectId]`), 요구사항정의서, 화면설계서, 프로그램설계서 CRUD,
다대다 연결, 추적표, 프로젝트별 변경 이력, 실제 대시보드 통계 및 XLSX 다운로드를 제공합니다.
프로젝트 수정/삭제, 파일 첨부 및 화면 이미지 편집, 테스트케이스 관리, AI 호출은 포함하지 않습니다.
화면설계서는 현재 화면 개요·구성·입출력·이벤트의 텍스트 설계입니다.

## 서식 기준

현재 기본 서식은 공공사업 요구사항에서 사용하는 공통 항목을 바탕으로 구성했습니다.
특정 기관의 원본 엑셀과 동일한 셀 배치/버전으로 인증된 서식은 아닙니다.
사용자가 지칭한 ‘전자정부 표준 요구사항정의서’의 기관명, 문서명, 원본이 확정되면
필드 매핑과 출력 레이아웃을 해당 버전에 맞추어야 합니다.

참고한 공식 공개 자료:
- [나라장터 공개 제안요청서](https://www.g2b.go.kr/pn/pnp/pnpe/UntyAtchFile/downloadFile.do?bidPbancNo=R26BK01453710&bidPbancOrd=000&fileSeq=2&fileType=&prcmBsneSeCd=03): 요구사항 분류·고유번호·명칭·상세설명(정의/세부내용)·산출정보·관련 요구사항·출처 구조.
- [중소기업중앙회 개발산출물 양식 안내](https://www.kbiz.or.kr/ko/contents/bbs/view.do?mnSeq=334&seq=161694): 단계별 산출물 양식 안내. 전자정부 원본 서식으로 간주하지 않음.

요구사항: 분류, 명칭, 정의, 세부내용, 출처, 원본 요구사항 번호(RFP), 산출정보,
검수 기준, 우선순위, 담당자, 비고/제약사항. 관련 요구사항은 텍스트가 아닌 실제 항목에 연결합니다.
화면: 명칭, 개요, 메뉴 경로, URL, 화면 구성, 입력 검증, 출력, 이벤트/처리 흐름.
프로그램: 명칭, 개요, 유형, 모듈/소스 경로, 입력, 출력, 처리 로직, 관련 테이블/CRUD, 예외 처리.
모든 항목에 상태, 담당자, 비고, 버전과 수정 시각을 저장합니다.

## ID와 관계

- 내부 UUID가 실제 관계 키입니다. 명칭 변경은 관계를 변경하지 않습니다.
- 프로젝트 내 분류별 순번: SFR-001, PER-001 등 / SCR-001 / PGM-001.
- 관리번호는 변경 불가이며 삭제 후에도 순번을 재사용하지 않습니다.
- 요구사항 분류는 관리번호와 일치하도록 등록 후 변경을 제한합니다.
- 원본 RFP 번호는 별도 보존하여 자체 관리번호와 구분합니다.
- 요구사항 → 관련 요구사항, 화면 → 요구사항, 프로그램 → 화면 또는 요구사항.
- 다른 프로젝트/테넌트, 삭제된 항목, 자기 자신 또는 허용되지 않은 유형은 연결할 수 없습니다.
- 연결된 항목은 먼저 관련 연결을 해제해야 삭제할 수 있습니다.
- 삭제는 soft delete이며 관리번호와 변경 기록을 보존합니다.
- 버전이 달라진 수정/삭제는 409로 거절합니다.

추적표는 실제 연결 경로마다 한 행을 만듭니다. 요구사항 → 화면 → 프로그램,
요구사항 → 프로그램 직접 연결, 미연결 요구사항, 요구사항 없는 화면과 그 프로그램,
상위 연결 없는 프로그램을 모두 표시합니다. 요구사항 간 참고 관계는 추적 경로와 구분하여 연결목록에 표시합니다.

## 이력과 보안

모든 API는 세션 사용자와 DB의 현재 워크스페이스/프로젝트 멤버십을 검사합니다.
owner 계정의 owner/admin/member만 수정하며 user/viewer는 읽기 전용입니다.
프로젝트 변경과 연결·버전 이력은 동일 write transaction에 저장합니다.
감사 이력은 기존 DB_LOGGING_ENABLED를 따르고, artifact_revisions는 문서 버전 관리 목적으로
항상 보존합니다. revision UPDATE/DELETE는 DB 트리거로 차단합니다.
UI는 최근 100건의 전체 스냅샷을 표시하고 DB는 전체 이력을 보존합니다.

## Excel

GET /api/projects/[projectId]/export는 권한 확인 후 read transaction의 동일 스냅샷으로
문서정보 / 요구사항정의서 / 화면설계서 / 프로그램설계서 / 요구사항추적표 / 연결목록을 생성합니다.
각 설계서의 관련 ID 열은 직접 연결과 화면 경유 연결을 반영하며, 연결목록은 실제 직접 연결을 표시합니다.
모든 값은 OOXML inlineStr로 출력하여 =, +, - 등으로 시작해도 수식으로 실행하지 않습니다.
기본 열 너비, 줄바꿈, 헤더 고정/색상, 자동 필터를 제공합니다. 외부 패키지 의존성은 추가하지 않았습니다.
대용량 스트리밍, 기관별 템플릿 업로드/매핑, 테스트 산출물은 후속 범위입니다.

## 실행 및 검증

기존 환경에서 `pnpm db:migrate`를 한 번 실행해야 005_traceability.sql이 적용됩니다.
이후 `pnpm dev`로 실행합니다. 기존 데이터를 삭제하거나 덮어쓰는 SQL은 없습니다.

`pnpm typecheck`, `pnpm lint`, `pnpm build` 후 `pnpm test:auth`를 실행합니다.
신규 통합 검증은 scripts/check-artifacts.mjs이며 기존 격리 DB 인증 테스트에서 함께 실행됩니다.
실제 .env의 Turso DB 대신 OS 임시 디렉터리의 SQLite를 사용합니다.
