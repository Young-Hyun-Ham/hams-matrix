# AI 챗봇 채팅·입력 영역 좌우 분리 구현

- 작성일: 2026-11-09 (한국시간, Asia/Seoul)
- 상태: 구현 및 관련 검증 완료
- 기준: [최신 설계 문서](../../history/2026-11-09/AI챗봇-채팅입력-좌우분리-설계.md)를 다시 읽고 구현했다. 별도 선택이 지정되지 않은 D1~D7은 문서의 권장안을 적용했다.

## 주요 변경사항

- 헤더 전환 버튼 앞에 좌우 분리/상하 배치 버튼과 접근 가능한 상태·설명·아이콘을 추가했다.
- 분리 시 왼쪽 대화, 오른쪽 입력 카드 전체, 상단 공통 방 제목으로 표시한다. 같은 채팅 DOM과 인스턴스를 유지한다.
- 분리 진입마다 기존 확대 너비를 기본 적용한다. 패널은 작업 영역 50%, 팝업은 최대 760px이며 화면 너비 제한을 지킨다. 팝업 위치 계산과 경계 보정도 같은 유효 확대 상태를 사용한다.
- 상하/분리 모드의 확대 선택을 구분했다. 분리 중 수동 축소를 허용하며, 분리 해제 시 기존 상하 모드 너비를 복원한다. 닫기/재열기·방 전환에서는 기존 창 훅 수명에 따라 유지하고 전체 새로고침 시 초기화한다.
- 내부 가용 폭 560px 이상에서 1:1·간격 12px로 분리한다. 더 좁으면 설정을 유지한 채 상하 표시하며 넓어지면 복원한다. 기존 960px/700px 반응형 너비는 유지한다.
- 대화와 입력 카드를 각각 스크롤하고, 분리 상태에서는 textarea 최소 높이 100px과 남은 높이를 활용한다. 모델·AI 대상 선택과 긴 문구는 좁은 열 안에서 줄바꿈한다.
- 팝업 확대 tooltip에 실제 팝업 너비 규칙을 표시하고 README를 갱신했다.

## DB 변경 여부

- 스키마·마이그레이션·API 계약·운영 DB 변경 없음. 창 설정은 로컬 React 상태로 관리한다.
- 브라우저 검증은 임시 SQLite DB와 모의 AI, 전용 headless Chrome 프로필을 사용했다. 테스트용 DB에만 기존 마이그레이션과 합성 데이터를 적용했다.

## 검증 결과

| 검증 | 결과 |
| --- | --- |
| `pnpm typecheck` | 통과 |
| 변경한 TS/TSX 및 브라우저 스크립트 대상 ESLint | 통과, 오류·경고 없음 |
| `pnpm build` | 통과, 종료 코드 0 |
| 변경한 브라우저 스크립트 3개 `node --check` | 통과 |
| `pnpm test:ai-targets-browser` | 통과. 새 분리 시나리오 및 기존 AI 대상 선택·저장·생성·첨부·임시 방 검증 |
| `node scripts/test-navigation-browser.mjs` | 통과. 기존 메뉴 geometry·모바일·포커스·Esc·로그아웃·패널 위치 회귀 검증 |
| 변경 범위 `git diff --check` | 통과 |

실제 브라우저에서 Enter로 분리 버튼 활성화, 패널 30%/50%, 팝업 460/760px와 화면 경계 보정, 모드별 너비 복원, 559/560/561px 경계, viewport 961/960/701/700/390px, 낮은 높이·다크 테마를 확인했다. 입력·모델·AI 대상·이미지와 textarea DOM을 유지하며 배치 전환만으로 API 요청이 추가되지 않았다. Next.js의 관련 없는 메뉴 링크 사전 로드는 API 요청 검증에서 제외했다. 생성 중 전환과 결과 모달 Esc·분리 상태 재열기도 통과했다.

증빙 스크린샷은 테스트가 출력한 임시 폴더에 생성된다. 최종 분리/AI 대상 실행 폴더는 `matrix-navigation-browser-t4gFzx`, 기존 메뉴 실행 폴더는 `matrix-navigation-browser-EyJQXB`이다. 분리 패널과 낮은 높이 화면을 직접 확인했다.

빌드 정적 생성 과정에서 `Request failed Error` 로그가 일부 출력되었지만 빌드는 성공했다. 해당 요청 로그의 원인 분석은 이번 UI 변경 범위에서 수행하지 않았다. 실제 UI 회귀 검증은 격리된 테스트 DB에서 통과했다.

## 미완료 사항 및 검증 한계

- 요청한 구현 범위의 미완료 사항 없음.
- 실기기, Chrome 외 브라우저, 브라우저 200% 실제 확대는 별도 수동 검증 대상이다. 자동 검증은 headless Chrome의 viewport/내부 폭·짧은 높이 변경으로 수행했다.
- 서버/API 로직 변경이 없어 전체 `pnpm test:ai`는 추가 실행하지 않았다. 관련 생성·대상·첨부 흐름은 모의 AI를 사용하는 실제 브라우저 테스트에서 확인했다.
