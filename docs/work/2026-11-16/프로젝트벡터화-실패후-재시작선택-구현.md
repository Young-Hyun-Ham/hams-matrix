# 프로젝트 벡터화 실패 후 재시작 선택 구현

- 작성일: 2026-11-16 (한국시간).
- 상태: 구현·관련 검증·구성 DB 적용 완료.

## 주요 변경사항

- 실패 작업에서 새로 시작/실패 지점부터 이어서 시작을 선택한다. 재개는 기존 모델과 저장 청크를 유지하고 새 작업 시도로 기록한다.
- 최신 실패 작업·동일 원본/차원/분할 방식만 재개하며 키 교체는 같은 모델 접근이 가능한 경우 허용한다. 원본 변경 시 새로 시작하도록 안내한다.
- 원래 실패 작업의 상태·오류·종료 시각과 저장된 청크 ID를 보존한다. 추가 호출은 새 job의 사용량으로 기록한다.

## 변경 파일·DB

- 신규 `lib/ai/rag-resume.ts`, `app/api/projects/[projectId]/rag/jobs/[jobId]/resume/route.ts`.
- 수정: `lib/ai/project-rag.ts`, `rag-types.ts`, 재시작 모달/CSS, migration 실행 prerequisite, RAG/승인/브라우저 검증 스크립트.
- 신규 migration 049: jobs에 restart_mode·resume_from_job_id, 자기 FK·모드 CHECK·범위/계보 보호 트리거·인덱스 추가. 048을 다시 수정·실행하지 않는다.
- 기존 설계 문서의 14절, README·AGENTS·CLAUDE·WORK_HISTORY를 갱신한다. 다른 미커밋 변경은 보존한다.
- 구성 DB에 `node --env-file=.env scripts/migrate.mjs --only 049_project_rag_resume.sql`로 049만 적용했다. 적용 이력 및 두 컬럼을 확인했고 `PRAGMA foreign_key_check` 위반은 0건이다. 기존 데이터와 다른 미적용 migration은 보존했다. 민감정보는 기록하지 않는다.

- `pnpm test:ai-settings-reviews` 통과: 신규 migration 포함 기존 데이터 보존과 승인 흐름 회귀 검증.

## 제한·재개 정보

- 원본·모델·분할 방식이 달라지면 이어서 시작을 거절하고 새로 시작을 요구한다.
- 공급자 호출이 끝났더라도 DB 저장 전에 실패했다면 해당 미저장 배치는 다시 호출될 수 있다.
- 기존 워커의 저장 청크 건너뛰기 기능을 재사용하므로 웹/API 변경 적용 시 신규 049 스키마가 필요하다. 실제 유료 임베딩은 검증에 사용하지 않는다.
- 미완료 구현은 없다. 실행 중인 웹/워커 프로세스에는 변경한 소스를 다시 시작하거나 배포해야 적용된다.
