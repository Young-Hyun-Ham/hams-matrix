# 요금제별 프로젝트 팀 초대 인원 한도

- 작성일: 2026-11-09 (Asia/Seoul)
- 기존 변경사항을 보존하며 슈퍼관리자 요금제 설정에 프로젝트별 팀 초대 인원 옵션을 추가했다.

## 주요 변경사항

- `프로젝트당 팀 초대 인원` 숫자 입력과 저장·조회 필드를 추가했다. 0 이상의 정수 또는 빈 값을 허용한다. 빈 값은 무제한, 0은 추가 초대 불가다.
- 기본값은 Free 1명, Pro 1명, Team 20명, Business 빈 값(NULL, 무제한)이다.
- 프로젝트 소유자는 초대 인원에서 제외한다. 각 프로젝트별 참여자를 별도로 집계하며, 관리자·회원·뷰어 모두 초대 인원에 포함한다.
- 프로젝트에 팀원을 초대할 때와 프로젝트 생성 시 초기 팀원을 선택할 때 모두 해당 워크스페이스 요금제의 한도를 검사한다. 중복 사용자 선택으로 정원을 잘못 계산하지 않는다.
- 한도 검사와 회원 등록은 같은 쓰기 트랜잭션에서 수행한다. 초과 요청은 회원·공간 소속을 추가하지 않고 거부한다. SQLite 동시 처리 충돌은 재시도 가능한 409 응답으로 안내한다.
- 한도 축소 시 기존 팀원을 삭제하지 않는다. 한도 이내로 조정하기 전에는 추가 초대를 막는다. 기존 팀공유 활성화 설정과 상품별 활성 사용자 정원은 별도로 유지한다.
- 개인 요금제 안내에도 프로젝트별 팀 초대 한도를 표시한다.

## DB 변경 여부

- 실제 연결 DB에 `042_project_invite_limit.sql`만 적용했다. 다른 마이그레이션을 일괄 실행하지 않았다.
- `plans.project_invite_limit` nullable 정수 컬럼과 비음수 정수 CHECK를 추가하고 네 요금제 기본값을 설정했다. 요금제 버전도 증가시켜 이전 화면의 설정 덮어쓰기를 막았다.
- 실제 DB 결과: Free=1, Pro=1, Team=20, Business=NULL.
- 기존 계정 역할·구독 유형·워크스페이스 플랜/소유자·프로젝트 소유자 보존 검사, 외래키 검사, DB 무결성 검사 통과.
- 재실행은 `applied:false`로 안전하게 종료되며 설정을 기본값으로 다시 덮어쓰지 않는 것을 확인했다.

- `tsc --noEmit`: 통과.
- 변경 소스 및 Next 설정 대상 ESLint: 오류·경고 없이 통과.
- `node scripts/test-product-administration-browser.mjs --plans-only`: 통과. 실제 슈퍼관리자 화면의 1/1/20/빈 값 표시, 입력값 변경·저장, 페이지 재진입 후 저장값 유지를 임시 DB와 숨김 Chrome으로 검증했다.
