- 상태: 현재 소스 분석에 근거한 검토용 설계. 구현 전이며, 제안 수치·파일 분리·기본 동작은 사용자 검토 후 확정한다.

### 1.1 이번 설계의 화면 해석

- 대상은 `/viewer`의 Markdown 문서 뷰어다. 이 화면에 문서 목록·본문·‘이 문서의 목차’와 원문 편집 기능이 함께 존재한다.
- ‘좌측 메뉴 패널’은 우선 공통 `WorkspaceShell`의 메뉴 열기/접기 버튼이 제어하는 전역 메뉴로 해석한다.
- 뷰어 내부의 250px 문서 목록은 별도 영역이다. 현재 이 목록 자체를 접는 버튼은 없다. 목록 접기 기능도 필요한지는 7절에서 구분하여 결정한다.
- Mermaid 탭은 문서 전체의 기존 ‘미리보기/원문’과 별개로, 문서 미리보기 안의 각 Mermaid 코드 블록에 제공하는 것을 권고한다.
- 문서 저장 API·권한·DB 구조, 아키텍처 편집기의 저장·AI 생성·이미지 동기화는 변경 범위에 포함하지 않는다.

## 2. 현재 구조와 확인한 제한

700px 이하의 전역 메뉴는 오버레이 방식이다. 모바일 메뉴 닫기는 데스크톱처럼 본문 폭을 늘리는 동작으로 취급하지 않는다.

### 2.2 뷰어 내부 레이아웃과 원문

핵심 파일은 `app/(workspace)/viewer/md/MarkdownViewer.tsx`와 `styles/pages/viewer/md/MarkdownViewer.module.css`다.

1. `.viewer`는 `container: markdown-viewer / inline-size`를 선언한다. `ResizeObserver`와 창 크기 이벤트는 부모·푸터의 크기로 `--viewer-height`를 갱신한다. 이 계산은 높이용이며 본문 열의 가로 폭 상한을 해제하지 않는다.
2. `.workspace`는 `250px minmax(0, 1fr)`로 문서 목록과 문서 내용 영역을 나눈다.
3. `.readingArea`는 본문과 목차를 `minmax(0, 900px) 190px`로 배치하고 가운데 정렬한다. 열 간격은 20px, 바깥 padding은 24px이다.
4. 넓은 화면에서 본문 열이 900px에 도달하면 메뉴를 접어도 추가 공간이 본문 폭으로 이어지지 않는다. 이 부분이 R1의 주요 변경 대상이다.
5. 원문 모드는 별도 1열 `minmax(0, 1fr)`이며 `drafts`를 편집한다. 미리보기·목차·문서 복사는 저장된 `selectedDocument.content`를 사용한다. 미저장 초안을 미리보기에 반영하는 변경은 이번 요구에 명시되지 않았다.

### 2.3 목차

- `extractHeadings()`는 본문을 줄 단위 정규식으로 읽어 h1~h3의 텍스트·원본 줄 번호·중복 방지 ID를 생성한다.
- 제목이 두 개 이상이고 문서 미리보기일 때만 `<nav aria-label="이 문서의 목차">`를 렌더링한다.
- 버튼의 왼쪽 들여쓰기는 h1 8px, h2 20px, h3 32px이다. 글꼴 크기는 12px이며 줄바꿈을 막는 규칙은 없다.
- 목차 폭은 190px이고, 내부 padding은 좌우 각 10px, 버튼 오른쪽 padding은 6px이다. h3에서 실제 제목에 쓸 수 있는 폭은 테두리까지 빼면 약 130px이다.
- `.outline`은 `position:sticky; top:0; max-height:100%; overflow-y:auto`다. 스크롤바 숨김 규칙은 없고, 부모가 긴 본문과 함께 커지는 grid인 상황에서 `100%`만으로 화면 내 유효 높이를 확실히 제한하기 어렵다.
- 뷰어 컨테이너가 1000px 이하이면 목차를 숨기고 본문을 1열로 전환한다. 720px 이하이면 문서 목록을 본문 위에 배치한다.
- 목차가 없는 문서에서도 미리보기 grid는 기본 2열이므로 빈 목차 열이 남을 수 있다. 본문 가용 폭 처리와 함께 정리할 대상이다.

추가 연계 사항: 현재 제목 추출기는 fenced code block을 제외하지 않는다. Mermaid 코드 안에 `#`로 시작하는 줄이 있으면 실제 제목이 아닌 줄이 목차 후보가 될 수 있다. Mermaid 지원 시 코드 블록 내부 제목 제외를 함께 검증하고 보완한다.

### 2.4 Markdown과 Mermaid

- Markdown은 `ReactMarkdown`과 `remark-gfm`으로 렌더링한다. `components.code`는 `className`·`data-line`을 전달하는 일반 `<code>`만 출력한다. `language-mermaid` 분기와 도식 렌더링은 없다.
- `package.json`에는 이미 `mermaid: ^12.2.0`, `react-markdown: ^10.1.0`, `remark-gfm: ^4.0.1`이 선언되어 있다. 새 패키지를 추가할 필요가 없다.
- `components/pages/architecture/architecture-mermaid.tsx`에는 동적 import, strict 설정, 테마 적용, 비동기 결과 무효화가 구현되어 있다. 해당 컴포넌트는 artifact·저장 API·미저장 상태와 결합되어 있어 뷰어에 그대로 삽입하기 적합하지 않다.
- `components/pages/architecture/mermaid-preview.ts`의 `safeMermaidSvg()`와 `readableMermaidLabels()`는 SVG 정리와 라벨 대비 보정의 참고·재사용 후보다.
- `lib/architecture-mermaid.ts`의 `editableMermaidError()`는 graph/flowchart 구성도만 허용한다. 문서에 사용하는 sequenceDiagram 등 일반 Mermaid까지 지원하려면 이 검증기를 그대로 적용해서는 안 된다.

## 3. 수정 방향

### 3.1 메뉴 접기와 문서 폭 확장

1. 기존 전역 메뉴 상태와 `--workspace-sidebar-width` 연동을 유지한다. viewer 전용으로 `window.innerWidth - 240` 같은 폭 계산을 추가하지 않는다.
2. 목차가 표시되는 미리보기의 본문 열을 `minmax(0, 1fr)`로 바꾸고, 두 번째 열에는 목차 전용 폭 변수를 사용한다. 가운데 정렬과 900px 상한으로 생기는 유휴 공간을 해소한다.
3. 목차가 없는 경우에는 명시적으로 1열을 사용한다. ‘제목 두 개 이상’이라는 기존 표시 조건과 레이아웃 조건을 일치시킨다.
4. 원문 모드는 기존 1열과 편집 상태를 유지한다. 본문 표·코드·도식이 페이지 전체를 가로로 밀지 않도록 `min-width:0`과 해당 블록 내부 overflow를 유지한다.
5. `ResizeObserver`의 높이 측정은 유지한다. 실제 메뉴 전환 시 높이·푸터 위치가 잘못되는 증거가 있을 때만 최소 보완한다.

데스크톱에서 AI 패널이 닫혀 있고 목차 표시 상태가 같다면, 메뉴 접기 시 문서 내용 영역과 본문 열의 증가량은 메뉴 폭 감소량인 176px/150px/146px과 대체로 일치해야 한다. 테두리·소수점 반올림은 1~2px 오차를 허용한다. AI 패널이 공간을 나누는 경우에는 페이지에 배정된 폭의 증가량으로 비교한다.

목차 표시 경계를 넘는 순간에는 새 목차 열도 공간을 사용하므로 본문 종이 영역의 폭 증가량이 달라질 수 있다. ‘문서 영역’을 전체 내용 패널로 볼지 본문 종이로 볼지는 7절의 검토 항목이다.

### 3.2 40단위 목차 폭

#### 문자 수의 정의

사용자 표현의 ‘40자’는 아래와 같은 **가중 길이 40단위**로 해석한다.

`가중 길이 = 한글 문자 수 × 2 + 그 외 문자 수 × 1`

| 제목 예 | 원래 문자 수 | 가중 길이 |
| --- | --- | --- |
| 한글 20자 | 20 | 40 |
| 영문 또는 숫자 40자 | 40 | 40 |
| 한글 10자 + 영문 20자 | 30 | 40 |

공백·구두점도 ‘그 외’에 포함한다. 코드 포인트 순회와 NFC 정규화를 기준으로 하고, 한글 완성형 및 한글 자모 범위를 한글로 분류하는 것을 권고한다. 이 규칙은 표시 기준 설명과 검증용이며 원문 제목을 변환하거나 잘라 저장하지 않는다.

#### 폭 산정과 표시

- 기준 글꼴 크기 12px에서 1단위를 약 0.5em, 한글 1자를 약 1em으로 보면 제목 자체에 필요한 폭은 `40 × 6px = 240px`이다.
- h3 최대 들여쓰기 32px, 버튼 오른쪽 6px, 목차 좌우 padding 20px, 외곽 테두리 2px를 합하면 **목차 전체 300px**이 1차 설계값이다.
- 제목 여유 폭과 글꼴 크기가 함께 움직이도록 제목 폭을 `20em`으로 표현하고, 들여쓰기·padding·테두리를 더하는 CSS 변수를 두는 방식을 권고한다. 300px은 12px 글꼴 기준 계산값이다.
- `.outlineButton`에는 `white-space:nowrap`을 적용한다. 긴 제목은 한 줄 말줄임으로 표시하고 `title` 등에 전체 제목을 제공한다. 목차 클릭은 전체 제목의 원래 heading ID로 이동한다.
- CSS `40ch`는 현재 글꼴의 숫자 0 너비를 기준으로 하므로 ‘한글 2, 그 외 1’을 그대로 보장하는 값이 아니다. 이를 40단위와 동일하다고 간주하지 않는다.
- 현재 Arial·한글 대체 글꼴은 가변 폭이다. 따라서 300px은 모든 영문·기호 조합을 정확히 보장하는 확정값이 아니다. W 등 폭이 큰 문자 40개, 한글 20자, 혼합 제목을 실제 대상 브라우저에서 측정해 여유 폭을 보정한다. 가중 길이 40 이하인 검증 제목에는 말줄임이 발생해서는 안 된다.
- 실제 모든 문자 조합에 대한 엄격한 보장이 필요하면 7절에서 고정 폭 글꼴 또는 실측 최대 폭 산정 방식을 선택한다. 글자 수를 줄이거나 40단위 이하를 잘라서 요구를 충족한 것으로 처리하지 않는다.

#### 반응형 경계

목차를 190px에서 약 300px로 늘리면서 기존 1000px 경계를 그대로 두면 본문이 과도하게 좁아진다. 경계는 다음 예산을 기준으로 재산정한다.

`뷰어 필요 폭 = 문서 목록 250 + 읽기 영역 좌우 여백 48 + 열 간격 20 + 목차 300 + 본문 최소 폭 500 = 1118px`

기본 권고값은 뷰어 컨테이너 **1120px 이하에서 목차 숨김**, 그보다 넓으면 표시하는 것이다. 최종 목차 폭을 보정하면 경계도 같은 증가량만큼 보정한다. 최소 본문 폭 500px은 검토용 값이며 확정 요구가 아니다. viewport 기준만으로 처리하지 않아 AI 패널이 열린 상태에서도 실제 페이지 폭을 반영한다.

### 3.3 Mermaid 코드 블록 탭

#### 렌더링 단위와 상태

1. Markdown AST/HAST에서 언어가 `mermaid`인 fenced code block만 찾아 전용 표시 컴포넌트로 전달한다. 일반 인라인 코드·다른 언어 코드·본문에 쓰인 단어 mermaid는 대상이 아니다.
2. 블록 전체를 바꾸는 `pre` 렌더러에서 판별하는 방식을 권고한다. 기존 `<pre>` 안에 탭과 `<div>`를 삽입해 잘못된 HTML이 생기지 않도록 한다. 기존 `code`의 `className`·`data-line` 동작은 일반 코드에서 보존한다.
3. 새 컴포넌트는 문서 경로, 블록 원본 위치, 코드 문자열을 전달받는다. `useId()` 등 인스턴스별 ID와 렌더 순번으로 탭·패널·SVG ID의 충돌을 막는다.
4. 기본 선택은 ‘텍스트’를 권고한다. Mermaid 코드와 ‘미리보기’ 탭을 보여 주며, 미리보기를 선택했을 때만 라이브러리를 동적 import하고 도식화한다. 여러 블록은 서로 독립적으로 전환한다.
5. 미리보기 상태는 `대기 → 로딩 → 성공/오류`로 관리한다. 텍스트로 돌아가면 원래 코드를 그대로 표시한다. 텍스트 탭은 읽기 전용이며 수정·저장은 기존 문서 전체 원문 모드에서 한다.
6. 문서 경로·블록 위치·코드가 바뀌면 이전 렌더 결과를 무효화하고 기본 탭으로 초기화한다. 단순 부모 재렌더에서 탭이 불필요하게 초기화되지 않도록 컴포넌트 타입과 key를 안정적으로 유지한다.

문서 전체 ‘원문’에서는 Mermaid도 Markdown 원문 그대로 편집한다. 문서 전체 ‘미리보기’는 기존처럼 저장된 본문을 사용한다. 초안 미리보기까지 확장하려면 별도 결정이 필요하다.

#### 도식화 처리

- 문서 조회·탭 전환을 위해 서버 저장 API나 아키텍처 artifact API를 호출하지 않는다.
- `mermaid.initialize({ startOnLoad:false, securityLevel:"strict", htmlLabels:false, ... })`처럼 앱이 소유한 렌더 설정을 적용한다. 검증 후 SVG를 표시하고 오류는 해당 블록 안에서 안내한다.
- 기본 지원 범위는 graph/flowchart, sequenceDiagram, classDiagram, stateDiagram, erDiagram, gantt를 권고한다. 기존 아키텍처 전용 flowchart 제한을 문서 전체에 강제하지 않는다. 범위 밖 문법도 텍스트 열람은 가능하게 한다.
- `safeMermaidSvg()`의 정리 방식과 라벨 대비 보정을 재사용 검토한다. 현재 허용 태그 집합이 flowchart 외 도형을 손실시키지 않는지 먼저 확인한다. 공통화할 경우 독립 helper로 옮기고 기존 아키텍처도 동일 함수를 쓰도록 연결하되, 기존 API나 편집 정책은 변경하지 않는다.
- 인라인 SVG의 `<style>`이 뷰어 밖 요소에 적용되지 않도록 SVG ID 아래로 스타일 범위를 제한한다. 기존 sanitizer의 태그·속성 정리만으로 CSS 격리까지 완료되었다고 보지 않는다.
- 코드 안의 렌더 설정 지시문·frontmatter가 앱 설정을 바꾸지 못하게 차단하고, 외부 URL·HTML·클릭 콜백은 실행하지 않는다. 일반 Mermaid 문법 허용과 SVG 삽입 경계 검증을 구분한다.
- 기존 구현과 같은 150,000자 상한을 후보로 두고 초과 시 텍스트와 안내를 제공한다. 이 값은 렌더 시간 보장값은 아니므로 큰 도식은 별도 검증한다.
- 동적 import 실패·문법 오류·빈 코드·지원하지 않는 표현도 문서 전체를 중단시키지 않는다. 오류 안내와 텍스트 탭을 유지한다.
- 문서 변경·탭 변경·컴포넌트 해제 후 늦게 도착한 결과를 삽입하지 않는다. Effect 정리와 렌더 순번 확인으로 오래된 SVG·오류 상태를 폐기한다.
- Mermaid 모듈의 초기화 설정은 공유되므로 여러 블록의 `initialize/parse/render`를 직렬화하는 작은 렌더 경계를 둔다. 공통 모듈로 분리한다면 기존 아키텍처 렌더러와의 사용도 점검한다.
- 현재 개인 테마·강조 색상을 구독한다. 선택된 미리보기의 테마가 바뀌면 다시 렌더링하며 전역 테마를 뷰어가 직접 변경하지 않는다.
- SVG는 컨테이너 폭에 맞추고 필요한 경우 블록 내부에서 스크롤한다. 확대·드래그·전체 화면·이미지 저장은 이번 기본 범위에 추가하지 않는다.

#### 접근성

- 각 블록에 독립적인 `tablist`, ‘텍스트/미리보기’ `tab`, 연결된 `tabpanel`을 제공한다. `aria-selected`, `aria-controls`, 키보드 좌우 이동·Home/End를 지원한다.
- 로딩·오류는 텍스트 상태로 전달하고, 성공 SVG에는 도식임을 알 수 있는 접근 가능한 이름을 제공한다. 탭 전환 때문에 문서 전체의 초점이나 읽기 위치가 초기화되지 않게 한다.

### 3.4 목차의 숨김 스크롤

1. 목차 외곽은 sticky를 유지하고, 제목은 고정한 채 `.outlineLinks`를 세로 스크롤 컨테이너로 만드는 방식을 권고한다.
2. 외곽을 세로 flex로 배치하고 링크 목록에는 `min-height:0; overflow-y:auto; overflow-x:hidden`을 적용한다.
3. 외곽 높이는 `.readingArea`의 실제 `clientHeight`에서 위아래 여백을 뺀 값으로 제한한다. 현재 observer와 별도로 필요한 읽기 영역 관측을 추가하거나 기존 측정을 확장하여 헤더 줄바꿈·창 크기·메뉴 전환에 대응한다. 부모의 불확정 `max-height:100%`에만 의존하지 않는다.
4. 스크롤을 소유한 `.outlineLinks`에 `scrollbar-width:none`과 `::-webkit-scrollbar { display:none; }`를 적용한다. 문서 본문·문서 목록·앱 전체 스크롤바에 전파하지 않는다. 숨긴 바를 위한 `scrollbar-gutter:stable` 여백도 남기지 않는다.
5. 휠·트랙패드는 기본 브라우저 스크롤을 사용한다. 목록에 `overscroll-behavior-y:contain`을 적용해 끝에 도달했을 때 본문으로 스크롤이 이어지지 않도록 한다.
6. 링크 목록뿐 아니라 목차 제목·외곽 여백 위에서도 휠 이동이 필요하므로, 이 영역에서 발생한 휠만 링크 목록으로 전달하는 제한된 처리를 둔다. 목록 위 이벤트는 다시 처리하지 않아 이중 이동을 막는다. Ctrl+휠 확대와 수평 스크롤 의도는 가로채지 않는다. 수동 처리 시 deltaMode를 고려한다.
7. 키보드 사용을 위해 목록 영역에 접근 가능한 이름과 초점 진입 지점을 제공하고, Tab으로 이동한 항목이 목록 안에 드러나도록 한다. 포커스 윤곽선은 숨기지 않는다.
8. 항목 클릭은 기존 `scrollToHeading()`을 통해 본문을 이동한다. 목차를 스크롤하는 것만으로 본문 위치를 바꾸지 않는다.

### 3.5 제목 추출과 기존 문서 기능 보존

- backtick 및 tilde fenced block 안의 `#` 줄을 목차에서 제외한다. 가장 작은 변경은 fence 상태 추적을 추가하는 것이지만, fence 길이·중첩 표현·원본 줄 번호를 검증해야 한다. 향후 AST 기반 추출로 바꾸는 경우에는 별도 범위를 명시한다.
- h1~h3 지원, 중복 제목 slug, 원본 줄 번호와 렌더 heading ID의 대응, 문서 간 상대 링크의 hash 이동을 유지한다.
- Mermaid 렌더링으로 뒤늦게 본문 높이가 바뀌어도 이미 누른 목차 항목의 위치가 크게 어긋나지 않는지 검증한다. 텍스트 탭 기본값으로 초기 비동기 높이 변경을 줄인다.
- 문서 검색·폴더 확장·열린 문서 탭·초안 보존·복사·저장·오류 처리의 현재 동작을 유지한다.

| Mermaid 종류 | 확정된 지원 종류별 대표 도식을 렌더링한다. | 노드·연결·라벨·축·마커가 sanitizer 때문에 누락되지 않는다. |
| 오류·비동기 | 빈 코드·문법 오류·상한 초과·import 실패, 렌더 중 다른 문서 선택·탭 닫기를 반복한다. | 해당 블록에만 오류를 표시하고 이전 SVG가 새 문서에 나타나지 않는다. |
| 설정·SVG 경계 | 설정 지시문·외부 링크·HTML·클릭 명령과 넓은 CSS 선택자를 포함한 합성 입력을 사용한다. | 앱 설정 변경·외부 요청·스크립트 실행·뷰어 밖 스타일 변경이 발생하지 않는다. |
| 테마 | 라이트·다크·커스텀 강조색 변경 전후 도식을 비교한다. | 선·라벨·배경이 읽히고 이전 테마 렌더가 새 결과를 덮지 않는다. |
| 제목·링크 | fence 안의 #, 중복 제목, 상대 Markdown 링크+hash를 검증한다. | 가짜 목차가 생기지 않고 클릭 대상 제목과 ID가 일치한다. |
| 기존 기능 | 검색·문서 탭·다른 탭 닫기·원문 초안·복사·저장 실패와 설정 화면 왕복을 확인한다. | 기존 동작과 CSS 격리를 유지한다. 목차 없음/제목 한 개 문서는 빈 목차 열을 남기지 않는다. |

### 5.3 실행 계획과 제한

- 정적 확인은 변경 파일 대상 lint 및 `pnpm typecheck`를 수행한다. 최종 상태는 `pnpm build`로 확인한다. 기존 실패가 있으면 이번 변경과 분리해 기록한다.
- 뷰어 회귀 스크립트의 실제 경로는 `scripts/test-viewer.mjs`다. 현재 `package.json`에 `test:viewer` 명령은 없으므로, 빌드 후 `node scripts/test-viewer.mjs`로 실행한다. 이 스크립트는 합성 문서와 임시 SQLite를 사용하는 구조다.
- helper를 공통화했다면 `pnpm test:architecture-mermaid-browser` 등 관련 기존 회귀를 추가한다. DOM/SVG 검증에서는 실제 휠 입력, 최종 폭, 도식의 의미 있는 요소를 확인하며 스냅샷만으로 판정하지 않는다.
- 운영 DB와 실제 사용자 문서에는 검증용 저장을 하지 않는다. 원문 저장 회귀가 필요하면 격리 fixture에서만 수행한다.

## 6. 영향과 구현 순서

### 6.1 영향

- 주 영향은 `/viewer`의 가로 배분과 목차·코드 블록 UI다. 본문 폭을 넓히면 문단 줄 수와 표의 배치가 달라진다.
- 목차 확대는 본문 폭과 목차 표시 경계에 동시에 영향을 준다. 메뉴 접기와 반응형 경계를 함께 검증해야 한다.
- Mermaid는 텍스트만 보이던 블록에 클라이언트 렌더 비용을 추가한다. 텍스트 기본값과 선택 시 동적 로딩으로 초기 문서 표시 비용을 제한한다.
- SVG helper 공통화는 아키텍처 화면까지 영향을 줄 수 있는 유일한 주요 공통 변경 후보다. 기존 편집기 재사용보다 조회 전용 컴포넌트를 분리하는 편이 영향 범위를 작게 유지한다.
- DB·API 계약·접근권한·AI 생성·원문 저장 형식에는 변경이 필요 없다.

### 6.2 후속 구현 순서

1. 7절의 범위·폭 기준·기본 탭·반응형 정책을 검토해 확정한다.
2. 뷰어의 본문 가변 열·목차 유무 1열·목차 폭과 표시 경계를 먼저 조정한다.
3. 목차 높이 제한·숨김 스크롤·휠·키보드 접근을 연결한다.
4. Mermaid 블록 컴포넌트와 필요한 최소 공통 helper를 연결하고, 제목 추출의 fence 처리를 보완한다.
5. 합성 문서로 수용 조건과 기존 회귀를 검증하고 실제 변경 파일·검증 결과를 기록한다.

## 7. 결정이 필요한 사항

아래 권고안은 확정 요구가 아니다. 사용자가 문서를 검토·수정한 뒤 후속 구현 요청에서 확정한다.

| 항목 | 권고안 | 대안 및 영향 |
| --- | --- | --- |
| 좌측 패널의 의미 | 현재 접기 버튼이 있는 전역 메뉴를 대상으로 한다. | 뷰어 내부 문서 목록도 접어야 한다면 별도 토글·복원 UI·반응형 정책이 추가된다. |
| 40자의 의미 | 한글 2·그 외 1의 합계 40단위로 본다. | 한글 40자 자체를 한 줄에 표시한다는 의미라면 본문 제목 폭은 약 40em이 필요하며 목차·반응형 예산을 다시 계산한다. |
| 정확한 글자 폭 보장 | 기존 글꼴을 유지하고 300px 출발값을 대표 제목 실측으로 보정한다. | 모든 문자 조합의 엄격한 보장은 고정 폭 글꼴 또는 가중 길이 40 이하 실제 제목의 최대 폭 측정이 필요하다. 후자는 문서 전환·글꼴 변경 시 재계산이 추가된다. |
| 목차 초과 제목 | 한 줄 말줄임과 전체 제목 안내를 제공한다. | 두 줄 이상 허용하면 ‘한 줄’ 기준과 긴 목차의 높이·스크롤 정책을 달리 정해야 한다. |
| 좁은 화면 목차 | 본문 최소 폭을 확보하기 위해 실제 컨테이너 약 1120px 이하에서 기존처럼 숨긴다. | 좁은 화면에서도 목차 접근이 필수라면 접이식 패널·오버레이 진입 버튼을 추가한다. |
| 메뉴 접기의 확장 기준 | 문서 내용 패널의 확장을 필수로 하고, 같은 목차 상태에서는 본문 종이도 확장한다. | 목차가 새로 나타나는 경계에서도 본문 종이의 폭이 절대로 줄지 않아야 한다면 목차 자동 재등장 정책이나 오버레이 배치를 별도 설계한다. |
| Mermaid 기본 탭 | ‘텍스트’를 기본으로 하고 ‘미리보기’ 선택 시 렌더링한다. | 미리보기를 기본값으로 하면 진입 시 도식화 비용·높이 변화를 고려해야 한다. |
| Mermaid 지원 종류 | 우선 일반적인 flowchart·sequence·class·state·ER·gantt를 검증한다. | Mermaid 전체 문법을 일괄 보장하려면 추가 SVG 요소·렌더 설정·회귀 범위 검토가 필요하다. |
| 미저장 원문 미리보기 | 기존처럼 저장된 `selectedDocument.content`를 기준으로 한다. | 초안 기준으로 바꾸면 목차·복사·전환 시 데이터 기준도 함께 정해야 한다. |
| helper 공통화 | 도식 렌더와 SVG 처리를 최소 공통화하고 블록 UI는 뷰어에 둔다. | 완전 분리는 기존 화면 영향은 작지만 검증·SVG 정리 코드가 중복될 수 있다. |
