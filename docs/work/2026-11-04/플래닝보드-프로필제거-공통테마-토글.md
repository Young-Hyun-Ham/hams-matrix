# 플래닝보드 프로필 제거 및 공통 테마 토글 적용

- 작성일: 2026-11-04 (한국시간, Asia/Seoul)

## 주요 변경사항

- 편집기 헤더의 사용자 프로필·이니셜 영역을 제거하고 Matrix 공통 `ThemeToggle`을 배치했다.
- 버튼 하나에서 공통 해·달 아이콘과 switch 상태로 라이트·다크 모드를 전환한다. 공통 버튼 스타일을 편집기 색상 규칙이 덮어쓰지 않도록 조정했다.
- 독립 편집기와 미리보기 layout에 `PreferencesRuntime`을 연결했다. 서버에서 현재 회원의 개인 설정을 읽어 저장된 테마·강조색을 적용하고, 기존 개인 설정 API의 저장·충돌·오류 처리 흐름을 재사용한다.
- 사용자가 작성한 캔버스의 색상과 문서 데이터는 테마 변경으로 수정하지 않는다.

## 변경 파일

- `app/(editor)/planning-board/components/editor-header.tsx`
- `app/(editor)/planning-board/layout.tsx`
- `app/(editor)/planning-board/styles/editor.css`
- `scripts/test-planning-board-browser.mjs`: 프로필 검사 대신 단일 테마 버튼, 저장·복원·아이콘 전환·캔버스 색상 보존·읽기 전용 사용자 전환 검증.
- 본 문서 및 `WORK_HISTORY.md`.

## DB 변경 여부

- 스키마·migration·운영 데이터 일괄 변경 없음. 사용자의 테마 버튼 조작은 기존 `/api/me/preferences`를 통해 개인 설정에 저장된다.
- 브라우저 검증은 임시 SQLite DB와 가짜 사용자·외부 서비스 대역을 사용한다.

## 검증 결과

- `pnpm typecheck`: 통과.
- 변경한 TypeScript 파일과 브라우저 스크립트 ESLint: 통과.
- `pnpm build`: 통과. 정적 생성 중 일반 `Request failed Error` 로그가 출력되었으나 빌드 자체는 성공했다.
- `pnpm test:planning-board-browser`: 통과. 단일 토글·프로필 제거·저장된 다크 테마 초기 적용·해/달 아이콘 전환·라이트/다크 저장·새로고침 복원·강조색 및 캔버스 색상 보존·READ 전용 사용자의 전환을 확인했다. 기존 인증·저장·이미지·내보내기·미리보기·화면 실행 링크 회귀도 통과했다.
- 임시 테스트 DB의 동시 접근 잠금은 WAL과 5초 대기로 보완한 뒤 전체 검증을 통과했다. 운영 DB 설정은 변경하지 않았다.
