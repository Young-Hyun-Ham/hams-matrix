# 챗봇 우측 시나리오 실행 패널 설계

작성일 2026-11-26 (한국시간, Asia/Seoul)  
상태 사용자 검토용 설계. 검토 및 수정 후 별도 구현 요청을 기준으로 진행한다.

## 1. 요구사항

1. 독립 챗봇 팝업 안에서 기존 채팅 영역을 좁혀 오른쪽에 시나리오 실행 패널을 배치한다. 넓은 화면에서는 왼쪽 이력, 가운데 채팅 메시지·입력창, 오른쪽 시나리오 패널을 함께 표시한다.
2. 시나리오 선택·시작, 실행 메시지, 폼·선택지 제출, 승인, 결과 확인을 오른쪽 패널에서 처리한다. 가운데 채팅은 같은 방의 메시지와 입력창을 유지한다.
3. 패널 우측 상단 화살표로 패널을 숨기면 채팅 영역이 빈 공간을 채운다. 패널을 다시 열 수 있는 버튼은 챗봇 헤더에 남긴다. 숨기기와 실행 중단은 별도 동작으로 표시한다.
4. 시나리오 목록의 상세 모달 상단 요약 영역에서 `View scenario versions` 버튼 바로 왼쪽에 `커맨드에 추가` 아이콘 버튼을 배치한다. 클릭으로 해당 시나리오의 등록 상태를 ON/OFF 전환하고 현재 상태를 아이콘과 강조 스타일로 표시한다.
5. 챗봇 입력창에 `/`를 입력해 여는 커맨드 레이어에는 `커맨드에 추가`가 ON인 실행 가능한 시나리오 목록을 표시한다. `/` 목록의 `이미지 생성`, `문서 생성` 항목은 제거한다. 시나리오를 선택하면 오른쪽 실행 패널에서 이어서 조작한다.
6. 후속 구현 범위는 독립 챗봇의 일반 채팅 모드와 빌더 시나리오 목록 상세 모달이다. 빌더 Flow/View는 공통 실행 화면의 회귀 검증 대상이다. [시나리오 실행 패널 참고 이미지](../../../public/layout/chatbot/시나리오실행패널.png)

시안의 제목·중단 버튼·화살표, 폼·선택형 표, 실행 종료 표시는 패널 안에서 실행 단계가 이어지는 구조를 보여준다. 예약·이메일은 예시 시나리오다. 표시할 입력과 결과는 서버에서 받은 실제 노드와 이벤트를 사용한다.

## 3. 수정 방향

### 3.1 배치와 접근성

- 헤더 아래 본문에서 채팅과 실행 영역을 나란히 배치한다. 오른쪽 패널 목표 너비는 320~388px, 채팅 본문·입력의 최소 가용 너비는 320px, 열 간격은 12px로 제안한다. 좌측 이력과 본문 여백을 제외한 실제 팝업 내부 너비로 분할 가능 여부를 판단한다. 패널을 숨기면 채팅 열이 남은 폭을 모두 사용한다.
- 좁은 화면에서는 같은 팝업 안에서 채팅과 시나리오를 한 화면씩 표시한다. 실행 패널의 화살표는 채팅 화면으로 돌아가는 동작을 제공한다. 팝업 전체 너비와 기존 이력의 모바일 배치는 유지한다.
- 실행 패널의 제목과 화살표는 상단에 두고 이벤트 목록은 독립적으로 세로 스크롤한다. 긴 폼은 패널 안에서 스크롤할 수 있게 하고 넓은 표는 표 컨테이너 안에서 가로 스크롤한다. 채팅 메시지·입력창과 설정 팝오버도 각 영역 안에 맞춰 표시한다.
- 화살표는 한·영 접근성 이름과 `aria-expanded`, `aria-controls`를 갖는 버튼으로 제공한다. 숨길 때 포커스를 남아 있는 헤더의 열기 버튼에 돌려주고, 펼칠 때 패널 제목이나 첫 조작 요소로 옮긴다. 숨긴 영역은 키보드 탐색과 보조기기 알림에서 제외한다. 설정·이력과 패널이 함께 열린 경우 Escape 키로 최상위 영역부터 닫히도록 순서를 확인한다.

### 3.2 실행 진입과 상태 관리

1. 새 채팅의 패널은 접힌 상태로 시작한다. 챗봇 헤더의 시나리오 버튼을 누르면 오른쪽에 배포 목록과 실행 버튼이 나타난다. 목록은 선택 UI를 열 때 현재 조회 경로로 요청하고 로딩, 빈 목록, 조회 오류, 실행 오류를 패널 안에서 표시한다. 기존 입력 폼의 선택기는 패널로 옮긴다. `/` 커맨드에서 진입하면 선택한 시나리오를 패널에 채운다.
2. 실행 요청에는 선택한 시나리오 ID, 시작 시점의 채팅방 ID, 요청 키를 담는다. 시작 버튼을 제출 중 잠그고, 진행 중인 일반 생성 중에는 기존 실행 버튼의 제한을 유지한다. 성공하면 같은 채팅 세션에서 반환된 run ID를 표시한다. 시작 요청 중에는 중복 시작과 방 전환·삭제·팝업 닫기에 따른 엇갈림을 막고, 응답 시 사용자·워크스페이스 범위가 바뀌었으면 이전 응답을 새 화면에 반영하지 않는다. 시작 요청과 입력 제출은 서버 멱등성 키 및 현재 버전 검증을 사용하고 자동 재전송을 피한다.
3. 호스트에서 현재 방 ID, 일반 채팅에서 시작한 실행의 run ID와 시작 방 ID, 선택한 이력 ID, 패널 표시 여부를 관리한다. `ConversationPane`의 키는 방 ID, 활성 `ScenarioPane`의 키는 run ID로 유지한다. 입력·첨부, 스크롤, 실행 폼 값과 선택 행, 이벤트 커서, 승인 카드 상태는 패널 토글이나 반응형 배치 전환에 따라 초기화하지 않는다. 새 실행 ID가 선택된 경우에만 새 실행의 입력 상태를 초기화한다.
4. 화살표는 패널 표시 여부만 전환한다. 숨겨진 실행도 기존 `queued`·`running` 조회 조건을 따르며, 입력·승인 대기 및 종료 상태는 주기 조회 대상에서 제외한다. 다시 열 때 같은 run ID의 상태를 재조회해 최신 단계를 표시한다. 노드 또는 대기 상태가 바뀌었으면 이전 입력을 새 노드로 보내지 않고 현재 상태를 보여준다. 방·워크스페이스 접근이 종료된 경우 이전 실행 응답이나 조작 버튼을 노출하지 않는다.
5. 패널 안에서 시작, 진행, 입력 대기, 변경안 검토, 정책 승인 대기, 완료·중단·실패 등 실제 실행 상태를 표시한다. 기존 `ReviewCard`와 `PolicyCard`를 사용하고 기존 링크·iframe 표시 경로를 재사용한다. 중단은 기존 run 중단 API를 호출하며 명시적인 사용자 조작으로 실행한다. 후속안에서는 서버가 중단을 허용하는 입력·승인 대기 상태에서도 패널에서 중단할 수 있게 한다.

### 3.3 방 전환, 이력과 닫기

| 동작 | 제안 동작 |
| --- | --- |
| 열린 채팅에서 일반 메시지 작성 | 채팅의 입력과 시나리오 입력을 각각 제출한다. 채팅에는 기존 요청별 상태·제한을 적용하고 시나리오 제출은 run ID에 연결한다. |
| 좌측 `Scenario` 이력 선택 | 현재 채팅방과 초안을 유지한 채 오른쪽에서 읽기 전용으로 연다. 이력을 보는 동안에도 현재 활성 실행 문맥은 보존하고 `현재 실행`으로 돌아갈 수 있게 한다. |
| 다른 채팅방으로 이동 또는 새 채팅 | 기존 실행은 시작한 방에 연결된 상태로 보존한다. 다른 방의 입력이나 실행 패널과 섞이지 않도록 실행 조작 화면을 접고, 원래 방으로 돌아왔을 때 같은 run을 다시 열 수 있게 한다. 진행 중인 실행의 시작 방을 삭제하는 동작은 중단이나 종료 뒤 허용하는 안을 제안한다. 현재 방 삭제 검사에는 run 상태가 포함되어 있지 않으므로 다른 탭에서 삭제된 경우도 상세 조회 실패로 처리한다. |
| 패널에서 `중단` / 팝업에서 `×` | 패널 중단은 해당 run에 적용하고 채팅은 열린 상태로 둔다. 팝업 전체 닫기는 현재 채팅 요청과 이 팝업에서 유지 중인 실행에 대해 기존 닫기 경로의 중단 의도를 각각 적용한다. 실패한 중단은 오류와 재확인 경로를 보여준다. 빌더 실행의 전체 닫기는 기존 run 중단과 빌더 콜백을 사용한다. |
| 완료·실패 후 다시 열기 | 마지막 실행 결과는 같은 패널에서 확인한다. 새 실행은 사용자가 명시적으로 시작한다. 실행 이력은 별도의 읽기 전용 경로에서 다시 열 수 있다. |

### 3.4 시나리오 상세의 커맨드 등록

1. 저장된 시나리오의 상세 모달 상단 요약 영역 버튼 순서는 `커맨드에 추가` → `View scenario versions` → `Flow edit`로 한다. 토글은 MUI `IconButton`과 툴팁을 사용한다. OFF는 윤곽 아이콘, ON은 채운 아이콘과 강조 스타일로 구분한다. `aria-label`은 `커맨드에 추가`로 유지하고 `aria-pressed`와 툴팁으로 현재 상태를 전달한다. 상세 조회 중에는 토글을 비활성화한다.
2. 토글은 클릭 즉시 서버에 원하는 `true` 또는 `false`와 `expectedRevision`을 저장한다. 요청 중 중복 클릭을 막고 응답의 값과 revision을 반영한다. 실패 시 저장된 상태를 표시하고 오류를 안내한다. 버전 충돌 시 최신 상세를 확인할 수 있게 하고 모달의 미저장 이름·설명 등 편집값은 보존한다. 토글을 누르는 동작으로 모달 폼을 제출하지 않는다.
3. 기본안은 기존 빌더 관리 권한을 재사용하는 워크스페이스 공용 설정이다. 상태는 버전별 스냅샷과 독립된 `builder_scenarios`의 시나리오 메타데이터에 저장한다. 후속 구현 시 `command_enabled` 불리언 필드를 추가하는 안을 제안한다. 기존·신규 시나리오와 복제본은 OFF에서 시작하고, 발행·배포·버전 복원은 현재 등록 상태를 유지한다. 미배포 시나리오도 등록할 수 있으며 `/`에는 배포 이후 표시한다.
4. 토글 전용 경로로 `PATCH /api/builder/scenarios/[scenarioId]/command`를 제안한다. 기존 빌더의 인증, Origin, 트랜잭션 내 현재 관리자 권한, 워크스페이스·삭제 여부 및 revision 검사를 재사용한다. 쓰기는 커맨드 상태와 변경 메타데이터에 한정하고 기존 감사 이력을 남긴다. 현재 모달이 편집 중인 경우 토글 응답을 해당 시나리오에만 합치고 폼을 초기화하지 않는다.

### 3.5 챗봇 `/` 커맨드와 실행 패널 연결

- `/` 레이어는 현재 워크스페이스에서 ON이고 삭제되지 않았으며 배포 버전이 있는 시나리오 이름을 보여준다. 기존 `GET /api/chatbot/scenarios`에 커맨드 필터를 추가하는 안을 제안한다. 필터링은 서버에서 목록 한도를 적용하기 전에 수행하고, 같은 이름은 ID로 구분한다. 일반 패널 선택기는 기존 배포 목록을 사용한다. 두 목록은 별도 Query 키로 관리하고, `/`를 다시 열 때 현재 목록을 조회해 다른 화면에서 바뀐 ON/OFF와 배포 상태를 반영한다. 등록된 배포 시나리오가 없거나 조회가 실패하면 레이어 안에서 이유를 안내한다.
- `/`에서는 시나리오 목록을 표시하고 이미지·문서 생성 메뉴는 입력창 옆 `☰`에서 이용한다. 기존 생성 모드 전환과 문서 형식·첨부 동작을 이어서 사용한다.
- 시나리오를 선택하면 레이어를 닫고 오른쪽 패널에 해당 시나리오를 선택한 상태로 연다. 실행은 패널의 `실행` 버튼으로 시작하도록 제안한다. `/` 선택으로 기존 활성 run과 미제출 입력을 덮어쓰지 않게 하고, 실행 중이면 해당 run으로 돌아갈 수 있게 안내한다.
- 선택 시 입력에 남아 있는 트리거 `/` 한 글자만 제거한다. `Esc`나 바깥 클릭으로 닫으면 초안 전체를 보존한다. 두 경우 모두 첨부·생성 모드·모델 선택을 보존한다. 레이어가 열린 상태에서 항목 선택에 사용한 Enter가 채팅 전송으로 이어지지 않도록 한다.

## 5. 검증 방법

아래 항목은 구현 이후 검증한다. 이번 문서 작업에서는 이미지와 소스·이전 작업 기록을 확인했다.

| 검증 항목 | 확인 방법과 기대 결과 |
| --- | --- |
| 상세 토글과 저장 | 저장된 시나리오를 열어 버튼 순서, ON/OFF 아이콘과 `aria-pressed`를 확인한다. 모달 재열기와 새로고침 뒤 서버에 저장된 상태가 보인다. 토글 연타, 다른 관리자의 동시 변경, 권한 거부, 저장 실패를 재현해 편집 중인 값과 기존 배포 버전·그래프가 보존되는지 확인한다. |
| `/` 목록과 패널 진입 | 같은 워크스페이스에서 ON·OFF·미배포·삭제 시나리오와 다른 워크스페이스 시나리오를 준비한다. `/`에는 같은 워크스페이스의 배포된 ON 항목만 보이고, 토글 상태가 바뀌면 다음 목록 열기에 반영된다. 선택 시 오른쪽 패널에 해당 시나리오가 표시되고 `실행` 전에는 run이 생성되지 않는다. 취소·선택 시 슬래시와 초안 처리, 키보드 조작, `☰`의 이미지·문서 생성을 확인한다. |
| 화면과 폭 | 넓은 팝업에서 채팅 입력창과 우측 폼·실행 이력이 동시에 보이는지 확인한다. 화살표를 누르면 채팅 열이 넓어지고 다시 열면 동일한 run이 표시된다. 좌측 이력을 접고 펼칠 때, 분할 임계값 전후, 모바일 폭에서 가로 넘침과 스크롤 잠김을 확인한다. |
| 상태 보존 | 채팅에 초안·첨부가 있고 패널 폼에 입력·선택값이 있는 상태에서 반복 토글 및 화면 폭 변경을 실행한다. 방 ID, run ID, 메시지 위치, 미제출 값과 선택 상태를 비교한다. 숨김 시 시작·입력·중단 POST가 발생하지 않고 `queued`·`running` 조회만 기존 조건을 따르는지 확인한다. |
| 시나리오 단계 | 임시 DB에 배포한 합성 시나리오로 목록 열기, 시작, 폼·그리드·선택 제출, 메시지, 승인 대기 및 재개, 정상 완료를 확인한다. 시작 연타로 run이 중복 생성되지 않는지, 시작 오류 및 오래된 입력 버전 오류에서 자동 재전송 없이 현재 상태를 다시 확인할 수 있는지 점검한다. 별도로 실행·입력 대기 중 명시적 중단과 팝업 닫기를 검증한다. |
| 방·이력 범위 | 방 A의 실행을 유지한 채 방 B로 이동한 뒤 방 A에서 같은 run을 다시 연다. 좌측 이력의 읽기 전용 제약, 최근 대화 복귀, 방 삭제와 사용자·워크스페이스 전환 시 이전 실행 정보가 노출되지 않는지 확인한다. |
| 접근성·테마 | Tab·Enter·Space로 토글과 패널 조작이 가능하고 접은 영역에 포커스가 남지 않는지 확인한다. 좁은 화면에서 설정·좌측 이력과 열린 패널의 Escape 동작을 점검한다. 한·영 표시, 밝은·어두운 챗봇 자체 테마, 긴 제목·폼·표를 확인한다. |
| 회귀 명령 | 임시 DB·합성 계정·모의 공급자로 `pnpm test:chatbot`을 실행한다. 테스트용 격리 빌드 후 `pnpm test:chatbot-browser`에서 일반 채팅의 요청·초안·선택형 HITL과 빌더 Flow/View 자동 시작·폼·모바일·전용 이력을 확인한다. |

## 6. 결정이 필요한 사항

| 결정 항목 | 제안 |
| --- | --- |
| `/`에서 항목을 선택했을 때 | 우측 패널에 선택된 시나리오를 표시하고 패널의 `실행` 버튼으로 시작하는 안을 제안한다. 헤더 버튼으로도 패널을 열 수 있다. 시안의 가운데 채팅 메시지에 보이는 실행 링크도 필요하다면 생성 시점과 저장·복원 방식을 별도로 결정한다. |
| 커맨드 등록 범위와 시점 | 기존 빌더 관리자가 워크스페이스 공용 목록을 관리하는 안을 제안한다. 배포 전 ON 설정을 허용하고 배포 시점부터 목록에 표시한다. 등록된 배포 시나리오가 기존 조회 한도 100건을 넘을 때의 추가 조회 방식을 구현 전에 확정한다. |
| 패널 기본 상태와 복원 범위 | 새 채팅에서는 접힌 상태를 기본으로 한다. 팝업에서 작업하는 동안 숨김·재열기와 방 왕복을 지원한다. 새로고침이나 다른 탭에서 진행 중인 실행을 복원하려면 목록의 방 연결 정보와 활성 실행 선택 기준이 필요하다. |
| 패널 너비와 좁은 화면 | 넓을 때 채팅 최소 320px와 패널 320~388px를 기준으로 하고, 좁을 때는 한 화면씩 전환한다. 실제 폼과 표를 보고 기준값을 확정한다. |
| 동시 실행과 채팅 | 팝업에서 조작 중인 일반 시나리오는 한 건으로 제한하고 종료 또는 중단 후 새 실행을 시작한다. 기존 채팅 요청 정책 안에서 일반 메시지 사용을 허용한다. 여러 run의 동시 조작이나 서버 전역 동시 실행 제한이 필요한지는 별도로 결정한다. |
| 팝업 전체 닫기와 빌더 | 패널 숨기기는 실행을 유지하고 팝업 전체 닫기는 현재 중단 동작을 따른다. 빌더의 독립 시뮬레이터에도 화살표나 분할 화면을 적용할지는 별도 결정한다. |
