# WBS 등록 오류 포커스 및 관계 기반 날짜 제한 구현

- 작성일: 2026-11-10 (한국시간, Asia/Seoul)
- 기준: `docs/history/2026-11-10/WBS등록-오류포커스-관계기반-날짜제한-설계.md` 최신 내용을 다시 읽고 구현.

## 주요 변경사항

- 공통 WBS 등록·수정 모달에서 서버·권한·네트워크 오류와 브라우저 필수 입력 오류를 하단 오류로 안내한다. 같은 오류로 재시도해도 오류 요소에 포커스를 주고 모달 본문만 스크롤한다. 실패 후 입력값을 유지하며, 편집 세션을 구분하여 이전 요청의 결과가 새 편집에 유입되지 않도록 했다.
- 날짜와 상위·선행 선택을 공유 상태로 관리한다. 계획 하한은 상위 계획 시작일과 모든 선행 계획 종료일 중 최댓값이며, 상한은 상위 계획 종료일이다. 선행 종료 당일 시작을 허용한다.
- 신규 초기 계획일은 최초 관계 선택 시 허용 시작일로 조정한다. 유효한 직접 입력은 유지하고, 범위 밖 기간은 길이를 유지하여 이동한다. 기존 기간이 들어가지 않으면 단축하지 않고 오류를 표시한다. 관계 순환·잘못된 대상도 저장 전에 검사한다.
- 달력에 최소·최대 날짜, 입력 ID, 안내 연결을 추가했다. 범위 밖 날짜·월·방향키 이동을 막으며, 선택 불가 기간을 안내하고 선택 날짜와 실제 날짜 지우기, 닫은 후 호출 버튼으로의 포커스 복귀를 유지한다.
- 달력·관계 변경도 명시적으로 수정 상태에 반영한다. 마일스톤의 날짜 동기화와 공수·진척률 규칙을 유지한다.

## 설계의 미확정 항목에 적용한 기본 정책

- 실제 날짜는 계획일에서 복사하거나 관계 변경만으로 이동·삭제하지 않는다. 실제 시작을 직접 지우면 종료도 함께 비운다.
- 선택한 상위의 실제 시작·종료와 모든 선행의 실제 종료가 확인된 경우에만 실제 관계 범위를 적용한다. 상위가 없으면 상위 정보는 필요하지 않다. 확인된 실제 하한을 사용자가 명시적으로 실제 시작일 후보로 적용할 수 있으며, 실제 종료 사실은 자동 생성하지 않는다.
- 기준이 부족하면 ‘실제 기준 미확정’을 표시하고 관계 범위를 강제하지 않는다. 실제 종료만 입력하거나 시작보다 앞선 종료는 항상 거부한다. 실제일을 계획 기간 안으로 가두지 않는다.
- 실제 범위는 UI뿐 아니라 서버의 최신 프로젝트 그래프 검증에도 적용한다. 확정된 실제 관계와 충돌하는 기존 데이터가 있으면 후속 저장에서 수정이 필요할 수 있으며, 기존 데이터 자체를 자동 보정하지 않는다.
- WBS 일정 탭의 별도 작업 편집에는 등록 모달의 관계 자동 보정을 확대하지 않았다. 공용 달력의 범위 미지정 동작 및 기존 차트·요약 집계 후 검증 순서를 유지했다.

## 변경 파일

- 신규 `lib/wbs-date-constraints.ts`: 관계 검사, 계획·실제 범위, 날짜별 경계, 기간 보정 및 공통 검증.
- 신규 `components/pages/wbs/wbs-form-state.tsx`: 공유 편집 상태, 자동 보정, 후보 적용, 수정 상태 통지.
- `components/pages/wbs/wbs-fields.tsx`, `wbs-structure-editor.tsx`: 공유 상태 및 범위·오류 안내.
- `components/pages/wbs/wbs-date-picker.tsx`, `wbs-date-picker.css`: 범위 제한, 접근성, 포커스 복귀 및 오류 포커스 표시.
- `components/shared/artifact-field-inputs.tsx`, `artifact-dialogs.tsx`, `use-artifact-actions.ts`: 날짜 범위 전달, 저장 전 검증, 실패별 오류 포커스 및 세션 보호.
- `lib/artifact-validation.ts`: 서버 공통 날짜 검증.
- 신규 `scripts/test-wbs-form-browser.mjs`: 실제 React 모달·달력을 Chrome에서 검증하는 격리 브라우저 검사.
- `scripts/test-wbs-schedule.mjs`: 순수 날짜 계산·직접 등록 API 검증 보강. 기존 테스트의 사용자/워크스페이스 요금제 전제를 현재 정책에 맞춤.
- 본 작업 기록 및 `WORK_HISTORY.md`.

## DB 변경 여부

- DB 스키마·마이그레이션·운영 데이터 변경 없음. 기존 날짜 필드와 관계 필드를 그대로 사용한다.
- API 검증에는 임시 디렉터리의 격리 SQLite만 사용했다.

## 미완료 사항 및 제한

- 운영 환경 수동 확인은 수행하지 않았다. 브라우저 검사는 실제 공통 모달·상태 훅·달력을 사용하되 주변 산출물 라우팅 컴포넌트와 네트워크를 대체했고, 서버 규칙은 별도 실제 API/격리 DB 검사로 확인했다.
- 참조 버전의 별도 요청·409 확장은 추가하지 않았다. 저장 트랜잭션의 최신 데이터 검증을 사용한다.
- 기존 다른 변경사항을 보존했으며, 이번 범위의 구현 미완료 사항은 없다.
