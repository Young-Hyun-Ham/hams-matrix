## 2. 현재 구조와 원인

### 2.1 캔버스와 일반 노드

- 편집 화면 `/react-flow/scenario-flow`의 `ScenarioFlow.tsx`는 Zustand의 노드·엣지를 React Flow 11의 제어 상태로 전달한다. 크기 변경 이벤트는 `store/index.ts`의 `onNodesChange`와 `applyNodeChanges`를 거친다. 버전 조회 `ScenarioView.tsx`와 시나리오 미리보기·편집 모달에서도 일부 노드 컴포넌트를 공유한다.
- `NodeWrapper.jsx`는 본문 기본 상태를 로컬에서 접힘으로 관리한다. 부모가 없는 일반 노드에 `isBodyCollapsed ? 250 : 420`을 인라인으로 적용하며, 높이와 핸들 위치는 본문 표시 변화 후 `useUpdateNodeInternals`로 갱신한다. 이 분기가 펼침 때 너비가 커지는 직접 원인이다.
- `selectionGroup`은 `GroupNode.jsx`에서 별도 컨테이너로 렌더링한다. 편집 화면의 그룹 배치 효과는 펼친 그룹 640px, 자식 520px를 기준으로 세로 재배치하고 자식 높이로 그룹 높이를 계산한다. 그룹 자식의 `NodeWrapper`는 바깥 노드 너비를 100% 채운다.
- Form은 `formNodeWrapper`에 520px 규칙이 있고 iFrame은 `data.width`에서 래퍼 너비를 계산한다. 부모 없는 노드에서는 공통 인라인 규칙이 이를 덮는다. Sub Agent 내부의 일반 자식처럼 부모가 있는 경우에는 개별 너비 규칙이 적용될 수 있다. Delay와 Y/N Branch는 독립 렌더러를 사용하므로 공통 래퍼 수정의 직접 대상에서 벗어난다.

### 2.2 Sub Agent 헤더·가져오기·크기

- 노드 트리의 **Sub Agent**는 항목 타입 `scenarioGroup`, 캔버스 노드 타입 `scenario`에 대응한다. 드롭하면 `ScenarioFlow.tsx`가 `ScenarioGroupModal`을 열고 선택 결과를 `store/index.ts`의 `addScenarioAsGroup`에 넘긴다.
- 선택 목록은 `depn_ver_id`가 있는 시나리오를 표시한다. 실제 가져오기는 `fetchScenarioData`로 시나리오 상세의 현재 `definition_json`을 읽는다. 배포판과 이후 저장한 정의가 다르면 캔버스에 그려지는 그래프가 배포판과 달라질 수 있다. 기존 `getScenarioVersion`은 버전 번호를 받아 해당 스냅샷을 읽을 수 있다.
- `addScenarioAsGroup`은 원본 위치와 크기로 부모 후보 영역을 계산하지만 최초 부모 `style` 적용은 주석 처리되어 있다. 가져온 노드는 ID와 연결선을 재매핑하고 자식을 `parentNode` 및 `extent: "parent"`로 설정한다. 현재 변환은 원본 노드를 모두 새 부모의 직계 자식으로 넣으므로, 원본 Group의 계층과 그 아래 노드의 상대 좌표를 검증해야 한다.
- `ScenarioNode.tsx`는 오른쪽 버튼 묶음에서 시작 노드 지정, 접기·펼치기, 삭제 순으로 렌더링한다. 노드 테두리는 접힘 450×50px, 펼침 450×120px로 고정한다. 반면 `toggleScenarioNode`는 React Flow 바깥 노드의 `style.width/height`를 바꾸며, 펼칠 때 직계 자식의 좌표를 직접 변경한다. 렌더러와 React Flow가 서로 다른 크기를 사용하고 자식은 React Flow의 별도 노드 요소로 배치되므로 테두리 밖에 그려질 수 있다.
- `ScenarioNode.tsx`에서는 `isCollapsed` 누락을 접힘으로 읽는다. store의 토글과 Flow/View의 표시 필터는 누락을 펼침으로 읽고, 필터는 직계 부모만 확인한다. 기존 저장 데이터에 플래그가 없거나 여러 단계가 중첩된 경우 헤더, 자식과 엣지의 표시 상태가 엇갈릴 수 있다.
- 속성 패널의 `ScenarioNodeController.tsx`에 있는 **Select Scenario**는 현재 로컬 노드의 제목과 참조 ID를 설정한다. 같은 파일의 `importScenarioIntoOrkesNode`는 호출처가 없어 현행 드롭 경로의 수정 지점으로 사용할 수 없다.

### 2.3 Add Node와 Branch 테마

- `providers/runtime.tsx`는 Matrix 개인 테마로 MUI 모드와 `data-builder-theme`를 설정한다. `styles/builder.css`가 Matrix의 `--surface`, `--ink`, `--line`, `--primary` 등을 `--builder-*` 변수에 연결한다.
- Add Node의 `ActivityPickerModal.tsx`는 현재 빌더 트리 안에 렌더링하는 fixed `Box` 오버레이다. 패널 배경에는 `--builder-surface`를 쓰지만, 검색 입력 글자색, 외곽선, 목록 호버, 아이콘 및 분류 타일에는 라이트용 고정 색이 남아 있다. Flow 하단의 Add Node와 Group의 노드 추가 버튼에서 열리며 시나리오 편집 모달에서도 컴포넌트를 재사용한다.
- `BranchNode.jsx`는 조건형·버튼형 본문의 읽기 전용 textarea와 분기 목록을 `NodeWrapper` 안에 렌더링한다. 공통 테마 규칙이 textarea와 일부 빈 상태를 이미 보정하지만, `ChatNodes.module.css`의 목록 컨테이너는 `#d3d3d3`, 분기 항목 테두리는 `#ccc`를 사용한다. `isSimpleYN`은 별도 `YnBranchNode` 렌더러로 위임한다.

## 3. 수정 방향

### 3.1 일반 노드 너비 고정

1. 독립 일반 노드는 기존 접힘 너비인 250px를 양쪽 상태의 기본값으로 사용한다. Group 자식은 그룹이 할당하는 너비를 양쪽 상태에서 그대로 채운다. Sub Agent 안의 일반 자식도 각 노드에 정해진 레이아웃 너비를 양쪽 상태에서 사용한다. 한 노드의 최종 너비를 정할 때 React Flow 외곽과 내부 래퍼의 우선순위를 맞춘다.
2. 고정 너비 안에서 제목은 기존 말줄임을 사용하고 본문은 줄바꿈하도록 한다. Form의 표와 iFrame 미리보기는 가용 폭에 맞추고, 필요한 가로 스크롤은 본문 내부의 해당 미리보기 영역에 한정한다. iFrame 설정값과 높이 동작은 유지한다. 핸들과 헤더 팝오버가 바깥으로 표시될 수 있도록 노드 래퍼의 overflow를 유지한다.
3. 펼침에 따른 높이 변경 후 React Flow가 핸들 위치를 다시 측정하도록 한다. Group의 기존 자식 배치·순서·연결 정책과 토글 없는 소형 노드의 크기를 유지한다.

### 3.2 Sub Agent 헤더와 컨테이너

1. 접기·펼치기 버튼을 헤더의 타입 아이콘 앞에 배치한다. 일반 노드와 같은 버튼 스타일과 상하 화살표를 재사용하는 안을 기본으로 둔다. `aria-expanded`와 상태별 접근 가능한 이름을 주고 `nodrag nopan`과 이벤트 전파 제어를 적용한다. 기존 시작 지정, 삭제, 제목·속성 편집을 유지한다.
2. 새로 가져올 때 기존 상세 조회로 선택 시점의 `deployed_version` 또는 `depn_ver_id`를 확인하고, 해당 번호의 스냅샷을 기존 버전 조회 서비스로 읽는 안을 제안한다. 상세 조회 시 배포가 취소되었으면 가져오기를 종료한다. 이 방식에서 기준 시점은 상세 응답을 받은 때다. 요청 완료 시 같은 편집 탭과 대상인지 확인하고, 빈 응답·실패·유효하지 않은 버전은 기존 그래프를 보존한 채 안내한다. 펼침은 저장된 자식 그래프를 표시하므로 재배포된 원본으로의 자동 갱신 여부는 검토 항목으로 둔다.
3. 자식 배치 계산과 부모 테두리에 같은 좌표·크기 규칙을 사용한다. 가져올 때 ID·부모 ID·엣지 끝점을 일관되게 재매핑하고, 최상위 자식을 부모 로컬 좌표로 변환한다. 음수 좌표 및 헤더와 겹치는 위치는 필요한 만큼 최초 배치에서 정규화한다. 중첩된 자식은 부모별 로컬 좌표를 유지하고 상위 기준 범위를 구할 때 조상 위치를 합산한다. 기존 그래프의 헤더 겹침이나 음수 좌표를 보정하는 경우에도 반복 토글마다 위치가 이동하지 않게 한다.
4. 펼친 영역은 배치된 자식의 최대 오른쪽·아래 경계에 각각 여백을 더해 결정한다. 위쪽은 헤더와 설명 영역, 아래쪽은 편집 버튼과 연결 핸들 여유를 확보한다. 가져온 시점에는 저장된 유효 크기나 타입별 기본값으로 계산하고 렌더 후에는 React Flow 측정값을 우선한다. 자식의 본문 열기, 이동, 크기 변화와 추가·삭제 이후 다시 계산한다. 동일 결과면 상태 쓰기를 생략하고, 캔버스 줌과 관계없는 좌표를 사용한다.
5. 부모 `node.style.width/height`와 `ScenarioNode.tsx`의 테두리를 한 값에 맞춘다. 펼침·접힘 크기와 자식 표시 여부는 공통 상태 판정으로 처리한다. `isCollapsed`가 명시되어 있으면 그 값을 우선하고, 기존 Sub Agent에 값이 누락된 경우 자식이 있으면 펼침, 없으면 접힘으로 읽는 안을 제안한다. 하위 노드와 그 노드를 끝점으로 삼는 엣지는 렌더링에서만 숨겨 원래 그래프를 유지한다. 기존 방식의 직접 좌표 변경을 제거하고, 부모·자식 핸들을 크기 변경 후 갱신한다. 꺾임점이 있는 외부 연결선은 현재 토글에서 접점 재계산을 위해 `edge.data.points`를 지우는 동작까지 확인한다.
6. 부모 크기는 파생 표시값으로 계산하는 방향을 우선한다. 현재 편집 화면의 초안 비교는 노드의 측정 `width/height`를 제외하지만 `style`은 포함하며, `sanitizeNodesForSave`는 노드 필드를 넓게 보존한다. 계산된 크기를 저장 상태에 넣게 되면 표시 측정만으로 초안이 바뀌는 문제와 기존 명시적 너비 덮어쓰기를 막을 범위를 정한다. 기존 저장 그래프는 다시 가져오지 않아도 새 크기 규칙을 적용한다.

### 3.3 Add Node·Branch 테마

- Add Node는 기존 오버레이와 선택 흐름을 유지하고 패널·입력·텍스트·구분선·타일·호버·포커스를 해당 컴포넌트 안에서 토큰으로 교체한다. 기존 `--builder-surface`, `--builder-input`, `--builder-text`, `--builder-muted`, `--builder-border`, `--builder-accent`, `--builder-accent-soft`를 우선 사용한다. 고정 오버레이의 명암은 두 모드에서 확인한다. 테마 경계를 명시할 필요가 있으면 공통 runtime 또는 호출 화면의 실제 테마를 모달 루트에 전달한다. 이후 포털을 사용하게 될 때도 포털 루트가 토큰을 받을 수 있어야 한다.
- Branch는 본문에 범위를 한정해 읽기 전용 입력, 목록 배경, 분기 항목, 빈 상태에 빌더 토큰을 적용한다. 조건식, 버튼 라벨, 긴 문자열과 공백 없는 값은 250px에 맞춰 줄바꿈한다. 조건·버튼 평가, 기본 분기, 핸들 ID와 연결 방향, 속성 편집 동작은 유지한다.

캔버스 표시와 기존 버전 조회를 활용하는 범위로 설계했다. DB 스키마·마이그레이션, 시나리오 실행 엔진, Matrix 공통 테마 정책은 현행 계약을 사용한다.

## 5. 검증 방법

후속 구현 시 기존 빌더 브라우저 테스트와 임시 테스트 데이터로 확인한다.

| 대상 | 검증 시나리오 | 기대 결과 |
| --- | --- | --- |
| 일반 노드 너비 | Message, API, Branch, Form, iFrame을 일반 캔버스·Group·Sub Agent 안에서 각각 열고 닫는다. 동일 줌에서 React Flow 외곽과 내부 테두리 너비를 전후 비교한다. | 각 배치에서 너비 차이 0px. 높이와 핸들 위치는 갱신되며 긴 문자열·큰 미리보기가 테두리를 밀지 않는다. |
| Group 예외 | Group을 열고 닫은 뒤 내부 본문도 개별 토글한다. | 부모의 접힘·펼침 크기가 달라지고, 자식 배치 및 순서·경로가 기존 규칙을 따른다. |
| Sub Agent 토글 | 마우스와 Tab·Enter·Space로 첫 버튼을 조작하고 시작 지정·삭제·속성 편집을 확인한다. | 버튼의 표시와 접근성 상태가 바뀌고 클릭으로 노드 드래그나 삭제가 발생하지 않는다. |
| Sub Agent 크기 | 단일·다수 자식, 가로 분기, 음수 원본 좌표, 펼침이 큰 Form·Branch와 중첩 Group을 가져온다. 자식 확장·이동 후 토글을 반복하고 새로고침한다. `isCollapsed`가 없는 기존 데이터와 빈 노드도 연다. | 펼친 테두리 안에 보이는 자식의 사각형이 모두 포함된다. 접으면 자식과 내부 연결선이 숨고, 다시 열면 위치·연결이 복원된다. 접힘 플래그 누락 시에도 버튼·테두리·자식 표시가 일치한다. 수동 꺾임점과 외부 핸들 연결도 확인한다. |
| 배포 버전·오류 | v1을 배포하고 다른 노드 구성을 v2로 저장한 뒤 가져온다. 배포 취소·버전 조회 실패 및 조회 중 탭 이동도 재현한다. | 선택된 배포 스냅샷인 v1이 표시된다. 실패나 늦게 도착한 응답이 현재 편집 그래프를 덮지 않는다. |
| Add Node 모달 | 캔버스와 Group에서 라이트·다크 및 커스텀 강조색으로 열고 검색, 키보드 포커스, 항목 선택, 닫기를 확인한다. | 패널과 내부 요소의 계산된 색이 현재 테마에 대응한다. 기존 검색·선택·삽입 및 닫기 흐름이 동작한다. |
| Branch 본문 | 조건형, 버튼형, 각 빈 목록과 긴 라벨을 라이트·다크에서 펼친다. 우측·하단 연결선도 확인한다. | 본문 배경·텍스트·테두리 대비가 유지되고 분기 평가와 핸들 매핑이 동일하다. |
| 공유 화면·초안 | 버전 조회·미리보기·편집 모달에서 기존 그래프를 열고, 편집 화면에서는 측정만 발생한 뒤 탭 이동 및 저장·다시 열기를 확인한다. | 공유 화면에도 일관된 테두리와 본문 테마가 적용되고, 측정만으로 미저장 경고나 그래프 변경이 발생하지 않는다. |

## 6. 결정이 필요한 사항

| 검토 항목 | 기본 제안 |
| --- | --- |
| 일반 노드 기본 너비 | 독립 노드는 현재 접힘과 같은 250px를 사용한다. Form·iFrame을 더 넓게 보여줄 필요가 있으면 해당 타입의 두 상태에 같은 고정 너비를 적용할지 결정한다. |
| Sub Agent의 접힌 크기와 아이콘 | 현재 화면에서 보이는 450px 접힘 너비를 우선 유지하고 공통 화살표를 사용한다. Group과 같은 250px로 좁힐 경우 제목 말줄임과 우측 버튼 배치를 확인한다. |
| Sub Agent의 배포판 갱신 | 새로 가져올 때 선택한 배포 버전을 복사하고 이후에는 그 그래프를 표시한다. 재배포 후 자동 갱신 또는 명시적 다시 가져오기가 필요한지 결정한다. |
| 속성 패널의 시나리오 재선택 | 현재는 제목·참조 ID를 설정한다. 이 동작을 유지할지, 새 배포 그래프로 교체하는 동작까지 제공할지 결정한다. 교체할 경우 기존 내부 편집과 외부 연결 처리 기준도 함께 정한다. |
| 큰 그래프와 Group 중첩 | 보이는 자식을 전부 담도록 폭·높이를 계산한다. 기존 데이터에 Group 아래 Sub Agent가 있는 경우에는 내부 그래프를 담을 수 있도록 외부 Group의 폭도 넓힐지 결정한다. |
